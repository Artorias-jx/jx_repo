# 计算机网络

# 1 计算机网络体系结构

> **主线**：整本书只回答一个问题 —— ==**两个程序要通信，怎么做到？**== 答案就两个字：**分层**。这一章不记细节，只搭地图：每层管什么、层与层之间怎么打交道。

## 1.1 计算机网络的基本概念

**定义**：==一些互相连接的、自治的计算机的集合==。"自治"是各自有硬件软件、能独立工作，"互连"是彼此能交换信息 —— ==被互连的"计算机"和连接它们的"网"是两回事==。

**组成**（四个角度，别混）：

| 角度 | 内容 |
| --- | --- |
| 从**部件**看 | 硬件、软件、**协议** |
| 从**工作方式**看 | 边缘部分（主机）＋ 核心部分（路由器 + 链路） |
| 从**功能**看 | 通信子网（负责传送）＋ 资源子网（负责处理） |
| 从**拓扑**看 | 总线、星型、环型、网状 |

**功能**：==数据通信、资源共享、分布式处理、提高可靠性==。

**分类**：按范围 —— ==PAN（个域）／LAN（局域）／MAN（城域）／WAN（广域）==；按使用者 —— 公用网 / 专用网；按交换技术 —— 电路 / 报文 / 分组。

### 主要性能指标（计算考点，公式要背）

| 指标 | 含义 | 说明 |
| --- | --- | --- |
| **速率**（数据率、比特率） | 每秒传多少比特 | b/s，==k=10³、M=10⁶、G=10⁹== |
| **带宽** | 本指频带宽度（Hz）；网络里指**最高数据率** | b/s |
| **吞吐量** | 实际通过的速率 | ==≤ 带宽==，被瓶颈卡住 |
| **时延** | 一个比特从源到目的花的时间 | 四部分相加，见下 |
| **时延带宽积** | 传播时延 × 带宽 | ==这条"管道"里能装多少比特== |
| **往返时延 RTT** | 一来一回 | |
| **利用率** | 有数据的时间 / 总时间 | ==利用率越高，时延越大==（排队） |

**时延的四部分**（==最常考"哪个是发送时延、哪个是传播时延"==）：

$$T_{发送}=\frac{数据长度}{发送速率}\qquad T_{传播}=\frac{信道长度}{波速}\qquad T_{总}=T_{发送}+T_{传播}+T_{处理}+T_{排队}$$

> ==发送时延看"数据多长 ÷ 网卡多快"，传播时延看"线多长 ÷ 光速多快"== —— 两者毫无关系。
> 波速：铜缆 / 光纤中约 $2\times10^8$ m/s，自由空间 $3\times10^8$ m/s。
> 单位记忆：==存储容量用 2 的幂（1 KB = 1024 B），速率用 10 的幂（1 kb/s = 1000 b/s）==。

## 1.2 体系结构与参考模型

**为什么要分层**：通信这件事太复杂，==切成几层、每层只解决一个问题==，层间约定好接口，就是"分而治之"。好处：各层独立演进、便于标准化。

**三个基本概念**（==关键是分清水平 / 垂直==）：

| 概念 | 方向 | 含义 |
| --- | --- | --- |
| **协议** | ==**水平**==（对等层之间） | 通信规则，三要素：**语法、语义、同步** |
| **服务** | ==**垂直**==（下层 → 上层） | 下层向上层提供的功能 |
| **接口（SAP）** | 垂直 | 上层使用下层服务的地方，如**端口号**就是传输层的 SAP |

> ==协议是"对等层怎么谈"，服务是"下层给上层什么"==。
> ==上层只用下层的服务，看不见下层的协议== —— 下层换实现，上层不受影响。

**OSI 参考模型 vs TCP/IP 模型**：

| OSI 七层 | TCP/IP 四层 | 五层（教学用） | 干什么 | 数据单元 |
| --- | --- | --- | --- | --- |
| 应用层 / 表示层 / 会话层 | **应用层** | 应用层 | 面向具体应用 | 报文 |
| 传输层 | 传输层 | 传输层 | ==进程到进程==（靠**端口**） | 报文段 |
| 网络层 | 网际层 | 网络层 | ==主机到主机==（靠 **IP 地址**） | 分组 |
| 数据链路层 | 网络接口层 | 数据链路层 | ==点到点==（靠 **MAC 地址**） | 帧 |
| 物理层 | （并入上面） | 物理层 | 传比特 | 比特 |

> - OSI 顶部三层被 TCP/IP 合成一层：==会话层管对话、表示层管格式/加密/压缩，TCP/IP 认为这些该由应用自己管==。
> - ==OSI 是"先有模型、后有协议"（理论先行）；TCP/IP 是"先有协议、后有模型"（实践总结）== —— 这是 OSI 失败、TCP/IP 胜出的根本原因。
> - TCP/IP 的**网络接口层**没规定具体内容，所以它==能在任何网络上跑==。

### 全书地图：数据在每层被加了什么

| 层 | 加什么 | 这一段"地址"管什么 |
| --- | --- | --- |
| 应用层 | 用户数据 | —— |
| 传输层 | ＋首部（**端口号**） | 哪个**进程** |
| 网络层 | ＋首部（**IP 地址**） | 哪台**主机**、在哪张网 |
| 数据链路层 | ＋帧头帧尾（**MAC 地址**） | 本段内**哪块网卡** |
| 物理层 | 变成**比特流** | —— |

> ==向下每走一层多一个首部，向上每走一层剥掉一个==。这张表就是第 3~6 章的目录：==3 章讲帧、4 章讲 IP、5 章讲端口、6 章讲应用==。

# 2 物理层

> **主线**：物理层只干一件事 —— ==把比特 0/1 变成信号送出去，并规定好接口==。它不管对错、不管发给谁，那些是上面几层的事。
> 全章回答四问：**信号怎么表示比特**（编码与调制）、**最快能多快**（奈奎斯特 / 香农）、**在哪传**（传输介质）、**传不远怎么办**（中继器、集线器）。外加一个宏观话题 —— **整条路怎么走**（交换方式）。

## 2.1 通信基础

### 基本概念

| 术语 | 含义 |
| --- | --- |
| **信源 / 信宿** | 发的一方 / 收的一方 |
| **信道** | 信号的传输通道 |
| **码元** | 一个固定时长的信号波形，==可携带 1 位或多位比特== |
| **波特率**（码元速率） | 每秒传**几个码元**（Baud） |
| **比特率**（数据率） | 每秒传**几个比特**（b/s） |
| **带宽** | 频带宽度（Hz） |

**两者的关系**（==必考==）：

$$\text{比特率}=\text{波特率}\times\log_2 V$$

$V$ 是一个码元能取的**离散状态数**（电平数）—— ==一个码元带 $\log_2 V$ 位比特==。

> 例：波特率 1000 Baud、码元有 4 种状态 → 比特率 $=1000\times\log_2 4=2000$ b/s。

### 奈奎斯特定理 与 香农定理（两个公式，分工不同）

**奈奎斯特**（==理想低通、无噪声==）：

$$C_{\max}=2W\log_2 V\quad(\text{b/s})$$

$W$ 是带宽（Hz），$V$ 是码元的离散状态数。含义：==带宽定了，码元速率就封顶在 $2W$==。

**香农**（==有噪声==）：

$$C_{\max}=W\log_2\!\left(1+\frac{S}{N}\right)\quad(\text{b/s})$$

$S/N$ 是信噪比；用 dB 表示时，==$\text{dB}=10\lg(S/N)$==。

> ==两个定理的分工==：奈奎斯特管"**每秒最多传几个码元**"（$2W$ 个），香农管"**每个码元最多能带多少比特**"（受信噪比限制）。合起来才是真实上限。
> 例：带宽 3000 Hz、信噪比 30 dB → $S/N=1000$ → $C\approx3000\times\log_2 1001\approx30000$ b/s。

### 编码与调制

**数字数据 → 数字信号（编码）**：

| 编码 | 规则 | 特点 |
| --- | --- | --- |
| **不归零 NRZ** | 高电平 1、低电平 0 | 简单，==无法自同步== |
| **曼彻斯特** | ==每比特**中间必跳变**==，跳变兼作时钟 | ==波特率是数据率的 2 倍==（效率 50%），10M 以太网用 |
| **差分曼彻斯特** | 中间跳变只做时钟，==用"比特开始处有无跳变"表 0/1== | 抗干扰更强，802.5 令牌环用 |
| **4B/5B** | 4 位数据映射成 5 位码 | ==保证足够跳变==，效率 80%，100M 以太网用 |

**数字数据 → 模拟信号（调制）**：**ASK**（幅移）、**FSK**（频移）、**PSK**（相移）、**QAM**（幅度 + 相位联合，效率最高）。

> 曼彻斯特"中间跳变既当时钟又当数据"是它最大的特点：==接收方能自己提取时钟，不用额外同步==，代价是效率只剩 50%。

### 交换方式

| | 电路交换 | 报文交换 | 分组交换 |
| --- | --- | --- | --- |
| 要不要先建立连接 | **要**（呼叫） | 不要 | 不要 |
| 资源 | ==**独占**== | 存储转发 | 存储转发 |
| 时延 | 小、**固定** | **大** | 小 |
| 线路利用率 | **低** | 高 | 高 |
| 典型用途 | 电话 | 早期电报 | **数据（互联网）** |

> ==分组交换胜出的原因==：把长报文切成小分组，==流水线式地存储转发== —— 既省掉建链时间，又让这条线能被多个用户同时用。

**分组交换的两种方式**（==常考对比==）：

| | 数据报 | 虚电路 |
| --- | --- | --- |
| 连接 | **无连接** | **有连接**（先建立） |
| 路由 | ==每个分组**独立选路**== | 建立时定好，分组只带**虚电路号** |
| 到达顺序 | 不保证 | ==保证按序== |
| 出故障 | 灵活，可绕行 | 该虚电路上**全断** |

> 互联网用的是**数据报** —— ==IP 的"无连接"就来自这里==。虚电路的代表是 X.25、ATM。

## 2.2 传输介质

| 介质 | 特点 |
| --- | --- |
| **双绞线** | 便宜、最常用；==绞合就是为了抗干扰==；UTP（无屏蔽）/ STP（屏蔽） |
| **同轴电缆** | 抗干扰好、带宽比双绞线大；早期以太网、有线电视 |
| **光纤** | ==带宽极大、衰减小、不受电磁干扰==；单模（远、贵）／多模（近、便宜） |
| **无线** | 微波（视距传播）、红外、蓝牙 |

**物理层接口的四个特性**：==机械（引脚形状）／电气（电压范围）／功能（某条线干什么）／过程（规程：事件顺序）==。

## 2.3 物理层设备

| 设备 | 干什么 | 层次 | 注意 |
| --- | --- | --- | --- |
| **中继器** | ==放大、整形信号==，延长传输距离 | 物理层 | ==不能连接不同速率的网段==；==不隔离冲突域== |
| **集线器 Hub** | ==多端口中继器==，收到信号向所有其他端口转发 | 物理层 | ==全网一个冲突域==，共享带宽、半双工 |

# 3 数据链路层

> 一句话主线：物理层交上来的是==不可靠的裸比特流==，数据链路层要把它整理成==一个个帧==，并解决"帧的边界在哪、有没有错、发多快、多个站抢一条线怎么办"这四件事。

## 3.1 数据链路层的功能

**链路 vs 数据链路**：
- **链路**：==物理线路==本身（两结点间一段没有其他交换结点的通路）
- **数据链路**：链路 + ==实现通信协议的硬件和软件==（加上了控制逻辑）

**五大功能**（对应后面五个小节，一一对应记）：

| 功能         | 解决的问题       | 对应技术         |
| ---------- | ----------- | ------------ |
| ==封装成帧==   | 帧的边界在哪      | 帧定界、透明传输     |
| ==差错控制==   | 比特传错了怎么办    | 奇偶校验、CRC、海明码 |
| ==流量控制==   | 发太快接收方来不及   | 滑动窗口         |
| ==可靠传输==   | 帧丢了、乱序怎么办   | 停等、GBN、SR    |
| ==介质访问控制== | 多个站共享一条线怎么抢 | 信道划分、随机访问、轮询 |

**两种服务**：
- ==无确认无连接==：以太网用（不可靠，出错就丢，交给上层）
- ==有确认无连接==：802.11 无线局域网用（==误码率高，必须逐帧确认==）

> [!warning] 易错点
> 以太网==只检错不纠错==、==不重传==，CRC 出错直接丢弃，可靠性交给传输层（TCP）。802.11 反而是有确认的——因为无线信道太差。

***

## 3.2 组帧（封装成帧）

**目的**：让接收方能识别==帧的开始和结束==（帧定界）。

**四种方法**：

| 方法         | 做法                                  | 缺点                      |
| ---------- | ----------------------------------- | ----------------------- |
| **字符计数法**  | 帧首字节存==帧长==                         | ==计数字段一错，全乱==（无法恢复同步）   |
| **字符填充法**  | 用 SOH/EOT 定界，数据中出现控制字符前插 ==ESC==    | 与字符编码相关，通用性差            |
| **零比特填充法** | 标志 ==01111110==，数据中每 5 个连续 1 后插一个 0 | 硬件易实现，==最常用==（PPP、HDLC） |
| **违规编码法**  | 用曼彻斯特编码里的==非法电平组合==做定界              | 依赖特定物理层编码（802.3 用此法）    |

**透明传输**：数据中出现和定界符相同的比特串时，==也能正确传输==。字符填充、零比特填充都是为了实现透明传输。

## 3.3 差错控制

**总思路**：==检错==靠冗余码，==纠错==要么用纠错码（前向纠错），要么靠重传（后向纠错）。

### 码距：检错纠错能力的根源

**码距**：一种编码中==所有合法码字之间的最小汉明距离==（对应位不同的个数）。

- 检出 $e$ 位错：==$d \geq e + 1$==
- 纠正 $t$ 位错：==$d \geq 2t + 1$==（纠错要保证出错后离原码字最近，故需双倍余量）

| 编码 | 码距 | 能力 |
|---|---|---|
| 奇偶校验 | ==2== | 检 1 位错 |
| 海明码 | ==3== | ==纠 1 位错== |
| 海明码 + 全局校验位 | 4 | 纠 1 检 2（SEC-DED） |

### 检错编码

**1. 奇偶校验码**
加 1 位校验位，使总的 1 个数为奇/偶。==只能检出奇数个错==，无法纠错，检错能力最弱。

**2. 循环冗余码 CRC**
- 收发双方约定==生成多项式 G(x)==（$r+1$ 位，最高位和最低位必须为 1）
- 发送方：数据后补 $r$ 个 0，对 G(x) 做==模 2 除法==，余数（$r$ 位 FCS）替换那 $r$ 个 0
- 接收方：收到的整串再除 G(x)，==余数为 0 则无错==，否则丢弃

> [!warning] 易错点
> CRC 理论上能纠错，但==实际链路层只用它检错==，一旦出错直接丢帧。所以说以太网提供的是"==无比特差错=="，而非"==无传输差错=="（帧可能整体丢失）。

### 纠错编码：海明码

**思想**：多组交叉校验，让==失效校验位的编号之和 = 出错位的位号==。

**① 定校验位数**：$2^r \geq k + r + 1$（+1 留给"无错"状态）

| $k$ | 4 | 8 | 16 | 32 | 64 |
|---|---|---|---|---|---|
| $r$ | ==3== | ==4== | ==5== | ==6== | ==7== |

**② 排位置**：位号从 1 开始，$P_i$ 放 ==$2^{i-1}$ 号位==（1、2、4、8…），剩余位依次放数据位。以 $k=4$ 为例：

| 位号 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 内容 | $P_1$ | $P_2$ | $D_1$ | $P_3$ | $D_2$ | $D_3$ | $D_4$ |

**③ 定校验组**：把位号==拆成 $2^i$ 之和==，就归这几个 $P$ 管。如 $5 = 1+4$ → 受 $P_1, P_3$ 校验。整理得
- $P_1$：位 1,3,5,7 → $P_1 = D_1 \oplus D_2 \oplus D_4$
- $P_2$：位 2,3,6,7 → $P_2 = D_1 \oplus D_3 \oplus D_4$
- $P_3$：位 4,5,6,7 → $P_3 = D_2 \oplus D_3 \oplus D_4$

**④ 检错纠错**：各组重算偶校验得==校验子 $S_3S_2S_1$==（$S_i$ 对应 $P_i$，==$S_1$ 为最低位==），其值==就是出错位号==，为 0 则无错，取反该位即纠错。

***

**例**：$D_4D_3D_2D_1 = 1011$

$P_1 = 1\oplus1\oplus1 = 1$，$P_2 = 1\oplus0\oplus1 = 0$，$P_3 = 1\oplus0\oplus1 = 0$ → 海明码 ==1010101==

若收到 1010==0==01（第 5 位错）：$S_1 = 1\oplus1\oplus0\oplus1 = 1$，$S_2 = 0\oplus1\oplus0\oplus1 = 0$，$S_3 = 0\oplus0\oplus0\oplus1 = 1$
→ $S_3S_2S_1 = 101 = 5$，==第 5 位出错==，取反还原。

> [!warning] 易错点
> - $S_1$ 是==最低位==，位序别反
> - ==只能纠 1 位错==；错 2 位时校验子非 0 却指向错误位置，会==纠成新的错==
> - 要区分 1 位错与 2 位错，需加==全局偶校验位==（码距→4）：全局失败 → 1 位错可纠；全局通过但校验子非 0 → ==2 位错，仅报错==

## 3.4 流量控制与可靠传输

**三个概念的关系**（容易混）：
- **流量控制**：控制发送速率，==别把接收方缓存冲爆==
- **可靠传输**：==无差错、不丢失、不重复、按序==
- **滑动窗口**：==实现上面两者的统一机制==（窗口大小限制了发送速率，编号+确认+重传保证可靠）

### 三种协议对比

| 协议             | 发送窗口 $W_T$ | 接收窗口 $W_R$ | 确认方式     | 出错重传            | 序号位数 $n$ 的约束                                     |
| -------------- | ---------- | ---------- | -------- | --------------- | ------------------------------------------------ |
| **停止-等待**      | 1          | 1          | 逐个确认     | 重传该帧            | 1 位够（0/1 交替）                                     |
| **后退 N 帧 GBN** | ==$>1$==   | ==1==      | ==累积确认== | ==重传出错帧及其后所有帧== | $1<W_T \leq 2^n - 1$                             |
| **选择重传 SR**    | ==$>1$==   | ==$>1$==   | ==逐帧确认== | ==只重传出错的那一帧==   | $W_T + W_R \leq 2^n$，一般 $W_T = W_R \leq 2^{n-1}$ |

**串联理解**：
- 停等的问题是==信道利用率太低==（发一帧等一次 RTT）→ 引入流水线（连续发多帧）
- 连续发就得考虑"错一帧怎么办"：==全部重发== 就是 GBN（接收窗口 1，实现简单，但浪费带宽）；==只补那一帧== 就是 SR（接收方要缓存，实现复杂）
- 接收窗口 = 1 意味着==必须按序接收==，这就是 GBN 要回退的根本原因

**信道利用率**：
$$U = \frac{W_T \times T_{\text{帧}}}{T_{\text{帧}} + RTT + T_{\text{ACK}}}\ (\text{上限为 }1)$$
停等时 $W_T = 1$。

> [!warning] 易错点
> GBN 的序号约束是 $2^n - 1$ 而不是 $2^n$：若 $W_T = 2^n$，发送方无法区分"全部 ACK 丢失导致的重传"和"新一轮的帧"。

## 3.5 介质访问控制

**问题**：多个站共享一条广播信道，==怎么避免同时发导致的碰撞==。三条路线：

| 类别 | 思路 | 代表 | 特点 |
|---|---|---|---|
| **信道划分** | ==静态==分配，各站互不干扰 | FDM/TDM/WDM/CDM | 无碰撞，但==站少时浪费带宽== |
| **随机访问** | ==动态争用==，碰了再退避 | ALOHA、CSMA/CD、CSMA/CA | 轻载时效率高，==重载时碰撞多== |
| **轮询访问** | ==动态但有序==，轮流发言 | 令牌环 | 无碰撞、公平，但有==轮询开销== |

### 信道划分

- **FDM 频分**：分频段，==各站同时发、各占一个频带==
- **TDM 时分**：分时隙，==各站轮流占用全部带宽==；**统计时分复用 STDM** 按需分配时隙，效率更高
- **WDM 波分**：光的频分复用
- **CDM 码分**：每站分配一个==正交码片序列==（如 8 或 64 位），==同时同频发送==，接收方用内积规范化提取。$S \cdot S = 1$，$S \cdot T = 0$

### 随机访问（演化主线，重点）

**1. ALOHA**
- **纯 ALOHA**：想发就发，碰撞了随机等一会儿重发。==不听信道==，效率最低（18.4%）
- **时隙 ALOHA**：==只能在时隙开始时发==，把易损时间减半，效率 36.8%

**2. CSMA（载波监听多路访问）**——发前先听

| 类型 | 忙时怎么办 | 特点 |
|---|---|---|
| **1-坚持** | ==持续监听==，一空闲立即发 | 利用率高，但==多站等待时碰撞概率大== |
| **非坚持** | ==放弃监听==，随机等一段再听 | 减少碰撞，但==信道可能空闲浪费== |
| **p-坚持** | 空闲时以概率 $p$ 发送 | 折中，用于时隙信道 |

**3. CSMA/CD（碰撞检测）——有线以太网**
==边发边听==，一旦检测到碰撞==立即停发==并发干扰信号，然后退避重传。适用于==半双工总线==。

**4. CSMA/CA（碰撞避免）——无线 802.11**
详见 3.6。

> [!tip] 为什么无线不能用 CD，必须改成 CA
> 1. 无线适配器==难以边发边收==（发射信号远强于接收信号）
> 2. ==隐蔽站问题==：A、C 都能到 B 但互相听不到，"信道空闲"的判断不可靠
> 所以只能==事前避免==（预约信道 + 强制退避 + 必须 ACK），而不是==事后检测==。

### 轮询访问：令牌传递

令牌沿环依次传递，==拿到令牌才能发==。无碰撞、有确定的最大等待时延，适合重载和实时场景；缺点是==令牌开销、单点故障==。

## 3.6 局域网

### 基本概念与体系结构

**LAN 特点**：地理范围小、==误码率低==、由单一组织拥有、==广播式==通信。

**IEEE 802 体系结构**：把数据链路层拆成两个子层
- ==LLC（逻辑链路控制）==：向上屏蔽不同 MAC 的差异。==已被淘汰==（TCP/IP 不用它）
- ==MAC（介质访问控制）==：与具体介质、拓扑相关，是实际考点

**MAC 地址**：==48 位==，固化在网卡中。前 24 位是厂商标识（OUI）。
- 单播：第一字节最低位 = 0
- ==广播 FF-FF-FF-FF-FF-FF==
- 多播：第一字节最低位 = 1

***

### 以太网与 IEEE 802.3

**核心定位**：==总线型拓扑 + CSMA/CD + 无确认无连接==。逻辑上是总线（广播），物理上现代以太网是==星型（用交换机/集线器）==。

**两种以太网**：区别只在==用集线器还是交换机==，由此决定了要不要 CSMA/CD。

- **共享式以太网**：总线或==集线器（Hub）==连接。Hub 工作在==物理层==，只是多端口中继器，收到帧向==所有其他端口转发==，所以全网是==一个冲突域==，各站==共享总带宽==，==必须用 CSMA/CD==，只能==半双工==。
- **交换式以太网**：==交换机（Switch）==连接。交换机工作在==数据链路层==，按 MAC 地址表==只往目的端口转发==，==每个端口是独立的冲突域==，各站==独享带宽==，==不需要 CSMA/CD==，可==全双工==。

| 对比项 | 共享式（Hub） | 交换式（Switch） |
|---|---|---|
| 核心设备层次 | ==物理层== | ==数据链路层== |
| 转发方式 | 广播到所有端口 | ==按 MAC 表定向转发== |
| 冲突域 | ==全网 1 个== | ==每端口 1 个== |
| 带宽 | ==共享==（10M 接 8 台，每台约 1.25M） | ==独享==（每端口都是 10M） |
| CSMA/CD | ==必需== | ==不需要== |
| 双工 | ==半双工== | ==可全双工== |
| 广播域 | 1 个 | ==仍是 1 个==（需 VLAN 或路由器才能隔离） |

> [!warning] 易错点
> - 交换机==只隔离冲突域，不隔离广播域==。要隔广播域得靠 ==VLAN 或路由器==
> - 交换式以太网==不需要 CSMA/CD==，所以下面最小帧长、争用期那套推导==只对共享式成立==
> - Hub 不能连接不同速率的网段（它不缓存帧），==网桥/交换机可以==

**MAC 帧格式**（Ethernet V2，考试用这个）：

> 662N4，收发协数验。N是46－1500

| 字段 | 长度 | 说明 |
|---|---|---|
| 前导码 | 8 B | 7B 前同步码 + 1B 帧开始定界符，==用于同步，不计入帧长== |
| 目的地址 | 6 B | 目的 MAC |
| 源地址 | 6 B | 源 MAC |
| 类型 | 2 B | 上层协议（0x0800 = IP） |
| 数据 | ==46~1500 B== | 载荷 |
| FCS | 4 B | ==CRC 校验== |

**帧长限制**（必须背）：
- ==最小帧长 64 B==（不含前导码）= 6+6+2+46+4，数据不足 46 B 要==填充==
- ==最大帧长 1518 B== = 6+6+2+1500+4 帧长过大，长时间占用总线；或者接收端的缓冲区存不下
- MTU = ==1500 B==

> [!tip] 最小帧长 64 B 是怎么来的（串联 CSMA/CD）
> 为了保证发送方在==发完最后一个比特之前==就能检测到碰撞（A收到了B的数据帧），必须让
> $$T_{\text{发送}}\ (\text{就是发送时延}）\geq 2\tau\ (\text{一个争用期})$$
> 10 Mbit/s (信号传输率，可用奈龙公式计算出来）以太网端到端时延 $\tau = 25.6\ \mu s$，争用期 $2\tau = 51.2\ \mu s$，
> $$L = 10\ \text{Mbit/s} \times 51.2\ \mu s = 512\ \text{bit} = 64\ B$$
> 所以：==最小帧长 = 数据传输速率 × 争用期==。若帧太短，发完就走人，碰撞了也不知道。

**CSMA/CD 完整流程**：
1. 发前监听信道，==空闲则发==（1-坚持）
2. ==边发边听==
3. 检测到碰撞 → ==立即停发==，发送 ==32/48 位干扰信号==（强化碰撞）
4. 执行==截断二进制指数退避==后重试

**截断二进制指数退避**：
- 基本退避时间 = ==争用期 $2\tau$ == = 51.2 μs（10 Mbit/s）
- 第 $k$ 次碰撞，从 $\{0, 1, \dots, 2^k - 1\}$ 中==随机取一个数 $r$==，等待 $r \times 2\tau$
- $k = \min(\text{重传次数}, 10)$（==这就是"截断"==）
- ==重传 16 次仍失败则丢弃==并报告上层

> [!warning] 高频易错点
> - 碰撞检测发生在==发送过程中==，所以 CSMA/CD 只用于==半双工==。全双工（交换机端口）==不需要 CSMA/CD==
> - 集线器（Hub）工作在==物理层==，是一个==冲突域==，需要 CSMA/CD；交换机工作在==数据链路层==，每端口独立冲突域，==可全双工==
> - 以太网速率提升时，为保持最小帧长 64 B，必须==缩短最大网段长度==（因为 $L = C \times 2\tau$，$C$ 变大则 $\tau$ 必须变小）。千兆以太网因此引入==载波延伸和分组突发==

**以太网标准命名**：格式 ==速率 + 传输方式 + 介质==
- 速率：10 / 100 / 1000（Mbit/s）
- ==Base== = 基带传输（Broad 为宽带，几乎不用）
- 介质：==T== = 双绞线，==F/S/L== = 光纤（S 短波多模、L 长波单模），==5/2== = 粗/细同轴电缆

| 标准 | 速率 | 介质 | 网段长度 | 说明 |
|---|---|---|---|---|
| 10Base5 | 10M | 粗同轴 | 500 m | 最早，总线型 |
| 10Base2 | 10M | 细同轴 | 185 m | 数字 2 指约 200 m |
| 10BaseT | 10M | ==双绞线== | ==100 m== | ==星型 + 集线器==，T 是转折点 |
| ==100BaseT== | 100M | 双绞线 | 100 m | ==快速以太网==，可全双工 |
| 1000BaseT | 1000M | 4 对 UTP-5 | 100 m | 吉比特以太网 |
| 1000BaseSX/LX | 1000M | 多模/单模光纤 | 550 m / 5 km | 长距离干线 |
| 10GBase-S/L/E | 10G | 光纤 | 300 m~40 km | ==只工作在全双工，无 CSMA/CD== |

> [!tip] 三个记忆锚点
> - ==T 系列网段一律 100 m==（双绞线的物理限制，与速率无关）
> - 100BaseT 保持最小帧长 64 B 不变，靠==缩短争用期==（$\tau$ 减为 1/10）实现，所以==网段和跨距都变小==
> - ==10G 以太网起就只有全双工==，不再需要 CSMA/CD，此时"以太网"仅指帧格式相同

### IEEE 802.11 无线局域网

**与 802.3 的根本差异**（抓住这三点，其余都能推）：

| 对比项  | 802.3 以太网         | 802.11 无线                |
| ---- | ----------------- | ------------------------ |
| 介质访问 | ==CSMA/CD==（事后检测） | ==CSMA/CA==（事前避免）        |
| 可靠性  | ==无确认==，错了丢给上层    | ==必须逐帧 ACK==（误码率高）       |
| 地址数  | 2 个（源、目的）         | ==最多 4 个地址==             |
| 地址字段 | 目的 MAC + 源 MAC     | ==地址1=接收端，地址2=发送端，地址3/4 补充真正的源和目的== |
| 拓扑   | 总线/星型             | ==有基础设施（AP）或自组织 Ad hoc== |

**两种组网方式**：
- **基础设施模式**：有 ==AP（接入点）==，一个 ==BSS（基本服务集）== 由 AP + 若干站构成，AP 有 ==SSID== 和信道。多个 BSS 通过分配系统连成 ==ESS（扩展服务集）==
- **Ad hoc 自组织**：==无 AP==，各站直接对等通信

**站点接入 AP 的过程**：==扫描（被动听信标 / 主动发探测）→ 选择 AP → 关联 → 认证 → 获取 IP==

**CSMA/CA 流程**（对照 CSMA/CD 记）：
1. 监听信道，若空闲则等待 ==DIFS==，然后发送
2. 接收方正确收到后，等待 ==SIFS==，回送 ==ACK==
3. 若信道忙，或发送后未收到 ACK → 执行==二进制指数退避==

**关键机制**：
- **帧间间隔 IFS**：==SIFS < PIFS < DIFS==。间隔越短优先级越高，==ACK 用最短的 SIFS==，保证确认帧优先抢到信道
- **RTS/CTS**：一套机制同时做两件事——==信道预约==与==虚拟载波监听==，共同解决==隐蔽站问题==
  - 发送方先发 ==RTS==（请求发送），AP 广播 ==CTS==（允许发送），两者都携带==持续时间字段==
  - ==信道预约==：CTS 一发出，信道就归这对站所有，其余站不再争用。RTS 帧很短，==碰撞只可能发生在 RTS 上，代价远小于碰撞一个长数据帧==
  - ==虚拟载波监听==：所有听到 RTS 或 CTS 的站据持续时间字段设置 ==NAV（网络分配向量）==，NAV 未归零就不发送，==无须真的去监听信道==
  - 这就叫"虚拟"监听——==没听到信道忙，但知道信道将忙==。隐蔽站 C 听不到 A，但听得到 AP 的 CTS，于是知道该沉默
- **退避计时规则**：若退避时，信道变忙则暂停计时；待信道空闲，且==持续空闲时间满一个DIFS==后，从断点处继续计时，归零即发
- **强制退避**：即使信道一直空闲，==发完一帧后也必须退避==再发下一帧（进一步降低碰撞概率）

> [!warning] 易错点
> - CSMA/CA 中的 ==CA 是 Collision Avoidance（避免）==，不是 Detection
> - ==RTS/CTS 是可选的==，短帧不值得用（开销占比太大）
> - 802.11 的 ==ACK 是链路层的==，与 TCP 的 ACK 不是一回事
> - 无线信道==只能半双工==

**802.11 帧的 4 个地址**：因为帧要经过 AP 转发（站→AP→站），必须区分=="这一跳的收发方"和"最终的源与目的"==。

- **地址 1 = 接收端地址**（这一跳收帧的那个设备）
- **地址 2 = 发送端地址**（这一跳发帧的那个设备）
- **地址 3** = 补上被 AP 遮住的那一端（真正的源或目的）
- **地址 4** 只在==无线自身作为分配系统（AP 之间无线桥接）==时才用，考试基本不涉及

| 场景 | 地址 1（接收端） | 地址 2（发送端） | 地址 3 |
|---|---|---|---|
| 站 A → AP（上行） | AP | A | ==最终目的== |
| AP → 站 B（下行） | B | AP | ==原始源== |
| Ad hoc（站↔站直连） | 目的站 | 源站 | ==BSSID== |

> [!tip] 记法
> ==前两个地址永远是"这一跳"==，从这一跳的视角看谁收谁发，1是收，2 是发；地址 3 用来找回被 AP 挡掉的另一端。上行时 AP 挡住了目的，地址 3 就填目的；下行时 AP 挡住了源，地址 3 就填源。

***

### VLAN

**目的**：在==一台或多台交换机上==用软件划分==多个逻辑广播域==，==隔离广播、提升安全性、便于管理==。

**要点**：
- 同 VLAN 内可直接二层通信，==不同 VLAN 间必须经路由器（或三层交换机）==
- 划分依据：==按端口==（最常用）、按 MAC、按协议、按 IP 子网
- ==802.1Q 帧==：在以太网帧的源地址后插入 ==4 B 的 VLAN 标记==（含 12 位 VLAN ID），所以带标记的最大帧长变为 ==1522 B==

## 3.7 广域网

**WAN 特点**：范围大、由==电信运营商==管理、==点对点链路==为主（==不需要介质访问控制==，因为没有共享争用）。

> [!warning] 易错点
> 广域网工作在==物理层 + 数据链路层==（有的教材算到网络层，因为要用到分组转发）；局域网和广域网的区别==不只是地理范围==，更在于==拓扑与介质访问方式==。

### PPP 协议

**定位**：目前使用最广泛的==点对点数据链路层协议==（拨号上网、PPPoE）。

**三个组成部分**：
- ==LCP（链路控制协议）==：建立、配置、测试、拆除链路
- ==NCP（网络控制协议）==：为不同网络层协议协商参数（如分配 IP）
- ==高级数据链路控制的封装方法==

**特点**：
- ==只检错不纠错==、==不用序号、不重传==、==不支持多点线路==（只点对点）
- ==全双工==
- 支持==多种网络层协议==和多种链路类型

**帧格式**：
```
| F(7E) | A(FF) | C(03) | 协议 2B | 信息 ≤1500B | FCS 2B | F(7E) |
```
- 标志字段 ==F = 0x7E == 作定界
- 透明传输：==异步链路用字节填充（转义字符 0x7D）==，==同步链路用零比特填充==

## 3.8 网络互联设备

### 五类设备总览

**演化主线**：从==单纯放大信号==（不隔离任何冲突）→ ==按 MAC 隔离冲突域==→ ==按 IP 隔离广播域==→ ==按协议全面转换==。

| 设备 | 层次 | 作用 | 冲突域 | 广播域 |
|---|---|---|---|---|
| **中继器** Repeater | ==物理层== | ==放大/整形信号==，延长距离 | ==全部同一个== | 同一个 |
| **集线器** Hub | ==物理层== | 多端口中继器，==共享带宽、半双工== | ==全部同一个== | 同一个 |
| **网桥** Bridge | ==链路层== | 按 MAC 转发，==连接两个网段== | ==每端口独立== | 同一个 |
| **交换机** Switch | ==链路层== | ==多端口网桥==，独享带宽、可全双工 | ==每端口独立== | ==同一个==（除非划 VLAN） |
| **路由器** Router | ==网络层== | 按 IP 选路，==连接异构网络== | 每端口独立 | ==每端口独立== |
| **网关** Gateway | ==高层== | ==协议转换==，连接完全异构的系统 | 独立 | 独立 |

> [!warning] 高频易错点
> - ==中继器和集线器不隔离冲突域==，接在一起的所有站属于同一冲突域，共享总带宽（10 Mbit/s 的 Hub 接 8 台机，每台平均 1.25 Mbit/s）
> - ==交换机隔离冲突域但不隔离广播域==——广播帧仍会泛洪到所有端口。要隔离广播域只能用==路由器或 VLAN==
> - 网桥/交换机会==缓存并重新发送==帧，所以能连接==不同速率==的网段；中继器不能
> - 集线器==不能连接不同速率==的网段（纯物理层，无缓存）

### 以太网交换机（重点）

**本质**：==多端口网桥==，工作在==数据链路层==，每个端口是==独立的冲突域==（但所有端口默认在==同一个广播域==）。

**三大功能**：
1. **帧过滤与转发**：查==转发表（MAC 地址表）==，只往目标端口转发，==不广播到所有端口==
2. **自学习**：收到帧时，把==源 MAC + 进入端口==写入转发表（带超时时间）
3. **未知单播/广播处理**：目的 MAC 不在表中 → ==泛洪==（向除源端口外的所有端口转发）

**自学习 + 转发算法**（考试常考画表）：
1. 收到帧，==登记源 MAC 与端口==（更新转发表和计时器）
2. 查目的 MAC：
   - 表中有且端口 ≠ 源端口 → ==从该端口转发==
   - 表中有且端口 = 源端口 → ==丢弃==
   - ==表中无 → 泛洪==

**两种交换方式**：
- ==直通式==：只看目的地址（前 6 B）就转发，==延迟低但不检错==
- ==存储转发==：收完整帧、==做 CRC 校验==后再转发，可靠但延迟高

**生成树协议 STP**：交换机之间有环路会导致==广播风暴==，STP 通过==阻塞部分端口==构造无环生成树。

**交换机 vs 集线器**：

| 对比项 | 集线器 | 交换机 |
|---|---|---|
| 层次 | 物理层 | ==链路层== |
| 带宽 | ==共享==（$N$ 端口共 $C$） | ==独享==（每端口 $C$，总吞吐 $N \times C$） |
| 双工 | ==只能半双工== | ==可全双工== |
| CSMA/CD | ==需要== | ==不需要==（全双工时） |
| 冲突域 | 1 个 | ==$N$ 个== |

# 4 网络层

## 4.1 路由器与网络层的功能

> **主线**：网络层只干一件事 —— 把分组从一个网络送到另一个网络。干这活的设备叫**路由器**，而路由器可以劈成两半：一半负责**想**（往哪走），一半负责**做**（把包送出去）。这一节先把这两半立住，后面每一节都挂在它们上。

**网络层提供什么服务**：==无连接、尽最大努力交付（best effort）==。不建连接、不保证可靠、不保证顺序；可靠性交给传输层（TCP）去补。这是互联网的设计哲学：**网络简单，智能放在端系统**。

### 为什么要有网络层：异构网络互连

向下要接住各种物理网（以太网、Wi-Fi、PPP），向上要给传输层一个**统一的分组格式**。==网络层的任务就是让这些五花八门的网络"看起来像一张网"==，所以叫"异构网络互连"。

### 网络层的两个动作：路由 与 转发

这两个词最容易混，==考纲里是两个独立条目==：

| | 路由 routing | 转发 forwarding |
| --- | --- | --- |
| 干什么 | 决定往哪个方向走，**填表** | 拿一个包**查表**，定从哪个口发 |
| 看多远 | 全局，比较多条路径 | 局部，只看当前这一个包 |
| 谁干 | 控制平面 | 数据平面 |
| 快慢 | 慢，路由变化才动 | 快，线速，每个包都做 |

> 一句话：==**路由是"算路"，转发是"走路"**==。算路的结果写进表；走路时只查表，不重算。

### 谁在干：路由器 = 控制平面 + 数据平面

**控制平面（想）**：跑路由协议、和邻居交换信息、算出**路由表**。
**数据平面（做）**：把路由表提炼成**转发表**，包进来就查表、从对应接口发出。

> ==整章其实就在回答两个问题：**表从哪来**（4.5 / 4.6）、**表怎么用**（4.4）。==

### SDN：把控制平面抽出来

**一句话**：既然路由器内部分成"想"和"做"，那就把"想"这一半**抽出来、集中到一台远程控制器上** —— 这就是 SDN。==本质特征：控制平面与数据平面分离 + 集中式控制 + 开放可编程==。

**三层架构**：

| 层 | 是谁 | 干什么 |
| --- | --- | --- |
| 应用层 | 各种网络应用（流量工程、安全策略） | 提出"我要什么样的网络" |
| 控制层 | **控制器**（SDN 的大脑） | 掌握**全局视图**，把策略翻译成**流表**下发 |
| 数据层 | 交换机 / 路由器 | 只按流表**查表转发**，自己不做任何决策 |

**三个接口**（==考点集中在"哪个有标准"==）：

| 接口 | 连谁和谁 | 干什么 | 有标准吗 |
| --- | --- | --- | --- |
| **北向接口** | 应用层 ↔ 控制层 | 上层调用控制器、下发业务策略 | ==没有统一标准==（各家自定义）|
| **南向接口** | 控制层 ↔ 数据层 | 控制器给设备**下发流表** | ==有，就是 **OpenFlow**== |
| **东西向接口** | 控制层 ↔ 控制层 | 多控制器之间**同步全局视图** | 集群内部的事 |

> 记法：==**南向有标准（OpenFlow），北向没标准**== —— 最常见的考法。
> 控制器和设备之间那条通道叫**安全通道**；OpenFlow 交换机里存**流表**，表项 = 匹配字段（各层首部）＋ 动作（转发 / 丢弃 / 修改）。

### 拥塞控制：路由器的队列满了

**网络层看到的拥塞只有一种样子**：==路由器队列溢出、开始丢包==。网络层自己不"通知"拥塞，只负责丢；真正的降速由端系统（TCP）感知丢包后完成 —— ==网络层是施压方，不是解决方==。

两类做法：**开环**（事先预防：分组调度、丢弃策略）／ **闭环**（监测到拥塞再反馈、调整）。

### 哪些设备要配 IP（易考）

==交换机转发时不看 IP，所以不配 IP；路由器每个接口都必须配 IP==。判据只有一句 —— **这个设备要不要在第三层被寻址**：

| 设备 | 层次 | 转发依据 | 要配 IP 吗 |
| --- | --- | --- | --- |
| 集线器 | 物理层 | 不判断，直接广播 | 否 |
| 交换机 | 链路层 | 目的 **MAC** | 否 |
| 路由器 | 网络层 | 目的 **IP** | **是，每个接口都要** |
| 主机 / 服务器 | 三层实体 | —— | 是 |

> 例外：三层交换机的 VLAN 接口（SVI）要配 IP —— 因为它在**兼做三层的事**；二层交换机配"管理 IP"是工程现实，题干不提就不用管。
> 交叉：[[#3.8 网络互联设备]]（五类设备总览、交换机与集线器对比）。

## 4.2 IPv4 地址与编址

> **主线**：地址是路由器接口的"坐标"。转发表里写的、掩码算出的、DHCP 发下去的，是同一个东西 —— **网络前缀**。本节顺序：**地址长什么样 → 怎么切 → 怎么合并 → 不够用怎么办 → 主机怎么拿到**。

### IPv4 地址与分类

**IPv4 地址**：32 位，点分十进制写（每 8 位一个 0–255 的数），分成**网络号**（前段）+ **主机号**（后段）两级。==网络号决定"在哪张网"，主机号决定"是这张网里的谁"==。

**分类地址**（早期方案）：靠**首位模式**区分网络号长度。

| 类别 | 首位 | 默认掩码 | 网络号位数 | 用途 |
| --- | --- | --- | --- | --- |
| A | 0 | 255.0.0.0 | 8 | 超大型网络 |
| B | 10 | 255.255.0.0 | 16 | 中型 |
| C | 110 | 255.255.255.0 | 24 | 小型 |
| D | 1110 | —— | —— | **组播**（见 4.7） |
| E | 1111 | —— | —— | 保留 |

> 现在编址全用 CIDR，分类只是历史。但==默认掩码要记牢== —— 题目给的掩码常常就是某个类的默认值。

**这些地址不能配给主机**（==高频考点==，判据看**主机号**）：

| 地址 | 含义 | 能配吗 |
| --- | --- | --- |
| 主机号全 0 | **网络地址**（代表整张网） | 否 |
| 主机号全 1 | **直接广播地址**（本网段广播） | 否 |
| 255.255.255.255 | **受限广播**（本网广播，路由器不转发） | 否 |
| 0.0.0.0 | 本机 / 默认路由 | 否 |
| 127.x.x.x | **环回**（本机测试，不出网卡） | 否 |
| 网络号全 0 | "本网络"（ARP、DHCP 里用） | 否 |

> ==落在网段内 ≠ 可用==：一个网段的**第一个（全 0）和最后一个（全 1）永远不能用**。

### 子网掩码与子网划分

**子网掩码**：32 位，==网络位（含子网位）全 1、主机位全 0==。作用是把 IP 一劈为二：

$$\text{IP}\ \text{AND}\ \text{掩码}=\text{网络地址}\qquad \text{IP}\ \text{AND}\ \lnot\text{掩码}=\text{主机号}$$

**划分子网**：==从主机位**借**若干位当"子网号"==。借 $k$ 位 → 划出 $2^{k}$ 个子网；剩 $h$ 位主机位 → 每个子网 $2^{h}-2$ 个可用地址（减掉网络地址、广播地址两个）。

> ==子网划分是"单位内部事务"==：对外仍是一个网络，外面看不到你分了几个子网 —— 所以对外路由表可以很小。

**算地址三步**（==遇到"能不能配 / 有几个可用地址 / 分配是否合法"，先把这三行写在纸上==）：

1. 写出**掩码**，数出**主机位位数 $h$**
2. 算**块大小** $2^{h}$，把每个子网的**首地址（网络）**、**尾地址（广播）**各写一行
3. 题目给的 IP 只要等于首或尾 → **直接判不可分配**，别的都不用想

例：`192.168.1.0/27`，$h=5$，块 $32$
→ 子网 1：`192.168.1.0`（网络 ✗）～ `192.168.1.31`（广播 ✗），可用 `192.168.1.1–30`，共 **30** 个

> **自查**：数出的可用地址数如果正好等于 $2^{h}$，那你一定漏掉了首尾那两个。

### CIDR 与子块划分

**CIDR**：无类别域间路由，记法 `a.b.c.d/n`，==n 是网络前缀位数==，其余 32−n 位是主机位。取代 A/B/C 分类地址（类别位写死，地址浪费严重）；前缀长短随意，还能把连续小块聚合成一条路由（==路由聚合==，缩小路由表）。

**地址块大小**：$2^{32-n}$ 个地址，==含网络地址、广播地址两个不能分给主机==。

| 前缀 | 地址数 | 占 ／24 的份额 |
|---|---|---|
| /24 | 256 | 1 |
| /25 | 128 | 1/2 |
| /26 | 64 | 1/4 |
| /27 | 32 | 1/8 |

**子块划分**：往下切一层 ==前缀 +1、块数翻倍、每块减半==。整块画成二叉树：根 = 整块，每条边 = 切一层。

> [!warning] 划分合法的判据
> ==子块互不重叠，且并集恰好铺满整块==——树上同一父节点的左右分支==要么都用、要么都不用==。
> - 只切一个分支 → 另一分支整段地址悬空（==漏水==），凑不出“恰好 N 个子块”
> - 两个子块挤进同一分支 → 地址重叠（==重复封堵==），非法

**快算（份额法）**：把整块折成 $2^k$ 份（k = 最深前缀 − 原前缀），每个子块按大小折成份额，==所有子块份额之和必须恰好等于总份额==，多一分少一分都不行。

例：／24 恰好切 5 个子块 → /26 计 2 份、/27 计 1 份，总共要凑 8 份。“1个/26+4个/27”=6 份（漏水）；“4个/26+1个/27”=9 份（重叠）；“1个/25+4个/27”、“3个/26+2个/27”=8 份且树上铺得满 ✓（例题 [[408/每日一题/408每日一题#No.005 CIDR 地址块划分|每日一题计网 No.005]]）

### 路由聚合（构成超网）

==把若干连续的小地址块合成一个大块，唯一目的是缩小路由表==。做法是**找这组网络的公共前缀**，前缀长度取到"刚好能盖住全部"那一位。

例：`192.168.0.0/24` + `192.168.1.0/24` → 公共前缀 `192.168.0.0/23`（第 3 字节最后一位不同，前缀退一位）

> ==聚合的前提是"连续且对齐"==：`192.168.0.0/24` 和 `192.168.2.0/24` 不能聚成 /23 —— 中间还夹着 `192.168.1.0/24`，聚了会把不存在的地址也放进来。
> 钉子：聚合让转发表一条顶多条，但也带来"多条前缀都命中"的问题 —— 这正是 4.4 **最长前缀匹配**要解决的。

### NAT（网络地址转换）

**为什么需要**：==IPv4 地址不够用==。私网内部随便编，出门时由路由器统一换成公网地址。

**私有地址段**（只能内网用，公网不路由这三段）：

| 地址段 | 简写 |
| --- | --- |
| 10.0.0.0 – 10.255.255.255 | 10/8 |
| 172.16.0.0 – 172.31.255.255 | 172.16/12 |
| 192.168.0.0 – 192.168.255.255 | 192.168/16 |

**NAPT**（网络地址端口转换，==实际用的都是它==）：出方向把 `(内网IP, 端口)` 换成 `(公网IP, 新端口)`，回方向再按端口换回去 —— 靠**端口号**区分是内部哪台主机。

| 方向 | 改哪个 |
| --- | --- |
| 出（内 → 外） | 源 IP、源端口 → 公网 IP、新端口 |
| 入（外 → 内） | 目的 IP、目的端口 → 内网 IP、原端口 |

> 钉子：NAT 是**路由器上的功能**，也是"路由器每个接口都要配 IP"的另一面。
> 代价：==外网想主动连内网主机做不到==（NAT 表里没有对应条目），所以才需要端口映射 / 打洞。

### DHCP（动态主机配置）

**解决什么**：主机刚接入网络，==**还不知道自己该用哪个 IP**== —— 人工配不现实，靠 DHCP 自动要一个。

**四步**（全程 **UDP**，客户端端口 68、服务器端口 67）：

| 步 | 报文 | 方向 | 源 IP | 目的 IP | 说什么 |
| --- | --- | --- | --- | --- | --- |
| 1 | **DHCP DISCOVER** | 客户 → 广播 | `0.0.0.0` | `255.255.255.255` | "谁是 DHCP 服务器？我要 IP" |
| 2 | **DHCP OFFER** | 服务器 → 广播 | 服务器 IP | `255.255.255.255` | "我这有个 IP，给你" |
| 3 | **DHCP REQUEST** | 客户 → 广播 | `0.0.0.0` | `255.255.255.255` | "我选这个" |
| 4 | **DHCP ACK** | 服务器 → 广播 | 服务器 IP | `255.255.255.255` | "确认，归你了" |

> 记法：==客户发的源地址是 `0.0.0.0`，服务器发的源地址是服务器自己的 IP；**四条的目的地址全是广播**==。
> **MAC 地址同样看，规律更简单**：==源 MAC 一律是**自己网卡的 MAC**，目的 MAC 一律是 `FF-FF-FF-FF-FF-FF`==。
> - 客户此刻**没有 IP，却有 MAC** —— 这正是服务器能认出它的原因（DISCOVER 报文里带着自己的 MAC）。
> - ==**为什么目的 MAC 也必须广播**==：IP 层用了受限广播 `255.255.255.255`，帧的目的地址就**必须**是广播 MAC，否则本网段的网卡根本不会收下这个帧、更不会上送 IP 层。
> 为什么客户用 `0.0.0.0`：==它此刻还没有可用 IP，只能拿它填源地址==，意思是"我这没地址"。
> 为什么目的全是广播 —— 四步里有两种"广播"，动机不同：
> - 第 1、2、4 步是**不得已**：客户还没有正式可用的 IP，谁都单播不到它，只能广播。
> - 第 3 步是**有意为之**：客户已经知道该选哪个服务器了，本可以单播，==广播是为了让其他发过 OFFER 的服务器撤回==。
> 例外（**续租**）：客户已有 IP，此时 DHCP REQUEST 改成**单播**给原服务器（源 = 客户 IP，目的 = 服务器 IP）。

**拿到的不是一个 IP，是一套配置**：IP 地址、**子网掩码**、**默认网关**、DNS 服务器地址。

> 钉子：==**默认网关 = 路由器接口地址**==。DHCP 这一步，本质是把主机**接进路由器管辖区** —— 主机拿到 IP 和网关，才知道"本网段直接发，出网段统统交给网关"。
> 交叉：DHCP 报文里用的 `0.0.0.0` 和 `255.255.255.255`，正是本节开头"不能配给主机"表里的那两个。

## 4.3 IPv4 分组与分片

> **主线**：分组是路由器手里流动的"货物"。首部 20 字节里，==路由器真正要用的只有几个字段==，其余是留给源 / 目的主机的。分清"谁读哪几个字段"，比按顺序背 12 个字段省一半力气。

**首部固定 20 字节**（不含选项），最大 60 字节。字段按==路由器用不用==排：

| 字段 | 位 | 干什么 | 路由器拿它做什么 |
| --- | --- | --- | --- |
| 版本 | 4 | 4 = IPv4，6 = IPv6 | 判断是不是 IPv4 |
| 首部长度 | 4 | 单位 **4B**，最小 5（=20B）、最大 15（=60B） | 找数据的起点 |
| 区分服务 | 8 | 服务类型 / QoS 标记 | **不看** |
| 总长度 | 16 | 首部 + 数据，单位 1B，最大 65535 | 算数据长度，**分片要用** |
| 标识 | 16 | 同一数据报的所有分片**共用一个值** | 分片后靠它"认亲" |
| 标志 | 3 | DF（不许分片）／ MF（后面还有分片） | 分片、判最后一片 |
| 片偏移 | 13 | 本片数据在原数据报中的位置，单位 **8B** | 重组时定位 |
| **生存时间 TTL** | 8 | 每过一个路由器减 1 | ==**减 1；减到 0 丢弃 + 回 ICMP 超时**== |
| 协议 | 8 | 数据交给谁：TCP=6、UDP=17、ICMP=1 | **不看**（留给目的主机） |
| **首部检验和** | 16 | 只校验**首部**，不校验数据 | ==**TTL 变过，必须重算**== |
| 源 IP | 32 | 谁发的 | 一般不改（NAT 例外，见 4.2） |
| **目的 IP** | 32 | 发给谁 | ==**查转发表，定出口**（见 4.4）== |

> ==**转发时真正要动的只有三个**：目的 IP（查表）、TTL（减 1）、首部检验和（TTL 变了要重算）==。其余字段转发时原样不动。
> 记住这一条，题目问"转发过程中路由器修改了哪些字段"就能直接答。

### 分片：出口 MTU 装不下怎么办

**为什么要分片**：每种链路的 **MTU**（最大传送单元）不一样 —— 以太网 1500B，PPP 可能更小。==一个包从大 MTU 链路进、往小 MTU 链路出，装不下就必须切==。

**谁切、谁拼**（易考）：

| 动作 | 谁做 |
| --- | --- |
| 分片 | **路由器**（源主机也可以主动切） |
| 重组 | ==**目的主机**；中间路由器只转不拼== |

> 所以每个分片**各自独立转发**，可能走不同路径、也可能丢。==丢一片，整个数据报就废了== —— 靠上层重传整包。

**分片靠三个字段**：**标识**（同一批分片共用一个值，认亲）＋ **标志**（MF："后面还有片"；DF："不许分"）＋ **片偏移**（本片数据在原数据报中的位置）。

**关键约束**：==片偏移以 8B 为单位，所以**除最后一片外，每片数据长度必须是 8 的整数倍**==。

**算一遍**：数据部分 3000B，出口 MTU = 1500B

→ 每片最多装 $1500-20=1480$ B 数据（$1480=8\times185$ ✓），切成 **3** 片：

| 片 | 数据长度 | 片偏移（单位 8B） | MF |
| --- | --- | --- | --- |
| 1 | 1480 | 0 | 1 |
| 2 | 1480 | **185** | 1 |
| 3 | 40 | **370** | 0 |

> 检查：数据 $1480+1480+40=3000$ ✓；偏移换算成字节是 $0,\ 1480,\ 2960$ ✓。
> ==最后一片 MF = 0，前两片 MF = 1== —— MF = 0 就是"这是最后一片"的信号。

## 4.4 数据平面：一个包的转发全过程

> **主线**：把 4.2 的地址、4.3 的首部串起来 —— 一个包从进路由器到离开，走一条固定流水线。==ARP 和 ICMP 不是独立知识点，它们就是这条线上的第 4 步、和第 5 步"出事时的分支"==。

### 两张表：路由表 与 转发表

| | 路由表（RIB） | 转发表（FIB） |
| --- | --- | --- |
| 谁生成 | **控制平面**（路由算法 / 协议算出） | 从路由表**提炼**出来 |
| 记什么 | 目的网络 + 掩码 + 下一跳 + 接口 | 前缀 + 出口 |
| 干什么用 | **决策**：往哪个方向走 | **执行**：这个包从哪个口出 |
| 形态 | 软件表，更新慢 | 硬件（TCAM），线速查 |

> 关键在于：==表里只有**下一跳**，没有整条路径==。每个路由器只管"下一步交给谁"，全程路径是逐跳拼出来的 —— 这叫**逐跳转发**，也是 IP"尽力而为"的由来。

### 最长前缀匹配

**问题从哪来**：4.2 讲过的路由聚合 —— 表里可能同时有 `0.0.0.0/0`、`192.168.0.0/16`、`192.168.1.0/24`，一个目的 IP **三条都命中**。

**规则**：==选**前缀最长**（最具体）的那一条==，与度量值、表项顺序都无关。

例：目的 IP `192.168.1.5`

| 表项 | 命中？ | 前缀长 |
| --- | --- | --- |
| 0.0.0.0/0 | 是 | 0 |
| 192.168.0.0/16 | 是 | 16 |
| **192.168.1.0/24** | 是 | **24 ← 选它** |

> 顺带解释了**默认路由**：`0.0.0.0/0` 前缀长 0，==按规则永远排最后== —— 所以它天生就是"谁都匹配不上时兜底"。这不是特例，是规则的自然结果。

### 转发流水线：六步

| 步 | 干什么 | 用到什么 |
| --- | --- | --- |
| 1 | 进口收到帧 → **剥掉帧头帧尾**，取出 IP 分组 | 链路层 |
| 2 | 拿**目的 IP** 查转发表，**最长前缀匹配** | 4.2 掩码 |
| 3 | 命中 → 得到**下一跳 IP** 和**出口接口** | 路由表 |
| 4 | 把下一跳 IP 解析成 **MAC** | **ARP**（见下） |
| 5 | **TTL 减 1**（为 0 就丢 + 回 ICMP 超时）＋ **重算首部检验和** | 4.3 首部 |
| 6 | 重新封装成帧，从出口发出去 | 链路层 |

> 出口 MTU 装不下 → 中间插一步**分片**（见 4.3）。
> 若目的 IP 就是本机某接口的地址 → 不再转发，直接交给上层。
> ==走完这一路：**IP 的源 / 目的地址一字未改，而帧的 MAC 地址每过一个路由器就换一对**== —— 最常考的对比。

### ARP：已知 IP，求 MAC

**为什么需要**：流水线第 4 步 —— 路由器知道下一跳的 **IP**，可链路层送帧只认 **MAC**。

**过程**（==请求靠广播，应答靠单播==）：

1. 先查 **ARP 高速缓存**，命中就直接用（缓存有生存时间）
2. 没命中 → **广播**请求，目的 MAC 填 `FF-FF-FF-FF-FF-FF`："谁的 IP 是 x.x.x.x？把 MAC 告诉我"
3. 目标主机**单播**应答，报上自己的 MAC
4. 双方都写进缓存

**三个考点**：

- ==**ARP 只在本局域网内工作**==。跨网段时，源主机解析的是**默认网关的 MAC**，不是目的主机的 MAC —— 因为帧只在本段内送。
- ==ARP 归**网络层**==（虽然它处理的是 MAC 地址）：它用 IP 地址，站在网络层与链路层的界面上。
- 与 DHCP 的分工：==DHCP 给主机 IP，ARP 帮主机找到网关的 MAC==。

### ICMP：网络层的信使

**作用**：==IP 自己不会报错，出错时由 ICMP 把消息送回**源主机**==。

| 类别 | 有哪些 | 用途 |
| --- | --- | --- |
| **差错报告** | 终点不可达 / **时间超过** / 参数问题 / 改变路由 | 告诉源主机"送不到 / 过期了" |
| **询问** | 回送请求与应答 / 时间戳请求与应答 | 主动探测 |

**怎么封装**：ICMP 报文装在 **IP 分组的数据部分**，协议号 **1**。==所以它是**网络层**协议，不是传输层==（虽然看着像在"传消息"）。

**两个经典应用**：

- **ping** —— 用**回送请求 / 应答**
- **traceroute** —— 依次发 TTL $=1,2,3,\dots$ 的分组，每到一个路由器就触发"时间超过"，==靠 ICMP 超时报文把路径一节一节骗出来==

**两条禁忌**（防止无限循环）：

- ==对 ICMP 差错报文，不再发 ICMP 差错报文==
- 对**分片后的非第一片**不发差错报文

## 4.5 控制平面：路由算法

> **主线**：4.4 讲的是"表怎么用"，这一节回答"**表从哪来**"。所有动态算法只分两家 —— **距离-向量**（道听途说）和**链路状态**（人手一张地图）。

### 静态路由 vs 动态路由

| | 静态路由 | 动态路由 |
| --- | --- | --- |
| 谁定 | 管理员手工配 | 路由协议自动学 |
| 拓扑变了 | **不会自己变** | 自动适应 |
| 开销 | 无 | 占带宽、占 CPU |
| 用在哪 | 小网络、**默认路由**、拓扑稳定处 | 大网络 |

> 静态不等于落后：==默认路由 `0.0.0.0/0` 通常就是手工配的== —— 一条顶一万条。

### 两家动态算法

**距离-向量（DV）**：==只和**邻居**说话，把**整张路由表**端过去==。邻居收到后：
$$\text{我到 }X\text{ 的距离}=\min\Big(\text{原来的},\ \text{邻居到 }X\text{ 的距离}+\text{我到该邻居的距离}\Big)$$

> ==好消息传得快，坏消息传得慢==。X 断了：A 本来 1 跳到 X；邻居 B 说"我 2 跳到 X"，A 就信了 → 改 3 跳；B 再听 A 说 3 跳 → 改 4 跳……==一圈圈加到"不可达"才知道 X 真没了==，这叫**计数到无穷**（路由环路）。
> 三个补丁：**最大跳数封顶**（RIP 用 16 表示不可达）、**水平分割**（不回传给自己的信息）、**毒性逆转**。

**链路状态（LS）**：==用**洪泛**把自己"直连链路的状态"发给**全 AS 每一台路由器**==。于是人人手里都有一张**完整拓扑图**，各自跑 **Dijkstra** 算最短路。

| | 距离-向量 | 链路状态 |
| --- | --- | --- |
| 告诉谁 | 只告诉**邻居** | **洪泛**给全网 |
| 告诉什么 | **整张路由表** | 只报**自己的直连链路** |
| 每台路由器知道什么 | 只有邻居的"传闻" | **全局拓扑图** |
| 算法 | Bellman-Ford | Dijkstra |
| 收敛 | 慢 | **快** |
| 环路 | 可能有 | **无** |
| 代表 | **RIP** | **OSPF** |

> 一句话记法：==距离-向量是"道听途说"，链路状态是"人手一张地图"==。

### 层次路由

**为什么**：互联网太大 —— 全局一张图存不下，洪泛也扛不住。

**怎么做**：切成**自治系统 AS**，==AS 内部怎么走，外面不用知道==。对外只暴露**边界路由器**。

- **域内**用 IGP，**域间**用 EGP
- 好处：路由表变小、洪泛范围受控、各 AS 能自主定策略

> 钉子：==层次路由是 4.6 的地基== —— 域内协议（RIP / OSPF）与域间协议（BGP）的分工，就是从这儿来的。

## 4.6 路由协议

> **主线**：4.5 讲原理，这一节讲**落地**。三个协议只要记住"**谁告诉谁 / 报什么 / 怎么算**"三问，就全分清了。

**自治系统 AS**：==由同一机构管理、执行**统一路由策略**的一组网络==，有唯一 AS 号。

**域内 vs 域间**（==最容易混的一点==）：

| | 域内 IGP | 域间 EGP |
| --- | --- | --- |
| 目标 | 找**最优**路径 | 找**可达且合规**的路径 |
| 看重 | **性能**（跳数、带宽、时延） | **策略**（商业关系、安全） |
| 协议 | RIP、OSPF | BGP |

> ==域间路由的核心不是"最短"，是"策略"== —— 两个 AS 之间因为商业关系不走最优路径，是正常的。

### RIP

**算法**：距离-向量。**度量**：**跳数**，==16 跳 = 不可达==（所以 RIP 只能管小网络，最大 15 跳）。

**交换**：==每 **30 秒**和邻居交换一次**整张路由表**==（跑在 **UDP 520** 上）。

**特点**：简单、慢收敛、有计数到无穷风险（靠水平分割 / 毒性逆转缓解）。

### OSPF

**算法**：链路状态。**度量**：**带宽 / 费用**（不只看跳数）。

**交换**：==用**洪泛**把链路状态发给**整个 AS**==，各自跑 Dijkstra。

**特点**：

- 收敛快、**无环路**
- 支持**划分区域**（骨干区 0 号），洪泛被限制在区内
- ==**直接用 IP**（协议号 89），不套 UDP / TCP==（考点）
- **触发式更新**：拓扑变了才发，不是定时全量

### BGP

**算法**：路径-向量。**度量**：==不是距离，是**路径属性**（AS 路径等）==。

**交换**：==只跑在 **AS 之间**，用 **TCP 179**== 建连接后交换路由。

**特点**：看重**策略**而非性能；只在 AS 边界路由器之间跑；交换的是"到某个网络要经过哪些 AS"。

### 三协议对比（==这张表背下来就够==）

| | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 类型 | 域内 IGP | 域内 IGP | **域间 EGP** |
| 算法 | 距离-向量 | **链路状态** | 路径-向量 |
| 度量 | 跳数（16 = 不可达） | 带宽 / 费用 | **路径属性（策略）** |
| 告诉谁 | 邻居 | **全 AS 洪泛** | AS 之间 |
| 承载 | **UDP 520** | **直接用 IP（89）** | **TCP 179** |
| 更新 | 30 秒定时、全表 | **触发式**、只报变化 | 触发式 |

> 三问自测：**告诉谁？报什么？怎么算？** —— 答得出这三句，RIP / OSPF / BGP 就分得开，也不会和 4.5 的两大算法脱节（==RIP 就是距离-向量的落地，OSPF 就是链路状态的落地，BGP 是第三家==）。

## 4.7 边界情况：IP 组播 与 移动 IP

> **主线**：前面讲的都是"一对一"的转发。这一节是两种例外 —— **一对一组**（组播）和**主机换网**（移动 IP），考频低，知道怎么串就行。

### IP 组播

**概念**：==一个源，发给**一组**主机==。比广播精确（不打扰无关主机），比单播省带宽（源只发一份）。

| 组播                                |     | 单播          | 广播                       |
| --------------------------------- | --- | ----------- | ------------------------ |
| **一组**                            | 发给谁 | 一个          | 本网段**所有**                |
| **D 类**：224.0.0.0–239.255.255.255 | 地址  | A / B / C 类 | 主机号全 1、`255.255.255.255` |

**怎么工作**：

- 组播地址==**只能做目的地址**，不能做源地址==
- 主机用 **IGMP** 告诉**本地路由器**："我要加入 / 退出这个组"
- 路由器之间跑**组播路由协议**，建出一棵**组播转发树**
- ==只在树的**分叉点**复制分组== —— 不是每个路由器都复制，这才是它省带宽的原因

### 移动 IP

**问题**：主机换了个网络，IP 一变，正在跑的 TCP 连接就断了。

**目标**：==IP 地址不变，照样通信==。

**三个角色**（==都在路由器上==）：

| 角色 | 在哪 | 干什么 |
| --- | --- | --- |
| 移动节点 | —— | 换网的那台主机 |
| **归属代理** | 归属网络 | 知道移动节点现在跑哪去了，负责**截获并转寄** |
| **外部代理** | 外地网络 | 给移动节点分配**转交地址** |

**过程（三步）**：

1. 移动节点到外地网 → 向**外部代理**注册，拿到**转交地址**；外部代理再告知**归属代理**
2. 别人发给它的包按原 IP 送到**归属网络** → **归属代理截获**
3. 归属代理用**隧道**（把包再封装一层）转发给外部代理 → 交给移动节点

> 反向不用绕：==移动节点发出去的包，源地址仍写自己的原 IP==，对方以为它还在家乡，所以可以直接发。

## 4.8 IPv6

> **主线**：IPv4 的地址不够用了 —— CIDR 和 NAT 只是续命，IPv6 是换一套根本方案。**地址变长、首部变简**是它的两条主线。

### 主要特点

| 变化 | 内容 | 为什么 |
| --- | --- | --- |
| 地址 | **32 位 → 128 位** | 根治地址耗尽 |
| 首部 | **固定 40 字节** | 定长好处理 |
| 检验和 | ==**取消首部检验和**== | 路由器不用每跳重算，**更快** |
| 分片 | ==**取消分片相关字段，路由器不再分片**== | 分片只由**源主机**做（用扩展首部） |
| 选项 | ==**取消选项**，改成**扩展首部**== | 首部保持定长，按需往后挂 |
| 配置 | 支持**地址自动配置**（即插即用） | 不依赖 DHCP 也能生成地址 |

> 剩下的字段只有 8 类：版本、通信量类、流标号、有效载荷长度、**下一个首部**（= IPv4 的协议）、**跳数限制**（= IPv4 的 TTL）、源地址、目的地址。

### IPv6 地址

**写法**：128 位，**冒号十六进制**（8 组，每组 4 位十六进制）。

**两条压缩规则**：

- 每组**前导 0** 可省
- ==连续的全 0 组可用 **`::`** 代替，但**一个地址里只能用一次**==

**三种类型**（==注意：没有广播==）：

| 类型 | 含义 |
| --- | --- |
| **单播** | 一对一 |
| **组播** | 一对多（一组） |
| **任播** | 一对"**最近的那一个**"（IPv6 新增） |

特殊地址：`::1` 环回（≈ `127.0.0.1`）、`::` 未指定（≈ `0.0.0.0`）、`FE80::/10` 链路本地地址。

### 过渡技术

| 方法 | 怎么做 |
| --- | --- |
| **双协议栈** | 一台设备同时跑 IPv4 和 IPv6，按目的地址选用哪套 |
| **隧道技术** | 把 IPv6 包整个塞进 IPv4 包里，穿过 IPv4 网络再取出来 |

# 5 传输层

发送窗口：发送方维护的一个发送数据的滑动窗口
​[已发已确认] | <左边界 [ 已发未确认 | 可发未发送 ] 右边界> | [暂时不能发]
​发送窗口的大小 = 第 2 段长度 + 第 3 段长度 = \min(cwnd, rwnd)。
​可用窗口的大小 = 仅指第 3 段的长度。

数据偏移（TCP报文段首部部分的字段）：即首部长度，单位为4B，因此该字段乘以4得到的值就是首部长度，并非偏移量。

# 6 应用层
