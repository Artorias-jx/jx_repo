# 一.绪论
## 1.数据结构与算法
**逻辑结构与存储结构**（物理结构）：
- **逻辑结构**指的是数据的关系，包括集合（数据之间无相关）、线性（一对一）、图（多对多）、树（==一对多==）
- **存储结构**指的是存储方法，有顺序存（地址连着）、链式（指针链接）、哈希（通过关键字算出地址）、索引（额外存储一个索引表）
## 2.算法时空复杂度
==重点==
**特性**：确定性、有穷性、可行性、I、O。**评估**：正确性、健壮性等，==不仅仅通过时间和空间复杂度==
**时间复杂度**：==一般指最坏==。**简单算法**：单变量，直接算；多变量，列举i与j的变化，求和找出与n的关系
**空间复杂度**：==只算额外开销==，比如需要额外一个与输入规模n同阶的数组，空间复杂度就是 $O(n)$，如果额外开销与数据规模n无关则 $O(1)$
[时间复杂度等价替换](琐碎知识点/时间复杂度等价替换.md)
# 二.线性表
## 1.顺序表
**存储地址直接相连**，如数组。静态分配方式和动态分配方式
==支持随机存取==，但是插入和删除比较麻烦：前者插入后需要后面的元素向后移动一位，后者则往前。时间复杂度为 ==$O(n)$==。
==重点是代码题==：如辅助数组的应用、双指针、快慢指针、三指针、数组逆置等。
- 做法：认真读题，抓住题目重点，简化题目所求条件，根据题目限制找到常用暴力解法。
- 快速想到时间复杂度尚可的暴力解，最优解一般不想。可适当列举几个情况进行模拟来判断代码的正确性。

## 2.链表
**存储地址不直接相连**，而是通过开辟一个空间存指针，指针指向下一个元素的地址。
==不支持随机存取==，但是插入和删除元素比较简单，但是仍要找到上一个节点以修改指针，==时间花在查找上==。
**头结点**：新增一个指向首元结点的节点，==不存数据==，为了==操作的统一性==，头指针head指向头结点。
- **单链表**：最基础的链表，只有一个next指针，重点是操作：头插和尾插，==头插法可以用于链表逆置==
- **双向链表**：新增一个prior指针指向前驱，==如果已知当前结点==，那么插入和删除时间复杂度为 ==$O(1)$==
- **循环单链表**：新增一个尾指针指向头结点，**判空**：==`l->next == l`==，头结点的next指向自己。==仅需一个尾指针==即可完成在表头和表尾进行插入和删除。若只有头指针，则查找表尾需要复杂度 $O(n)$
- **循环双链表**：新增一个prior指针指向前驱，==头节点的prior指向尾节点==，查找节点方便，但操作复杂
- **静态链表**：用结构体类型的数组模拟链表，游标部分存储下一个结点的数组下标，数据部分用来存数据。==尾结点为-1==
## 3.顺序表和链表的比较
1. **存取方式**：前者==支持随机存取==，后者==只能顺序存取==
2. **逻辑结构与物理结构**：==逻辑结构都是线性==，物理结构前者是顺序存储，后者是链式存储
3. **查找、插入和删除**：若按值查找，无序则都为 $O(n)$，若有序，==顺序表可用折半查找==，优化为 $O(\log n)$。按序号查找，前者 ==$O(1)$==，后者 ==$O(n)$==。插入、删除：顺序表==平均移动一半的元素==，而链表只需要移动指针，==但是查找操作需要 $O(n)$==
4. **空间分配**：顺序表静态不方便，动态可能浪费，链表额外存储指针域，==存储密度小于1==
5. **应用选择**：频繁查找序号，则顺序表；频繁插入删除则链表

## 4.选择题重点
- **结构选择**：对频繁的操作来选取合适的线性表的结构
- **复杂度要求**：对时间复杂度的要求来选取合适的结构
- **指针操作**：对常用操作所需指针的变化熟练掌握，**判空判满**
- **边界情况**：删除结点时注意删除时结点的数量，特殊情况：只有一个首元节点
- **操作顺序**：熟练指针的变化来判断对应的操作，注意指针变化的先后顺序能不能颠倒

# 三.栈与队列
## 1.栈
**入栈/出栈**：按入栈次序写，分析选项的出栈顺序，==对应一个删去一个即可==
**栈的合法出栈序列数**（n 个互异元素、栈容量不限）：$$C_n = \frac{1}{n+1}C_{2n}^{n}=\frac{(2n)!}{(n+1)!n!}$$ 这个数列叫 **卡特兰数**（Catalan）。#卡特兰数

**递推式**：$C_n=\sum_{i=0}^{n-1}C_iC_{n-1-i}$，$C_0=C_1=1$。前几项 ==1, 1, 2, 5, 14, 42, 132==（$n=0\sim6$），408 常考到 $C_4=14$。

**408 会考的卡特兰数场景**：

| 计数对象                 |  结果   | 说明                      |
| -------------------- | :---: | ----------------------- |
| n 个互异元素的**合法出栈序列数**  | $C_n$ | 反推：由出栈序列数合法入栈序列也是 $C_n$ |
| n 个结点的**不同二叉树形态数**   | $C_n$ | 只数形态，不看结点值              |
| 只给先序序列，**可能的二叉树数目**  | $C_n$ | 缺中序 ⇒ 不唯一（2015-02 考点）   |
| n 个关键字的**不同二叉排序树数目** | $C_n$ | 关键字已定序，BST 形态与二叉树形态一一对应 |
| n 对括号的**合法匹配序列数**    | $C_n$ | 左括号=入栈、右括号=出栈           |

> [!warning] 易错点
> - ==卡特兰数的前提是"元素互异 + 栈容量不限"==；栈容量若限定为 $k$，合法出栈序列数一般**不是**卡特兰数。
> - ==只给先序序列求二叉树数 = $C_n$；先序 + 中序则唯一确定==——前者是计数题，后者是建树题。
> - $C_n$ 数的是"个数 / 形态数"，不是某一条遍历序列本身。

[二叉树非递归遍历的指针与栈映射机制](琐碎知识点/二叉树非递归遍历的指针与栈映射机制.md)

## 2.循环队列
**队首**：删除元素的地方。**队尾**：加元素的地方。
**核心策略**：==默认牺牲一个空位==来避免**判空和判满**使用同一语句。
详见 [循环队列常见两种情况](琐碎知识点/循环队列常见两种情况.md)

**判空 / 判满的三种写法**（$M$ = MaxSize）：

| 方式 | 队满条件 | 队空条件 | 元素个数 |
| --- | --- | --- | --- |
| ① 空一法（牺牲一个单元） | $(rear+1)\%M == front$ | $front == rear$ | $(rear-front+M)\%M$ |
| ② 计数法（增设 `size`） | $size == M$ | $size == 0$ | $size$ |
| ③ 标记法（增设 `tag`，入队置 1、出队置 0） | $front==rear \;\&\&\; tag==1$ | $front==rear \;\&\&\; tag==0$ | $(rear-front+M)\%M$ |

> ①的约定：队头指针在队尾指针的**下一个位置**即为队满，`rear` 所指那格就是牺牲的空位。

## 3.数组和特殊矩阵
###  二维数组：m 行 n 列
1. **按行优先**：设 $a_{ij} = S_{ij}$，则同列下一行的元素地址：$a_{(i+1)j} = S_{ij} + L \cdot n$ （$L$ 是每个单元大小）
2. **核心技巧**：可用于快速求给定位置元素的地址。**算出对应行，再依次往后加即可**。
3. **例题实操**：已知 $A[1][1] = 420$，$A[3][3] = 446$，$L = 1$，求 $A[5][5]$：
	- 先向下推导到第 3 行第 1 列：$A[3][1] = 420 + 2n$
	- 再向后推导到第 3 行第 3 列：$A[3][3] = 420 + 2n + 2 = 446$，解得：$2n + 2 = 26 \implies n = 12$
	- 继续推导至第 5 行第 5 列：$A[5][5] = A[3][3] + 2n + 2 = 446 + 2n + 2 = 446 + 26 = 472$
### 对称矩阵与三角矩阵
1. **下三角矩阵**：第 $i$ 行有 $i$ 个元素。
2. **上三角矩阵**：第 $i$ 行有 $n - i + 1$ 个元素（第 1 行有 $n$ 个，第 2 行有 $n-1$ 个...）。
3. **核心策略**：无论是按行还是按列存储，不需要死记公式，**依次推即可**。
###  三对角矩阵
1. **一般按行优先**：求第 $i$ 行，第 $j$ 列（==$i, j$ 都从 1 开始==）
	**计算公式**：$3(i-1) - 1 + j - i + 1 \;=\; 2i + j - 3$
	**公式拆解**：$3(i-1) - 1$ 代表该行第一个元素的地址（它前面有 $3(i-1)-1$ 个非零元）；$j - i + 1$ 代表在该行内的偏移量，取值范围为 `[0, 1, 2]`。
	> 算出的 $k$ 是**一维数组的存储下标（从 0 开始）**——别把这里的"0 开始"错记到 $i, j$ 头上。
2. **按列优先**：**计算公式**：$3(j-1) - 1 + i - j + 1$；**核心策略**：将按行优先公式中的 $i$ 与 $j$ **互换即可**。

# 四.KMP
## 1. 时间复杂度对比
$O(m+n)$：KMP 算法。主串移动 $m$ 次，指针不会返回（回溯）。
$O(mn)$：暴力求法（BF 算法）。主串移动后指针会返回 $0$。
## 2. 求子串 $T$ 的 `next` 和 `nextval` 数组 与右滑距离
[KMP求next和nextval数组](琐碎知识点/KMP求next和nextval数组.md)
实际做题时，通常从 `next[3]` 和 `nextval[2]` 开始求解。（注：此规律基于**下标从 1 开始**的情况。若题目要求下标从 0 开始，则整体减 1）。

> [!tip] 下标从 0 开始：整体减 1（2015-8）
> ==下标和值一起减 1==，next、nextval 都适用。最易错是**哨兵**：1 基 $next[1]=0$ → 0 基 $next[0]=\mathbf{-1}$（不是 0）。
> 例：`abaabc` 的 1 基 $next=[0,1,1,2,2,3]$ → 0 基 $next=[-1,0,0,1,1,2]$（正合 2015-8 的表）。
> 移动距离 $j-nextval[j]$ 形式不变（两端都减 1，差值不变）。
## 3. 匹配与失配时的指针
- ==匹配 $S[i]==T[j]$== → $i$、$j$ 同时 +1（一起向前走）。
- 失配 $S[i] \neq T[j]$：令 $j = \text{nextval}[j]$ 或 $j = \text{next}[j]$，将跳转后的新位置记为 $k$，再从 $S[i]$ 与 $T[k]$ 重新比较。
- ==失配时主串指针 $i$ 不回退==，只滑模式串——这就是 KMP 比 BF 省时之处。
## 4. 边界情况（指针为 0 时）的物理意义
**只要 $j$ 变到 0（无论是 `next` 还是 `nextval`），无脑执行 $i$ 与 $j$ 移动 1 位，即用主串的新字符补充模式串的首字符。 j=nextj 就是 j 要移动到的位置，若 nextj 为 0 或者 nextvalj 为 0 就表示不需要移动，直接让 i 加 1，j 为 1 （相当于 j 等于 0 加 1）即可**

# 五.树
## 1.树的结构与性质
**树的定义**：一对多结构，可顺序存储，可链式存储。
**度的概念**：结点的度 = ==该结点的孩子数==（即拥有的子树数，叶子度为 0）。**树的度** = 各结点度的最大值。
**路径长度**：根节点到叶结点的边的个数。
**结点个数公式**：$n = \text{总度数} + 1$（树的"度" = ==结点的孩子数==，叶子度为 0）
	理由：==每条边恰好对应一个孩子结点==（除根外，每个结点有且只有一条边连向父结点）→ **边数 = 总度数**；而 $n$ 个结点的树恰有 $n-1$ 条边 → 总度数 $=n-1$ → $n=\text{总度数}+1$。
	==叶子不破例==：叶子度为 0、不计入总度数，但它作为**结点**计入 $n$，它连向父结点的那条边记在**父结点的度**里。
## 2.二叉树
1. **定义**：二叉树指 度不大于2的树。
2. **有序性**：二叉树的子树有明确的次序，固定，不能交换，属于有序树。
3. **满二叉树**：结点满。
4. **完全二叉树**：给结点编号，现有的结点编号与满二叉树中的对应的相同。完全二叉树中如果有度为1的结点，那么只会有一个，如果有第二个，那么编号会对不上。只有最后两层有叶结点。
5. **二叉排序树（BST）**：左子树关键字 < 根节点关键字 < 右子树关键字，具有递归性。
6. **平衡二叉树（AVL）**：任意一个结点左子树的度与右子树的度的差的绝对值 ≤ 1。
7. **结点数公式**：$n_0 = n_2 + 1$；$n_1$ 消去了。完全二叉树可以用这个结论来算结点数。（非空）
8. **高度与结点数**：高度 $h = \lceil \log_2(n+1) \rceil$ 的上界，$n$ 是结点数。满二叉树的结点数 = $2^h - 1$
## 3.二叉树的遍历和线索二叉树
==重点==
1. **中序遍历的边界结点**
	**第一个结点**：整棵树最左下的结点（一直向左走到底）。
	**最后一个结点**：整棵树最右下的结点（一直向右走到底）也是绝对位置最靠右的结点，若一棵完全二叉树没有右子树，那么最右侧就是根。
2. **序列推导：先/后序 + 中序 确定二叉树**
	**定根**：先序序列的第一个结点，或后序序列的最后一个（倒数第一个）结点，必然是当前树（或子树）的根结点。
	**划界**：找到根结点后，在中序序列中定位该结点，以此为界将中序序列分为两部分。然后再对左右两部分分别递归寻找左、右子树的根。
3. **序列推导：仅给先序和后序（确定中序可能性/结点度数）**
	**结构对位法**：先序形态：`[根] [左子树的根, ...] [右子树的根, ...]`；后序形态：`[..., 左子树的根] [..., 右子树的根] [根]`
	**核心判定（对比”第二”与”倒二”）**：提取先序序列的第 2 个结点（即左子树的根），和后序序列的倒数第 2 个结点（即右子树的根）。
	- 若两者相等：说明该根结点**只有一个孩子**（无法确定是左还是右，因此对应的中序序列不唯一）。
	- 若两者不等：说明该根结点**有两个孩子**（左右孩子齐全）。
4. **找反例的常用模型**
	遇到判定树的形态或序列特性的命题，常构造退化树（单链表结构）来证伪：
	- **左斜树**：根 A $\rightarrow$ 左孩子 B。
	- **右斜树**：根 A $\rightarrow$ 右孩子 B。
5. **线索二叉树的查找局限性（”健康”与”残疾”）**
	**中序线索二叉树（健康）**：能够完美找到任意结点的直接前驱和直接后继。
	**先序线索二叉树（残疾 - 找前驱困难）**：若某结点有左孩子（`lchild` 指针被占用，无法存线索），由于先序遍历的特性，它的直接前驱大概率是其父结点。而在常规二叉链表中没有双亲指针，因此无法直接逆向找到前驱。
	**后序线索二叉树（残疾 - 找后继困难）**：若某结点有右孩子（`rchild` 指针被占用，无法存线索），由于后序遍历的特性，它的直接后继大概率是其父结点。同理，无双亲指针导致无法直接查找到后继。

> [!tip] 本质
> `ltag/rtag`：每个结点各 1 bit 的**标志位**（==0=指向孩子，1=指向线索==），本身不存前驱/后继，真正存地址的是 `lchild/rchild`。
> 线索 = **借用空闲的空指针域**，故只有"该侧无孩子"时才塞得进线索。
> 找前驱/后继难的根因：有孩子 → 该侧指针域被占 → 线索无处存，只能现场推；而后序里结点是本子树最后被访问的，==后继必落在子树外，须向上回溯双亲==，二叉链表==没有双亲指针==，所以"残疾"那一侧找不到。
> 判据：==tag=0（无线索可存）+ 目标须上溯双亲，二者同时成立才"残疾"==；中序里二者互斥（有孩子则前驱/后继必落在子树内，往下走即可），==故中序永不残疾==。

## 4.树、森林与二叉树的转换技巧（左孩子右兄弟法）
1. **空指针的物理意义映射**
	**左指针为空**（无左孩子）：对应原树/森林中的叶结点（即原结点没有任何孩子）。
	**右指针为空**（无右孩子）：对应原树/森林中没有右兄弟的结点。
2. **求解原树/森林中”无右兄弟结点”的数量**
	- **分支结点的最右孩子**：原图中每个非终端结点（分支结点）都对应一组孩子。不管有几个孩子，排在最右边的结点（”小儿子”）一定没有右兄弟。这部分数量 = 非终端结点数。
	- **森林的最后根结点**：在森林中，每棵树的根都通过右指针连着右边的兄弟树，但”最后一棵树的根”必然没有右兄弟。
	- **核心公式**：总数 = 非终端结点数 + 1（这个 1 代表最后一棵树的根）。
3. **遍历序列的等价映射（高频考点）**
	- 树的先根遍历 = 二叉树的先序遍历
	- 树的后根遍历 = 二叉树的中序遍历
	- 森林的先序遍历 = 二叉树的先序遍历（依次对每棵树先根遍历）
	- 森林的中序遍历 = 二叉树的中序遍历（依次对每棵树后根遍历）
	- ==二叉树的后序遍历在树/森林中没有对应==
	- （防坑注意：由于”右孩子”对应”右兄弟”，先访问左子树即子结点，再访问根，最后访问右子树即兄弟结点，因此后根遍历映射过来是中序，绝对不是后序）。
## 5.并查集与哈夫曼树
### 哈夫曼树 (Huffman Tree)
1. **WPL（带权路径长度）**
	**定义**：叶结点的权值 $W_i \times$ 根到叶的路径长度 $L_i$ 之和。
	**等价计算**：所有分支结点权值之和。
2. **前缀编码**
	**特征**：没有一个编码是其他编码的前缀。
3. **结点规律**
	- 哈夫曼树中无度为 1 的结点。
	- 结点数量关系：$n_0 = n_2 + 1$。
4. **k 叉哈夫曼树（严格 k 叉树）**
	每个分支结点恰有 k 个孩子。设叶结点数 $n_0$，由 $n_0 = (k-1)n_k + 1$ 得 $(n_0-1) \bmod (k-1) = 0$ 才构得成。
	==不满足就得补「权值为 0 的虚结点」，补的个数 $= (k-1) - ((n_0-1) \bmod (k-1))$==；虚结点放最底层，不改 WPL。
	（$k=2$ 时 $\bmod 1$ 恒为 0，故二叉哈夫曼树永远不用补；==只有 3 叉及以上才需补==。与八.7 最佳归并树补「虚段」是同一规则。）
### 并查集 (Disjoint Set)
1. **数组表示 (双亲表示法)**
	- S[x] 存储双亲结点的下标。
	- 根结点的 S[x] 为集合内元素个数的负数。
2. **查找操作 (find)**
	- **功能**：find 返回根结点的下标。
	- **时间复杂度**：常规情况为 $O(n)$。
	- **改进（路径压缩）**：查找时将所有结点都挂在根结点下，优化后复杂度趋近 $O(1)$。
3. **合并优化 (union)**
	**策略**：小树并入大树（防止树过深退化成单链表）。

# 六.图
## 1.图的概念
1. **路径与弧的区分**：主要区分有向图里面的路径和弧。
	- **路径**是u到v，涉及的点。
	- **弧**是u直接连到v。
	- 因此**强连通图**指每两个结点之间有路径，而不是有弧。
2. **连通分量与生成树**
	- **极大连通子图是连通分量**：不包含所有点，但要包含点涉及的所有边
	- **极小连通子图是生成树**：包含所有点，并且包含最少需要的边
3. **连通图的结点与边的关系**
	- 无向图：v-1个节点两两相连，此时完全图。再加一个点即不相连
	- 同时，**最少v-1条边**即可连通，若点数 > 边数+1，则不连通
4. **图的度**
	- **有向图**：每个结点与其余 $n-1$ 个结点有两条边，此时为有向完全图。每个结点最大的度为 $2n-2$，$n$ 为节点数。总最大度数 = $n \times (2n - 2)$
	- **无向图**：每两个结点都连一条，总边数：$\frac{n(n-1)}{2}$，度为2倍的边数。
5. **路径类型**：**简单路径**和**简单回路**，即顶点不重复出现的路径。
## 2. 图的存储
1. **邻接矩阵 (数组)**
	**特性**：无向图的矩阵必然对称；有向图不一定对称。空间复杂度恒为 $O(|V|^2)$。
	**考点**：无向图常利用对称性进行压缩存储，数组大小为 $\frac{n(n+1)}{2}$。
2. **邻接表 (数组+链表)**
	**特性**：同一个图的邻接表表示不唯一（取决于边插入链表的顺序）。
	**结点数**：含有 $E$ 条边的无向图，边表结点数必为偶数（$2E$）；有向图边表结点数等于 $E$。
	**复杂度**：无向图 $O(|V|+2|E|)$，有向图 $O(|V|+|E|)$。
3. **高级链表 (解决特定痛点)**
	**十字链表 (仅有向图)**：解决邻接表”求入度极其困难”的问题（融合了邻接表和逆邻接表）。弧尾是同行，弧头指向其他行。
	**邻接多重表 (仅无向图)**：解决邻接表”同一条边存两份，删除/修改边困难”的问题（每条边只存一个结点）。结构：头，下一个头相同，尾，下一个尾相同。
## 3. 图的遍历
1. **核心逻辑**
	**广度优先遍历 (BFS)**：类似树的层次遍历。借助队列实现。
	**深度优先遍历 (DFS)**：类似树的先序遍历。借助递归栈实现。
2. **时空复杂度**
	**空间复杂度**：无论是 BFS 还是 DFS，最坏情况下的辅助队列/栈深度均为 $O(|V|)$；同时都需 $O(|V|)$ 的 `visited` 数组。故空间复杂度均为 $O(|V|)$。
	**时间复杂度** (仅取决于存储结构)：
	- 邻接表：$O(|V|+|E|)$
	- 邻接矩阵：$O(|V|^2)$
3. **遍历与连通性的判定**
	**无向图**：调用遍历算法（BFS/DFS）的次数 = **图的连通分量数**。若一次调用就能访问所有结点，则图是连通图。
	**有向图**：极易踩坑！有向图能否一次遍历完，高度依赖起始点。即使图不是强连通图（例如 $A \rightarrow B \rightarrow C$），只要从正确的起点（如 $A$）出发，也可能一次遍历完毕。
## 4.图的应用
==重点==
1. **最小生成树**
	**prim算法**：加点，选择最小边。适合边稠密，O（V²）
	**kruskal算法**：选最小边加入。O（ElogE），与点无关，对边数及其敏感。堆排序找最短边，然后并查集判断是否在同一个集合中。
	对于同一个图，二者可能相同，可能不同。若图中每条边的权值不同，那么最小生成树只有一种。若边有相同的，则可能有多种，也可能只有一种。
	虽然MST不同，但是**权值之和**是相同的。
2. **最短路径**
	单源最短路径（起点唯一）：Dijkstra算法，选择题仔细找出每种情况。分析好长度的变化
	所有顶点直接的最短路径：Floyd算法，依次选择v0，v1....vn作为中间结点。时间复杂度O(V三次方)。对每个顶点都使用一次迪杰斯特拉也可以，时间复杂度也是三次方
	迪杰斯特拉不能算存在负权的图，弗洛伊德可以算负权图，但不能算负环图。
3. **有向无环图描述表达式**
	相同的子表达式共享同一个顶点。减法除法等不能共享一个顶点
4. **拓扑排序**
	AOV网。每次选出入度为0的即可。若最终输出定点数小于V,则必有环。可以有不同结果。
	DFS遍历退出的序列，是逆拓扑序列。若想得到拓扑序列，则退出时压栈，最后一个一个出栈即可。
	**时间复杂度**：==邻接表 $O(V+E)$==（每个顶点、每条边各访问一次）；==邻接矩阵 $O(V^2)$==（每轮都要扫一行找入度为 0 的顶点）。
5. **关键路径**
	AOE网。路径长度最大的是关键路径，关键路径上的活动是关键活动。
	加快公共关键活动才能缩短工期。若有多条关键路径，单独缩短一条无效。必须**组合缩短，确保所有关键路径的长度同时减小**（可缩短全局公共活动，也可组合缩短不同路径上的活动）
# 七.查找
## 1.查找的基本概念
1. **静态与动态查找**：静态查找表只能查找，动态可以边插入删除边查找
2. **关键字与ASL**：关键字唯一标识元素。$\text{ASL}$ (平均查找长度) = 关键字的比较次数。$\text{ASL}$ 是查找算法效率的核心
## 2.顺序查找和折半查找
1. **顺序查找**：所有顺序查找适合**线性表的所有物理结构**。一般查找设置一个哨兵防止数组越界。$\text{ASL} = \frac{n+1}{2}$
2. **有序线性表的查找**：$x$ 大于前一个小于后一个，则判定失败。对应判定树为矩形结点（失败结点），失败结点的个数为 $n+1$，失败结点是虚构的，比较次数为对应的父结点的层数。
	- $\text{ASL}_{\text{成功}} = \frac{n+1}{2}$
	- $\text{ASL}_{\text{失败}} = \frac{1+2+3+\cdots+n+n}{n+1}$，顺序查找的判定树的==单支树==，相当于每个==非叶结点左子树==都是失败结点。一共$n+1$ 个失败结点，最后一层有==两个失败结点==。
3. **折半查找**：只适合关键字有序的**顺序表**。
	- 取整方式唯一，向上：$\lfloor \frac{\text{low}+\text{high}+1}{2} \rfloor$，向下：$\lfloor \frac{\text{low}+\text{high}}{2} \rfloor$。
	- 判定树（只数圆形结点）的高度 $h = \lceil \log_2(n+1) \rceil = \lfloor \log_2 n \rfloor + 1$。特殊值法最为简单。
	- ==取整方式==不同导致对应的判定树不同，唯一不变的是左右子树==结点数==之差是固定值：0，或者 $\pm 1$ 中的一个。只能是0或1以及0或-1两种情况。
	- 时间复杂度 $O(\log_2 n)$
	- 失败结点代价 = 自己层数 $- 1$（即父结点层数），所以==最大比较次数（成功、失败都一样）= 判定树高度 $h$==；含方形结点的整棵树高才是 $h+1$
4. 分块查找（索引顺序查找）：
	块间有序，块内无序。块间递增，key为最大值，块间递减，key为最小值。$\text{ASL} = L_1 + L_2$。
	查找块间key可以用顺序或者折半查找。折半查找失败后指向大于key的第一个索引项。
	**长度为** $n$，**块数** $b$，**每块长度** $s$，$n = b \times s$。当且仅当 $s = \sqrt{n}$ 时，$\text{ASL}_{\min} = \sqrt{n} + 1$
## 3.树形查找
1. **二叉排序树（二叉搜索树）BST**
	- 要么为空，要么递归满足左 $<$ 根 $<$ 右。
	- **查找**：逐层比较选择左右子树即可。
	- **插入**：新插入结点必为叶子结点。递归查找插入位置，恰好是查找失败的结点的左/右孩子。
	- **删除**：
		- 若是叶子结点：直接删
		- 若只有一个非空子树（左右皆可）：直接上移
		- 若同时有左右子树：找该结点p的中序遍历的直接前驱或直接后继q，p与q互换位置，按照前两种操作删除p即可。
	- **查找效率**：需要看构造情况，一般 $O(\log n)$，若==原序列有序，则退化为 $O(n)$ 线性表。==
	与二分查找==类似==，但==二分查找==的判定树==唯一==，二叉排序树则看==插入顺序==。==静态==查找用==二分查找==（插入删除麻烦），==动态==查找用==BST==。
2. **平衡二叉树（AVL）**
	- 或为空树。或者：每个结点的平衡因子仅为0或 $\pm 1$ 即可，不一定是BST，但多数直接当BST了。
	- **平衡二叉树的调整**：见 [平衡二叉树和红黑树的调整](琐碎知识点/平衡二叉树和红黑树的调整.md)
		- 只需要一个原则。定位==最小失衡根A==及其==沿失衡路径延伸==的==子B，孙C==共3个结点，按关键字大小排成a < b < c;以中位数b为新根，a、c分别居左右孩子，其余4棵子树依序挂回两侧。
	- **平衡二叉树的查找**
		- 本质和BST一样，比较次数就是树的深度。
		非叶结点的平衡因子都为0，则最稠密，为满二叉树。
		非叶结点的平衡因子都为1，则最稀疏，构成斐波那契树。
		$N_h$ 表示构造高度为 $h$ 的AVL所需的最小结点，$n_0 = 0$，$n_1 = 1$，$n_2 = 2$。
		显然满足 $N_h = N_{h-1} + N_{h-2} + 1$(左/右是前一个高度的🌳，另一边是前两个高度的🌴，+1是根)。此为==斐波那契树==。时间复杂度 $O(\log n)$
3. **红黑树**
	- 大部分情况下也是BST。相当于对BST的另一种”平衡”化，降低了调整频率，但查找效率低于AVL。但广泛采用，如C++的map和set
	- 记忆口诀：左根右，根叶黑，不红红，黑路同。
	从根到叶最长路径 $\le 2\times$ 最短路径；高 $h \le 2\log_2(n+1)$
	红黑树的插入：默认插入为红，只会不满足根叶黑和不红红两个原则
		若为**根节点**，直接变黑[平衡二叉树和红黑树的调整](琐碎知识点/平衡二叉树和红黑树的调整.md)
		若**叔叔结点为红**，则叔父爷变色，爷变为新插入结点。再对爷调整
		若**叔叔结点为黑**，则可借助AVL的3-4重构法，将==新结点、父结点、👴结点==按大小重构成3个结点的子树；==中位数升为新根且变黑，左右两子变红==,其余子树按大小依序挂回两侧，新结点的左子树挂在新根的左子树，右子树挂在新根的右子树上
	红黑树的删除考的概率为0
## 4. B树和B+树
==选择题重点==
1. **B树：多路平衡m叉树**
	m阶指每个结点**最多$m$棵子树**，即最多$m-1$个关键字。根结点最少2棵子树，即最少1个关键字。非根非叶结点==最少$\lceil m/2 \rceil$ 棵子树，最少$\lceil m/2 \rceil-1$个关键字==。
	所有叶结点都存在同一层，不存数据，表示失败结点。（统考真题将叶结点定义为最底层的终端结点）。
	**B树的查找**：只支持随机查找，先定位结点（访问磁盘）再找结点中查找关键字（读入内存之后），第二步，可以用**折半查找**或**顺序查找**。层数是查找效率关键
	**B树高度的推理**：（这部分写题的时候有点晕，多写了一点）
		按照每个结点对应的不同关键字的范围，依次推理下一层的关键字个数。
		步骤为：先从根结点的关键字个数出发，为1则对应最高树高，m-1则算最矮树高，每个结点都存入最少或最多的关键字。除根外，每层关键字的个数：先算上一层关键字对应的结点数，再乘每个结点有的最少或最多的关键字个数。
		**根为 1 个关键字，高度最高的情况**（每层都尽量少存）：
		**递推规律**：本层结点数 = 把上一层关键字数算式里的"关键字数 $k$"换成"分支数 $k+1$"；本层关键字数 = 本层结点数 $\times k$。
		例：7 阶 B 树，非根非叶结点关键字最少为 3，最多为 6。
		3 个关键字，4 个结点：
			- 第二层：结点数 $1\times2$，关键字数 $1\times2\times3$
			- 第三层：结点数 $1\times2\times(3+1)$，关键字数 $2\times4\times3$
			- 第四层：结点数 $1\times2\times4\times(3+1)$，关键字数 $2\times4\times4\times3$，依次类推
			- 通项：结点数 $2\times4^{\,h-2}$，关键字数 $2\times4^{\,h-2}\times3$，构成等比数列
		**根为6个关键字，高度最矮的情况**：
			此时每层都为最满，结点数为以7为公比的等比数列，关键字数为6。
	**B树的插入**：
		先定位，再判断是否分裂。分裂则选择第$\lceil m/2 \rceil$个元素，放到父结点，以此类推。
	**B树的删除**：
		**1判断关键字个数是否满足范围**，满足则直接删除。
		**2不满足**，若兄弟结点关键字够借，则把该结点和父结点中一个关键字互换，把父节点关键字和兄弟结点再一次，删除该结点。
		**3兄弟也不够借**（只有 ⌈m/2⌉−1 个）：把「违规结点 + 紧邻兄弟 + 父中隔开它俩的那一个关键字」按中序揉成一个结点，父因此少一个关键字。父仍合法 → 结束；父不合法 → 把父当新的违规结点，回到2继续；合并到根且根剩 0 个关键字 → 删根，树高减 1。
		一个注意点：揉的顺序是**兄弟 → 父分隔键 → 违规结点**。

|触发条件|关键字总数变化|父结点|
|---|---|---|---|
|**②旋转**|紧邻兄弟 ≥ ⌈m/2⌉|三方总和不变，环形搬家|个数**不变**|
|**③合并**|紧邻兄弟 = ⌈m/2⌉−1|三方合为一个结点，**掉一层**|个数 **−1**，可能递归|

2. **B+树**——分块查找PLus
	m路，每个关键字对应一个子树，故最多m个关键字，m个子树。其余与B树相同。
	**只有叶结点存储关键字，叶结点关键字升序，相邻叶结点还有一个指针顺序连接**，故支持顺序查找。非叶结点只存储副本。每次查找无论是否成功，都要查到叶结点。
## 5.散列查找
==大题新晋重点==
通过哈希函数，将关键字Key直接映射成存储地址Addr。
散列函数构造方法常用除留余数法。$H ＝ key \% p$ p是一个不超过散列表长度m又很接近m的质数。
**解决冲突的方法**：
	**开放定址法**： $H = (H+d)\%m$
		线性探测：d = 1,2,3...。容易引发堆积（聚集），影响ASL成功。
		平方探测：d＝1,-1,4,-4,...。散列表长度m＝4k+3。的素数
		双散列法：d＝ H2(key) * i;
		伪随机法：d = 随机数
	**拉链法**：将Addr相同的**同义词**通过头插法组织成一个链表。
ASL成功：$比较成功的次数/关键字的个数$
ASL失败：$比较失败的次数/H的取值个数$
	比较失败的次数：对应Addr不是该关键字，通过不同的开放定址法，一直往后比较，直至空的比较次数。
	H的取值个数：可以通过函数计算出的数值的个数。
==散列表不能直接物理删除（开放定址法），否则会影响其他同义词的查找==，因为删完为空了，其他同义词也不用查了😂。
应该设置一个删除标记，实现逻辑删除。副作用是会导致很多没有利用的位置。若是拉链法，则无所谓。

# 八.排序
## 1.排序的基本概念
1. **时间复杂度**：取决于比较次数和移动次数，一般指较多的那个操作的复杂度
2. **空间复杂度**：排序时所需的额外辅助空间大小（除去输入数据本身）
3. **稳定性**：排序后相同值的元素相对位置不变则稳定，否则不稳定
4. **内部排序与外部排序**：内部排序在内存中进行，外部排序涉及内外存交换
5. **排序算法的适用性**：顺序存储和链式存储，需要随机存取的只能用顺序存储
## 2.插入排序
1. **直接插入排序**
	- **思想**：维护已有序部分，每次从无序部分取一个元素，插入到已有序部分的正确位置。
	- **步骤**：
		1. 从第2个元素开始（第1个默认有序）
		2. 将当前元素与已有序部分从后向前比较
		3. 找到插入位置，将该位置后的元素向后移动一位
		4. 将当前元素插入空出的位置
	- **时间复杂度**：平均 $O(n^2)$，最坏 $O(n^2)$（逆序），最好 $O(n)$（已有序）
	- **空间复杂度**：$O(1)$（原地排序）
	- **稳定性**：稳定
	- **代码**：
		```c
		// a[1..n]，a[0] 作哨兵
		for (int i = 2; i <= n; i++)
		    if (a[i] < a[i-1]) {          // 需前插
		        a[0] = a[i];              // 哨兵暂存待插元素
		        int j;
		        for (j = i-1; a[j] > a[0]; j--)
		            a[j+1] = a[j];        // 比哨兵大的整体后移
		        a[j+1] = a[0];            // 插入空位
		    }
		```
2. **折半插入排序**
	- **改进**：利用折半查找优化插入位置的查找过程
	- **思想**：比较次数降低到 $O(n \log n)$，但移动次数仍为 $O(n^2)$（需要移动元素）
	- **时间复杂度**：$O(n^2)$（移动次数决定）
	- **稳定性**：稳定
	- **实际效果**：仅在比较代价很高、移动代价低的场景才有优势
	- **代码**：
		```c
		for (int i = 2; i <= n; i++) {
		    a[0] = a[i];                  // 暂存
		    int low = 1, high = i-1;
		    while (low <= high) {         // 折半找插入位置
		        int mid = (low+high)/2;
		        if (a[mid] > a[0]) high = mid-1;
		        else               low  = mid+1;
		    }
		    for (int j = i-1; j >= high+1; j--)
		        a[j+1] = a[j];            // 统一后移
		    a[high+1] = a[0];             // 插到 high+1
		}
		```
3. **希尔排序（也叫缩小增量排序）**
	- **思想**：分组插入排序。先将序列分成 gap 个间隔的子序列，对每个子序列做插入排序，然后缩小 gap，重复直到 gap = 1
	- **步骤**：
		1. 选定初始 gap（通常 gap = n/2）
		2. 对每个间隔为 gap 的子序列进行插入排序
		3. gap = gap/2，重复第2步
		4. 直到 gap = 1，进行最后一次插入排序
	- **时间复杂度**：平均 $O(n \log n)$ 或 $O(n^{1.3})$（与 gap 序列选择有关），最坏 $O(n^2)$
	- **空间复杂度**：$O(1)$（原地排序）
	- **稳定性**：**不稳定**（因为间隔比较会破坏原有顺序）
	- **特点**：快速、实用，但不稳定
	- **做题思路**：每次把子序列拿出来分析，放一块看很容易看错。
	- **代码**：
		```c
		for (int d = n/2; d >= 1; d /= 2)     // 步长逐次折半
		    for (int i = d+1; i <= n; i++)    // 各子序列内插入排序
		        if (a[i] < a[i-d]) {
		            a[0] = a[i];
		            int j;
		            for (j = i-d; j > 0 && a[j] > a[0]; j -= d)
		                a[j+d] = a[j];        // 隔 d 后移
		            a[j+d] = a[0];
		        }
		```
## 3.交换排序
1. **冒泡排序**
	- **思想**：从后往前选最小的放最前面；或者从前往后选最大放最后面
	- **步骤**：
		1. 从前往后还是从后往前
		2. 若从前往后。选最大，每两个比较，前面的大于后面的就交换
		3. 若从后往前。选最小，每两个比较，后面的小于前面的就交换
		4. 重复直到某趟无交换
	- **时间复杂度**：最坏 $O(n^2)$，平均 $O(n^2)$
	- **空间复杂度**：$O(1)$（原地排序）
	- **稳定性**：稳定，元素相同不会移动
	- **特点**：每趟移动后至少有一个元素在最终位置上
	- **代码**：
		```c
		for (int i = 1; i < n; i++) {
		    bool flag = false;                // 本趟是否发生交换
		    for (int j = n; j > i; j--)       // 从后往前，小者上浮
		        if (a[j-1] > a[j]) {
		            swap(a[j-1], a[j]);
		            flag = true;
		        }
		    if (!flag) break;                 // 一趟无交换则已有序
		}
		```
2. **快速排序**：==重点，会写代码==
	- **思想**：选一个枢轴（pivot），将序列分成三部分：小于 pivot、等于 pivot、大于 pivot，然后对左右两部分递归排序
	- **步骤**：
		1. 通常选第一个元素为 pivot，low 指向第一个元素，high 指向最后一个元素
		2. high 从后往前移动，直到指向元素小于 pivot，然后将该元素赋值给 low 所指元素
		3. low 从前往后移动，直到所指元素大于 pivot，然后将该元素赋值给 high 所指元素
		4. low = high 时，停止，将 pivot 赋值给 low
		5. 对分成的两个子序列递归排序
	- **时间复杂度**：平均 $O(n \log n)$，最坏 $O(n^2)$（pivot 每次都选到最小/最大值）
	- **空间复杂度**：$O(\log n)$（递归栈深度，平均情况）
	- **稳定性**：**不稳定**，元素交换过程中会跨越相同元素。例如两个相等的元素 $a_1$、$a_2$，如果 $a_1$ 在 pivot 左边，$a_2$ 在 pivot 右边，经过交换后它们的相对位置会改变
	- **特点**：每趟排序之后，都会确定枢轴的位置。每趟排序确定一个枢轴的最终位置。性能高度依赖枢轴的选择——好的选择能均匀分割，坏的选择导致退化。若一趟排序后，枢轴的位置在两端，那么只有一个子序列，只能确定的一个枢轴。若枢轴位置在中间，有两个子序列，可以确定两个枢轴。也可以用n趟排序之后至少确定几个n个元素的位置来确定答案。==选择题考频两次==
	- **代码**：
		```c
		int Partition(int a[], int low, int high) {
		    int pivot = a[low];               // 取首元素为枢轴
		    while (low < high) {
		        while (low < high && a[high] >= pivot) high--;
		        a[low] = a[high];             // 右边小的填到左边
		        while (low < high && a[low] <= pivot) low++;
		        a[high] = a[low];             // 左边大的填到右边
		    }
		    a[low] = pivot;                   // 枢轴归位
		    return low;
		}
		void QuickSort(int a[], int low, int high) {
		    if (low < high) {
		        int p = Partition(a, low, high);   // 每趟定一个枢轴
		        QuickSort(a, low, p-1);
		        QuickSort(a, p+1, high);
		    }
		}
		```
## 4.选择排序
1. **简单选择排序**
	- **思想**：每趟从未排序的元素中选择最小（或最大）的元素，放到已排序序列的末尾
	- **步骤**：
		1. 第 $i$ 趟从第 $i$ 个位置开始，在剩余 $n-i+1$ 个元素中找到最小元素
		2. 将最小元素与第 $i$ 个位置的元素交换
		3. 重复 $n-1$ 趟即可完成排序
	- **时间复杂度**：$O(n^2)$（无论什么情况，比较次数都是 $\frac{n(n-1)}{2}$）
	- **空间复杂度**：$O(1)$
	- **稳定性**：**不稳定**（交换操作可能破坏相等元素的相对顺序，如2，**2**，1 变成 1，**2**，2，两次位置发生变化）
	- **特点**：比较次数与序列初始状态无关，移动次数最少（最多 $n-1$ 次交换）
	- **代码**：
		```c
		for (int i = 1; i < n; i++) {
		    int k = i;                        // 记录最小元素下标
		    for (int j = i+1; j <= n; j++)
		        if (a[j] < a[k]) k = j;
		    if (k != i) swap(a[i], a[k]);     // 一趟只换一次
		}
		```
2. **堆排序**：==重点==
	- **堆的定义**：
		- **完全二叉树**的顺序存储结构
		- **大根堆**：每个节点的值 $\geq$ 其子节点的值，根节点最大
		- **小根堆**：每个节点的值 $\leq$ 其子节点的值，根节点最小
		- **节点关系**（数组下标从 1 开始）：
			- 节点 $i$ 的左孩子：$2i$
			- 节点 $i$ 的右孩子：$2i + 1$
			- 节点 $i$ 的父节点：$\lfloor i/2 \rfloor$
	- **建堆**（初始建堆）：
		- **思想**：从最后一个==非叶节点==开始，自底向上进行**向下调整**
		- **最后一个非叶子节点**：$\lfloor n/2 \rfloor$（$n$ 为元素个数）
		- **向下调整算法**（以大根堆为例）：
			1. 将节点 $i$ 与其较大的子节点比较
			2. 若节点 $i$ 小于较大的子节点，则交换
			3. 继续向下调整，直到叶子节点或满足堆的性质
		- **时间复杂度**：$O(n)$（不是 $O(n \log n)$！）
			- 分析：叶子节点不需要调整（占一半），倒数第二层最多移动 1 次，倒数第三层最多移动 2 次...
			- 计算：$\sum_{h=1}^{\log n} \frac{n}{2^{h+1}} \cdot h = O(n)$
	- **添加元素**（插入）：
		- **思想**：将新元素添加到堆的末尾，然后进行**向上调整**
		- **向上调整算法**（以大根堆为例）：
			1. 将新元素与其父节点比较
			2. 若新元素大于父节点，则交换
			3. 继续向上调整，直到根节点或满足堆的性质
		- **时间复杂度**：$O(\log n)$（最多调整树的高度次）
	- **删除元素**（删除堆顶）：
		- **思想**：删除堆顶元素（最大/最小值），用堆的最后一个元素替代堆顶，然后进行**向下调整**
		- **步骤**：
			1. 取出堆顶元素（数组的第 1 个元素）
			2. 将堆的最后一个元素移到堆顶
			3. 对堆顶元素进行**向下调整**，恢复堆的性质
		- **时间复杂度**：$O(\log n)$
	- **堆排序过程**（升序排序，使用大根堆）：
		1. **建初始堆**：将无序序列调整为大根堆（$O(n)$）
		2. **交换与调整**：重复 $n-1$ 次以下操作：
			- 将堆顶元素（最大值）与堆的最后一个元素交换
			- 堆大小减 1（排除已确定位置的元素）
			- 对新堆顶进行**向下调整**，恢复大根堆性质
	- **时间复杂度**：$O(n \log n)$（建堆 $O(n)$ + $n-1$ 次调整，每次 $O(\log n)$）
	- **空间复杂度**：$O(1)$（原地排序）
	- **稳定性**：**不稳定**（堆调整过程中会改变相等元素的相对位置）
	- **特点**：
		- 适合处理海量数据（如 Top K 问题）
		- 效率稳定，不会出现快排的最坏情况
		- 对初始序列不敏感，任何情况下都是 $O(n \log n)$
		- 不适合链式存储结构
	- **代码**：
		```c
		void AdjustDown(int a[], int k, int n) {   // 大根堆向下调整
		    a[0] = a[k];                           // 暂存待调结点
		    for (int i = 2*k; i <= n; i *= 2) {
		        if (i < n && a[i] < a[i+1]) i++;   // 取较大的孩子
		        if (a[0] >= a[i]) break;           // 已满足堆
		        a[k] = a[i]; k = i;                // 孩子上移，继续下探
		    }
		    a[k] = a[0];
		}
		for (int i = n/2; i >= 1; i--) AdjustDown(a, i, n);   // 建堆：末个非叶结点起
		for (int i = n; i > 1; i--) {                        // 堆排序
		    swap(a[1], a[i]);                                // 堆顶(最大)换到末尾
		    AdjustDown(a, 1, i-1);                           // 剩下 i-1 个重建堆
		}
		```
## 5.归并排序，基数排序
1. **归并排序（Merge Sort）**：==重点==
	- **思想**：**分治法**，将序列递归地分成两半，分别排序后再**合并**成一个有序序列
	- **步骤**：
		1. **分解**：将长度为 $n$ 的序列分成两个长度为 $n/2$ 的子序列
		2. **递归排序**：对两个子序列递归地进行归并排序
		3. **合并**：将两个已排序的子序列合并成一个有序序列
	- **二路归并算法**（合并过程）：
		1. 设置两个指针分别指向两个子序列的起始位置
		2. 比较两个指针所指元素，将较小的元素放入辅助数组，指针后移
		3. 重复步骤 2，直到某个子序列遍历完
		4. 将另一个子序列的剩余元素直接复制到辅助数组
		5. 将辅助数组的内容复制回原数组
	- **时间复杂度**：$O(n \log n)$（任何情况下都是，非常稳定）
		- 递归深度：$\log n$
		- 每层归并：$O(n)$
	- **空间复杂度**：$O(n)$（需要辅助数组存储合并结果）
	- **稳定性**：**稳定**（合并时相等元素保持原有顺序）
	- **特点**：
		- 效率稳定，不受初始序列影响
		- 2路，i趟过后，==每2的i次方个==数有序
		- 适合链式存储结构（不需要随机访问）
		- 适合外部排序（大文件排序）
		- 空间代价较大
	- **代码**（合并是核心，递归只是先分左右再 Merge）：
		```c
		void Merge(int a[], int b[], int low, int mid, int high) {
		    for (int k = low; k <= high; k++) b[k] = a[k];   // 复制到辅助数组
		    int i = low, j = mid+1, k = low;
		    for (; i <= mid && j <= high; k++)               // 两段取小者回填
		        (b[i] <= b[j]) ? a[k] = b[i++] : a[k] = b[j++];
		    while (i <= mid)  a[k++] = b[i++];               // 剩余段直接复制
		    while (j <= high) a[k++] = b[j++];
		}
		```
2. **基数排序**
	- **思想**：按关键字的各位进行多次分配和收集，不基于比较
	- **两种方式**：
		- **LSD（Least Significant Digit）**：从最低位到最高位依次排序
		- **MSD（Most Significant Digit）**：从最高位到最低位依次排序（常用 LSD）
	- **LSD 步骤**（以十进制为例）：
		1. 从个位开始，按个位数字将元素分配到 0-9 共 10 个桶中
		2. 按桶的顺序收集元素，形成新序列
		3. 对十位、百位...依次重复步骤 1-2
		4. $d$ 轮后得到有序序列（$d$ 为最大数的位数）
	- **时间复杂度**：$O(d(n+r))$
		- $d$：最大数的位数（趟数）
		- $n$：元素个数
		- $r$：基数（十进制为 10）
		- 每趟分配：$O(n)$，收集：$O(r)$
	- **空间复杂度**：$O(n+r)$（需要 $r$ 个桶，每个桶最多 $n$ 个元素）
	- **稳定性**：**稳定**（必须使用稳定的分配方法，如队列）
	- **特点**：
		- ==不基于比较，是分配排序==
		- 适合位数较少、元素较多的情况
		- 需要额外空间存储桶
		- 只能用于整数或字符串排序
	- **代码**（分配 + 收集，$r$ = 基数）：
		```c
		for (int d = 1; d <= 最大位数; d++) {       // 从最低位到最高位
		    clear(Q[0..r-1]);                     // 清空 r 个桶(队列)
		    for (int i = 1; i <= n; i++)          // 分配：按第 d 位入桶
		        Q[取第d位(a[i])].push(a[i]);
		    int idx = 1;
		    for (int k = 0; k < r; k++)           // 收集：0~r-1 依次出桶
		        while (!Q[k].empty()) a[idx++] = Q[k].pop();
		}
		```
## 6.内部排序的比较
**① 时间 / 空间 / 稳定性**

| 排序 | 最好 | 平均 | 最坏 | 空间 | 稳定 |
|---|---|---|---|---|---|
| 直接插入 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ 稳定 |
| 折半插入 | $O(n\log n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ 稳定 |
| 希尔 | $O(n^{1.3})$ | $O(n^{1.3})$ | $O(n^2)$ | $O(1)$ | ❌ 不稳定 |
| 冒泡 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ✅ 稳定 |
| 快速 | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | ❌ 不稳定 |
| 简单选择 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | ❌ 不稳定 |
| 堆排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | ❌ 不稳定 |
| 归并 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | ✅ 稳定 |
| 基数 | $O(d(n+r))$ | 同左 | 同左 | $O(n+r)$ | ✅ 稳定 |

> 希尔复杂度==与增量序列有关==，常记约 $O(n^{1.3})$，最坏 $O(n^2)$；折半插入只把比较降到 $O(n\log n)$，==移动仍 $O(n^2)$==，故整体还是 $O(n^2)$。

**② 选择题常考的"是否"**

| 排序 | 一趟能定一个最终位置 | 比较次数与初序无关 | 移动次数与初序无关 | 总趟数与初序有关 |
|---|---|---|---|---|
| 直接插入 | ✗ | ✗ | ✗ | ✗ |
| 折半插入 | ✗ | ==✓== | ✗ | ✗ |
| 希尔 | ✗ | ✗ | ✗ | ✗ |
| 冒泡 | ✓ | ✗ | ✗ | ==✓== |
| 快速 | ✓ | ✗ | ✗ | ==✓== |
| 简单选择 | ✓ | ==✓== | ✗ | ✗ |
| 堆排序 | ✓ | ✗ | ✗ | ✗ |
| 归并 | ✗ | ✗ | ==✓== | ✗ |
| 基数 | ✗ | —（不比较） | ==✓== | ✗ |

> [!tip] 四句口诀
> - ==一趟能定最终位置==：**冒、快、选、堆**（4 个）
> - ==比较次数与初序无关==：**折半插入、简单选择**
> - ==移动次数与初序无关==：**归并、基数**（每趟都得整体搬一遍）
> - ==总趟数与初序有关==（趟数不定）：**冒泡**（有序 1 趟、逆序 $n-1$ 趟）、**快速**（看枢轴分得匀不匀）

## 7.外部排序

**问题**：数据量太大，内存一次装不下，只能分块读入、排好写回。==瓶颈不在 CPU 比较，而在磁盘 I/O==（磁盘比内存慢好几个数量级）。所以外部排序的一切优化，只为做一件事：**减少内外存之间的读写次数**。

**主线**：先把大文件切成若干小段、各自排好（**段内有序**），再多路归并成一个大段——==造段 → 归并==两步。

### 1.造初始归并段（内部排序）
把文件按内存大小切成若干块，每块读入内存用快排/堆排排好，写回外存。每块排好的结果叫 **归并段（顺串）**，设共 $m$ 段。

### 2.多路平衡归并
内存里开 $k$ 个输入缓冲区 + 1 个输出缓冲区，一趟把 $k$ 段并成 1 段，反复并到只剩 1 段。
- **一趟怎么并**：给 $k$ 段各配一块输入缓冲、再开一块输出缓冲。反复从 $k$ 段的头上挑出**最小者**送进输出缓冲；输出缓冲满就写回磁盘，某段输入缓冲读空就补读一块。
- **归并趟数** $S = \lceil \log_k m \rceil$（每趟段数缩为原来的 $1/k$）。

### 3.核心指标：I/O 次数（考试就考它）
**规矩：每趟归并，全部数据都要读一遍、写一遍。**
- **造段**：读 $m$ 段 + 写 $m$ 段 = $2m$。
- **每趟归并**：全量读 + 全量写 = $2m$（段数在变，总记录数不变）。
- 共 $S$ 趟 → $2mS$。
- ==总 I/O $= 2m(S+1)$==，那个 $+1$ 就是造段那一趟。

> [!tip] 一句话记住
> ==$S=\lceil\log_k m\rceil$，总 I/O $=2m(S+1)$==。降 I/O 只有两条路：**↑$k$** 或 **↓$m$**——下面两节正好各对应一条。

> [!example] 看杠杆（文件 1000 段）
> $k=10$：$S=\lceil\log_{10}1000\rceil=3$，总 I/O $=2\times1000\times(3+1)=8000$。
> $k=100$：$S=\lceil\log_{100}1000\rceil=2$，总 I/O $=2\times1000\times(2+1)=6000$。
> ==每减一趟归并，就省下 $2m$ 次 I/O==——这就是为什么值得花大力气增大 $k$、减少 $m$。

### 4.路子一：增大归并路数 $k$ —— 败者树
$k$ 越大 $S=\log_k m$ 越小，直觉上就该使劲增大 $k$。**但**：每并一个元素，都要从 $k$ 段里挑最小，得比较 $k-1$ 次；一整趟 $n$ 个元素就是 $O(nk)$——$k$ 一大，CPU 比较反而成了新瓶颈。

**败者树**：一棵**完全二叉树**，把 $k$ 路选最小做成一场淘汰赛。
- **结构**（$k$ 段 → $k$ 个叶子 + $k-1$ 个内部结点）：
	- **叶子**：$k$ 个归并段；每段的"当前待比较元素"另存在缓冲区 $b[]$ 里。
	- **内部结点**：只存==这一局**败者所在的段号**（下标）==，**不存元素值**。
	- **冠军位**（常记 $ls[0]$）：存==最终胜者的**段号**==。
- **为什么存段号**：值都在 `b[段号]` 里，结点只记下标，比较时直接取 `b[ls[i]]`，省得把整棵树的结点都塞上值。
- **取最小**：拿冠军段号去查 `b[冠军]`，$O(1)$。
- **换人重赛**（某段出了新元素）：从该段的叶子往上，把"新上来的胜者"和父结点记的**败者**比一次——==赢的继续上升、输的留在原结点==，比到根，根上方就是新冠军。比较次数 = 树高 ==$\lceil\log_2 k\rceil$==。
- 总比较 ==$(n-1)\lceil\log_2 k\rceil$==，是 $O(n\log k)$ 而非 $O(nk)$——==与 $k$ 成对数关系，这才敢放心增大 $k$==。

> [!example] $k=3$ 的败者树（当前元素 `b1=5, b2=3, b3=8`）
> 先比 1、2 段：`5>3` → ==结点记败者段号 `1`==，胜者段 2 上升；再比段 2、段 3：`3<8` → 结点记 `3`，冠军 = 段 2。
> 现段 2 输出 3、补进新值 7 重赛：先和结点 `1` 比（`b1=5`），`7>5` → 结点改记 `2`、段 1 上升；再和结点 `3` 比（`b3=8`），`5<8` → 冠军变段 1。==全程只比 2 次 = ⌈log₂3⌉==。

> 胜者树 vs 败者树：胜者树内部结点存**胜者**段号，重构时每层都要重新取两个孩子再比一次；==败者树存**败者**，重构时只需和路径上那个败者比一次、不用管兄弟==，更快也更省。

### 5.路子二：减少初始归并段数 $m$
$m$ 小则 $S$ 的分子小，趟数就少。两手：**置换-选择排序**（把段变长）、**最佳归并树**（把段并得省）。

#### 5.1 置换-选择排序（让每段更长）==23 年大题考过，仍可能出选择==
**目标**：传统造段"装满内存就换段"，段长 = 内存大小 $w$；置换-选择能造出**平均长度 $\approx 2w$** 的段，段数直接减半。
**做法**：内存工作区维护一个 $w$ 个元素的**小根堆**。
1. 堆顶最小值输出到当前段，同时从输入补一条新记录 $x$。
2. 若 $x \ge$ 刚输出的值：它还能排在当前段后面，**入堆**继续参与。
3. 若 $x <$ 刚输出的值：再也接不到本段后面了，**冻结**，留给下一段。
4. 当堆里只剩冻结元素时，本段结束 → 解冻开新段。
5. 重复直到所有记录处理完。

> [!example] 小例（内存 $w=3$，输入 `3 6 2 5 1 8 4`）
> 堆先装 `3 6 2` → 依次输出 `2 3 5 6 8`（读到 `1`、`4` 时都比刚输出的小，被冻结）→ 段1 = `[2 3 5 6 8]`，==长 5 > 内存 3==；解冻后段2 = `[1 4]`。

#### 5.2 最佳归并树（让归并更省）—— Huffman 思想
**问题**：各段**长度不等**时，先并谁、后并谁，总 I/O 差很多。==思路：短的先并（多读几趟也不贵），长的后并（少读写几次最省）==。
**做法**：把各段长度当**权值**，构造一棵**严格 $k$ 叉 Huffman 树**（每个内部结点恰好 $k$ 个孩子，即每趟都真并满 $k$ 段、不空手）。
- ==权（段长）大的往高层放（后并、少碰），小的往低层放（先并、多碰）==，带权路径长度 WPL 最小 → I/O 最少。
- **补虚段**：严格 $k$ 叉树要求 $(m-1) \bmod (k-1) = 0$；不满就补长度为 0 的**虚段**凑满，个数 $=(k-1)-u$（$u=(m-1)\bmod(k-1)$）。
- **WPL（带权路径长度）** $=\sum_i w_i \times d_i$（$w_i$ 叶权值、$d_i$ 叶深度，与哈夫曼树那节同义）。归并树里：**权 = 段长（记录数）**、**深度 = 该段被并的趟数**。
- **总 I/O**：==归并部分 $=2\times WPL$（读一遍 + 写一遍各算一次），再加造段的 $2m$，合计 $2\times WPL+2m$==。

> [!tip] 为什么 WPL 能等于"归并读取的总记录数"
> 把归并画成树后，**每个内部结点 = 一次归并**（读 $k$ 个孩子、写 1 个父）；一条记录**每往上并一层就被读一次**，所以它被读的次数 = 所在叶的**深度** $d_i$。一段有 $w_i$ 条记录，相乘 $w_i d_i$ 就是这一段总共被读了多少次；==对所有段求和 $\sum_i w_i d_i=$ WPL，正好把整个归并过程读取的记录数一条不差地数完==。写与读同量，故归并 I/O $=2\,WPL$。

> [!example] 补虚段（$k=3$，$m=4$ 段）
> $u=(4-1)\bmod(3-1)=1\ne0$ → 补 $(3-1)-1=1$ 个虚段，凑成 5 个叶子（$5=2\times(3-1)+1$，才够画严格三叉树）。
