## 知识页｜做数组 Cache 题，按这个顺序看

### 1. 先看数组首元素在 Cache 块中的位置

- 算块内偏移：`首地址 mod 块大小`。
- 偏移为 0：首块是满块，每块装 k 个元素。
- 偏移不为 0：首块只装 `(块大小 − 偏移) / 元素大小` 个，后面每块才装 k 个。
- 这决定数组一共占多少个主存块，也就是大概要缺多少次。

> 例：2025 年 d[0] 的偏移是 32B，首块只装 8 个 int，所以是 129 块，不是 128 块。

### 2. 再看 Cache 映射方式

- **直接映射**：一个块只能放固定的一行，最容易冲突。
- **组相联**：一组有几路，组内就能放几个块；路数够就不容易冲突。
- **全相联**：想放哪放哪，基本不冲突。

> 这一步决定：按列访问时，后面的块会不会把前面的块挤掉。

### 3. 再看一个 Cache 块能装几个数组元素

$$k=\frac{\text{块大小}}{\text{元素大小}}$$

比如块 64B、int 4B → 一块装 16 个元素。

- 同一块第一次访问缺失，后面 $k-1$ 个命中。
- 按行访问、不冲突时：命中率 $=1-\dfrac{1}{k}$。

### 4. 最后看数组是行优先还是列优先

C 语言数组**按行优先存放**：`a[i][j]` 的右边一个元素和它在同一块，下一行则隔一整行。

- 循环 `i` 外、`j` 内 → **按行访问** → 连续访问同一块，命中率高。
- 循环 `j` 外、`i` 内 → **按列访问** → 每次跳一行，步长 = 行长 × 元素大小。

> 按列时，看步长是不是 Cache 行数（或“组数 × 路数”）的整数倍；是的话容易反复映射到同一行/同一组，产生冲突。

### 最后算

$$\text{命中率}=1-\frac{\text{缺失次数}}{\text{总访问次数}}$$

- 每块第一次缺失，后面命中 → 缺失次数 ≈ 块数。
- `a[k] = a[k] + 32`、`s[k] = 2 * s[k]` 是**读+写 = 2 次访存**；`sum += a[i][j]` 只读 1 次，`a[i][j] = 10` 只写 1 次。
- 若问平均访问时间：$\text{AMAT}=t_{hit}+m\times t_{miss}$。
- 遇到问地址字段的，再切 `| Tag | 行号/组号 | 块内地址 |`：块内地址 = $\log_2(\text{块大小})$，组数 = 行数 / 路数。

## 第 1 页｜2010·T44　按行 / 按列（直接映射）

**题目（12 分）**

某计算机的主存地址空间大小为 256MB，按字节编址，指令 Cache 和数据 Cache 分离，均有 8 个 Cache 行，每个 Cache 行大小为 64B，数据 Cache 采用直接映射方式。现有两个功能相同的程序 A 和 B，其伪代码如下所示。

程序 A：

```c
int a[256][256];

int sum_array1()
{
    int i, j, sum = 0;
    for (i = 0; i < 256; i++)
        for (j = 0; j < 256; j++)
            sum += a[i][j];
    return sum;
}
```

程序 B：

```c
int a[256][256];

int sum_array1()
{
    int i, j, sum = 0;
    for (j = 0; j < 256; j++)
        for (i = 0; i < 256; i++)
            sum += a[i][j];
    return sum;
}
```

假定 int 类型数据用 32 位补码表示，程序编译时 i、j、sum 均分配在寄存器中，数组 a 按行优先方式存放，首地址 320（十进制数）。请回答下列问题，要求说明理由或给出计算过程。

(1) 若不考虑用于 Cache 一致性维护和替换算法的控制位，则数据 Cache 的总容量为多少？

(2) 数组数据 `a[0][31]` 和 `a[1][1]` 各自所在的主存块对应的 Cache 行号分别是多少（Cache 行号从 0 开始）？

(3) 程序 A 和 B 的数据访问命中率各是多少？哪个程序的执行时间更短？

**作答区**

<br><br><br><br>

> [!faq]- 答案与解析
> **讲解抓手**：先看首地址 320 mod 64 = 0，首块是满块；再问 A/B 谁按行；再算每块 16 个 int；最后看按列步长 1024B = 16 块，是 8 行的整数倍 → 每行都冲突。
>
> **(1) 532B**
> - 主存 256MB $=2^{28}$B → 地址 28 位；块内地址 $\log_2 64=6$ 位；8 行 → 行号 3 位；标记 $=28-6-3=19$ 位。
> - 再加 1 位有效位 → 每行标记项 20 位 $=2.5$B。
> - 总容量 $=8\times(64+2.5)=532$B。
> - 注意：数据区是 $8\times64=512$B；问“总容量”才把标记位和有效位算进去。
>
> **(2) 行号分别为 6、5**
> - `a[0][31]` 地址 $=320+31\times4=444$，$444/64=6\cdots60$ → 行号 $6\bmod8=6$。
> - `a[1][1]` 地址 $=320+(256+1)\times4=1348$，$1348/64=21\cdots4$ → 行号 $21\bmod8=5$。
> - 位运算更快：把地址切成 `| 标记 | 行号 | 块内地址 |`。
>
> **(3) A：93.75%；B：0%；A 更快**
> - 每块 64B 装 $64/4=16$ 个 int。A 按行访问，同一块的 16 个元素连续访问：第一个缺失，后 15 个命中 → $h_A=15/16=93.75\%$。
> - B 按列访问，相邻两行地址相差 $256\times4=1024$B $=16$ 块。Cache 只有 8 行，$16\bmod8=0$，同一列相邻行映射到**同一行**，每次都把上一行的块替换掉 → 每次访问都缺失，$h_B=0$。
> - B 每次都要访问主存，所以 A 执行时间更短。
>
> 易错：==B 的步长 16 块是 8 行的整数倍==，不是“每 16 行冲突一次”；8 行 Cache 下是**每行都冲突**。

## 第 2 页｜2016·T15　直接映射缺失率（选择）

**题目**

有如下 C 语言程序段：

```c
for (k = 0; k < 1000; k++)
    a[k] = a[k] + 32;
```

若数组 a 以及变量 k 均为 int 型，int 型数据占 4B，数据 Cache 采用直接映射方式，数据区大小是 1KB，块大小是 16B，该程序段执行前 Cache 为空，则该程序段执行过程中，访问数组 a 的 Cache 的缺失率是（ ）。

A. 1.25%

B. 2.5%

C. 12.5%

D. 25%

**作答区**

<br><br><br>

> [!faq]- 答案与解析
> **讲解抓手**：这题只考一个点——读+写 = 2 次访存。每块 4 个 int → 8 次访问 → 缺 1 次。
>
> - Cache 行数 $=1\text{KB}/16\text{B}=64$；每块装 $16\text{B}/4\text{B}=4$ 个 int。
> - `a[k] = a[k] + 32` 对每个元素**读 1 次、写 1 次**，所以每块 4 个元素共 $4\times2=8$ 次访问。
> - 每块第一次读缺失，之后的读和写全部命中 → 每 8 次访问缺 1 次。
>
> $$m=\frac{1}{8}=12.5\%$$
>
> ==选 C。==
>
> 易错：漏掉写访问会算成 $1/4=25\%$（选项 D 就是给你踩的）。

## 第 3 页｜2020·T44　Cache 缺失次数（数组）

**题目（10 分）**

假定主存地址为 32 位，按字节编址，指令 Cache 和数据 Cache 与主存之间均采用 8 路组相联映射方式，直写（Write Through）写策略和 LRU 替换算法，主存块大小为 64B，数据区容量各为 32KB。开始时 Cache 均为空。请回答下列问题。

(1) Cache 每一行中标记（Tag）、LRU 位各占几位？是否有修改位？

(2) 有如下 C 语言程序段：

```c
for (k = 0; k < 1024; k++)
    s[k] = 2 * s[k];
```

若数组 s 及其变量 k 均为 int 型，int 型数据占 4B，变量 k 分配在寄存器中，数组 s 在主存中的起始地址为 008000C0H，则该程序段执行过程中，访问数组 s 的数据 Cache 缺失次数为多少？

(3) 若 CPU 最先开始的访问操作是读取主存单元 00010003H 中的指令，简要说明从 Cache 中访问该指令的过程，包括 Cache 缺失处理过程。

**作答区**

<br><br><br><br>

> [!faq]- 答案与解析
> **讲解抓手**：问的是缺失次数，不是缺失率；每块只在第一次读时缺一次，1024 个 int = 64 块 → 64 次。
>
> **(1) Tag 20 位；LRU 3 位；没有修改位**
> - 块内地址 $\log_2 64=6$ 位。
> - 行数 $=32\text{KB}/64\text{B}=512$，8 路 → 组数 $=512/8=64=2^6$ → 组号 6 位。
> - Tag $=32-6-6=20$ 位。
> - 8 路组相联 LRU 位 $=\log_2 8=3$ 位。
> - 直写（Write Through）不需要脏位/修改位。
>
> **(2) 64 次缺失**
> - s 起始地址 008000C0H 的块内地址为 0，正好从块首开始。
> - 1024 个 int 共 $1024\times4\text{B}=4\text{KB}=64$ 个主存块。
> - 每块装 $64/4=16$ 个元素；每个元素读一次、写一次，但**每块只在第一次读时缺失一次**。
> - 缺失次数 $=64$。
> - 补充：总访问 $=1024\times2=2048$ 次 → 缺失率 $=64/2048=3.125\%$。
>
> **(3) 地址划分与处理过程**
> - 00010003H 的低 6 位 = 000011B = 3 → 块内地址 3。
> - 中间 6 位 = 000000B = 0 → 组号 0。
> - 高 20 位 = 00010H → Tag。
> - Cache 初始为空，有效位为 0 → **缺失**。
> - 从主存取该块 → 放入指令 Cache 组 0 的某一行 → 写入 Tag=00010H → 置有效位 → 更新 LRU 位 → 按块内地址 3 取出指令。
>
> 易错：题目问的是==缺失次数==，不是缺失率；读写虽然各一次，但每块只缺一次。

## 第 4 页｜2023·T43　数组访问的 Cache 命中率

**题目（14 分）**

已知计算机 M 字长为 32 位，按字节编址，采用请求调页策略的虚拟存储管理方式，虚拟地址为 32 位，页面大小为 4KB；数据 Cache 采用 4 路组相联映射，数据区大小为 8KB，主存块大小为 32B。现有 C 语言程序段如下：

```c
for (i = 0; i < 24; i++)
    for (j = 0; j < 64; j++)
        a[i][j] = 10;
```

已知二维数组 a 按行优先存放，在虚拟地址空间中分配的起始地址为 0042 2000H，`sizeof(int)=4`，假定在 M 上执行上述程序段之前数组 a 不在主存，且在该程序段执行过程中不会发生页面置换。请回答下列问题。

(1) 数组 a 分为几个页面存储？对于数组 a 的访问，会发生几次缺页异常？页故障地址各是什么？

(2) 不考虑变量 i 和 j，该程序段的数据访问是否具有时间局部性？为什么？

(3) 计算机 M 的虚拟地址（A31~A0）中哪几位用作块内地址？哪几位用作 Cache 组号？`a[1][0]` 的虚拟地址是多少？其所在主存块对应的 Cache 组号是多少？

(4) 数组 a 占用多少主存块？假设上述程序段执行过程中数组 a 的访问不会和其他数据发生 Cache 访问冲突，则数组 a 的 Cache 命中率是多少？若将循环中 i 和 j 的次序调换：

```c
for (j = 0; j < 64; j++)
    for (i = 0; i < 24; i++)
        a[i][j] = 10;
```

则数组 a 的 Cache 命中率又是多少？

**作答区**

<br><br><br><br>

> [!faq]- 答案与解析
> **讲解抓手**：按行 7/8；按列别急着写 0%，先算 24 行落到 8 个组、每组 3 行，4 路装得下 → 还是 7/8。
>
> **(1) 2 个页面；2 次缺页；0042 2000H、0042 3000H**
> - 数组大小 $=24\times64\times4\text{B}=6\text{KB}$，页面 4KB → $\lceil6/4\rceil=2$ 页。
> - 执行前不在主存，每页第一次访问缺页 → 2 次。
> - 起始 0042 2000H 在第一页；第二页从 0042 3000H 开始（跨过 4KB 边界）。
>
> **(2) 没有时间局部性**
> - 每个数组元素只被访问 1 次，没有“同一数据再次访问”。
>
> **(3) 块内地址 A4~A0；组号 A10~A5；a[1][0] = 0042 2100H；组号 8**
> - 块 32B $=2^5$ → 块内地址低 5 位。
> - 行数 $=8\text{KB}/32\text{B}=256$，4 路 → 组数 $=256/4=64=2^6$ → 组号 6 位，即 A10~A5。
> - `a[1][0]` $=0042\,2000\text{H}+(64\times1+0)\times4=0042\,2100\text{H}$。
> - 0042 2100H 的 A10~A5 = 001000B = 8。
>
> **(4) 192 个主存块；两种顺序都是 87.5%**
> - 数组 6KB / 32B $=192$ 块；起始地址块内偏移为 0，正好 192 个整块。
> - 每块装 $32/4=8$ 个 int。
> - **按行**：同一块的 8 个元素连续访问，第一个缺失、后 7 个命中 → $h=7/8=87.5\%$。
> - **按列**：4 路组相联、共 64 组；同一列涉及的 24 行只映射到其中 8 个组（行步长 8 块），每组 3 行，$3<4$，组内装得下，不会替换。每个块含同一行的 8 列，第一次访问缺失、后 7 列命中 → 仍为 $h=7/8=87.5\%$。
>
> 易错：==按列访问不一定命中率低==。要看组相联路数是否装得下同一列涉及的行数；本题 3 行 < 4 路，所以不冲突。

## 第 5 页｜2025·T45(3)　组相联 + 数组缺失率

**题目**

32 位机，按字节编址。Cache 数据区 32KB，8 路组相联，块大小 64B，命中时间 2 个时钟周期，缺失损失 200 个时钟周期。页大小 4KB，数组 d 的起始虚拟地址为 0180 0020H。

```c
for (i = 0; i < 2048; i++)
    d[i] = d[i] / x;
```

int 占 4B，i、x 在寄存器中，代码已在 Cache 中，数组 d 在主存但不在 Cache。

(a) d[0] 在主存块内的偏移量是多少？

(b) 访问数组 d 的 Cache 缺失率是多少？

(c) 平均访问时间是多少？

**作答区**

<br><br><br>

> [!faq]- 答案与解析
> **讲解抓手**：先算偏移 32B，首块只装 8 个元素 → 129 块；再算读+写 4096 次访问 → 3.15%。
>
> **(a) 偏移 20H（32B）**
> - 块 64B → 块内地址 6 位；0180 0020H 的低 6 位 = 20H = 32。
>
> **(b) 缺失率 3.15%**
> - 每块装 $64/4=16$ 个 int；Cache 共 $32\text{KB}/64\text{B}=512$ 行，8 路 → 64 组。
> - d[0] 在块内偏移 32B，首块只装 8 个元素（d[0]~d[7]）；之后每块 16 个。
> - 所需块数 $=1+\lceil(2048-8)/16\rceil=1+128=129$。
> - 129 块连续分布到 64 组，每组 2~3 块，均 < 8 路 → 无冲突缺失；每块首次读缺失一次。
> - 每次迭代读+写各一次 → 总访问 $=2048\times2=4096$。
> - 缺失率 $=129/4096=3.15\%$。
>
> **(c) 8.30 个时钟周期**
> - $\text{AMAT}=2+(129/4096)\times200=8.30$。
>
> 易错：==首块不是满块==（d[0] 从块内 32B 开始），所以是 129 块而不是 $2048/16=128$ 块；另外读+写要算 2 次访存。
