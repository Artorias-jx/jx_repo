# 进程与页表专题

## 1. 核心本源

**一语破的**：页表是虚拟地址到物理地址映射的核心数据结构，每进程独立持有以实现内存隔离与虚拟存储。

**解决痛点**：
- **无页表场景的灾难**：多进程直接使用物理地址会导致地址冲突（进程 A 的代码可能覆盖进程 B 的数据）、无法防止恶意越界访问、无法突破物理内存容量限制（一个 4GB 进程需要 4GB 物理内存全程常驻）。
- **物理直觉**：页表 = 地址翻译字典 + 权限防火墙 + 按需调度索引。硬件 MMU 根据页表将进程"以为的地址"翻译为"真实的物理位置"，OS 根据页表项的存在位（P）决定数据在内存还是磁盘。

---

## 2. 运行机制与核心数据结构

### 核心数据结构

**页表项（PTE, Page Table Entry）**：
```
| 页框号 (20 bit) | 标志位 (12 bit) |
标志位包括：P(存在位), R/W(读写), U/S(用户/内核), D(脏位), A(访问位), NX(禁止执行)
```

**页表基址寄存器（PTBR / CR3）**：
- **存储内容**：顶级页表的物理基址（注意：是物理地址，非虚拟地址）
- **为何存物理地址**：MMU 硬件翻译虚拟地址的起点，若存虚拟地址会导致"查页表需先查页表"的硬件死循环

**进程控制块（PCB）**：
- 保存该进程的页表物理基址（进程切换时用于恢复 CR3）
- 保存页表结构元数据（多级页表的层级信息）

### 运转闭环

**地址翻译流程（以二级页表为例）**：
1. **CPU 发出虚拟地址**：`| 页目录索引(10 bit) | 页表索引(10 bit) | 页内偏移(12 bit) |`
2. **MMU 硬件操作**：
   - 读 CR3 获取页目录物理基址
   - 用页目录索引计算页目录项物理地址：`页目录基址 + 页目录索引 × 4`
   - 从页目录项读取二级页表的物理页框号
   - 用页表索引计算页表项物理地址：`二级页表基址 + 页表索引 × 4`
   - 从页表项读取数据页的物理页框号
   - 拼接：`物理地址 = 物理页框号 << 12 | 页内偏移`
3. **异常触发点**：
   - 若页目录项或页表项的 P 位为 0 → **触发缺页中断**（硬件）
   - CPU 陷入内核态，OS 缺页处理程序接管（软件）
   - OS 从磁盘调入页面，更新页表项，返回用户态重新执行访问指令

**进程切换与页表**：
1. **上下文保存**：当前进程的 CR3 值保存到其 PCB
2. **页表切换**：从新进程 PCB 读取其页表基址写入 CR3
3. **TLB 刷新**：硬件自动或 OS 显式刷新 TLB（防止新进程使用旧进程的地址翻译缓存）
4. **旧页表去向**：仍完整保留在物理内存中（低级调度不换出页表；只有中级调度挂起时才可能将部分下级页表换出至 Swap）

## 3. 408 选择题：易混陷阱与概念辨析

### 概念排雷

**陷阱 1：页表物理存放方式的误判**
- **单级页表**：必须严格物理连续（一个大数组，基址 + 页号 × 项大小直接寻址）
- **多级页表**：整体物理离散，每个页表页（4KB）内部连续，不同页表页可分散存放
- **408 陷阱**："多级页表解决了单级页表占用大量连续物理内存的问题" → 正确（多级按需分配 + 离散存放）

**陷阱 2：PTBR / CR3 存储的地址属性**
- **错误认知**：以为 CR3 存虚拟地址（因为页表"属于"进程虚拟地址空间）
- **正确理解**：CR3 存物理地址，是 MMU 硬件寻址的绝对起点
- **对比记忆**：PC（程序计数器）、SP（栈指针）存虚拟地址；CR3、中断向量表基址存物理地址

**陷阱 3：进程切换后旧页表的状态**
- **错误认知**：进程下 CPU 后页表被换出磁盘或销毁
- **正确理解**：低级调度（进程切换）仅改变 CR3 指向，旧页表完好留在物理内存；只有中级调度挂起进程时，才可能将不活跃的下级页表页换出至 Swap
- **推论**：频繁切换的进程（如时间片轮转）页表始终常驻内存

### 对比表格

| **维度**       | **单级页表**                       | **多级页表**                      |
| ------------ | ------------------------------ | ----------------------------- |
| **物理连续性**    | 必须严格连续（易产生外部碎片）                | 整体离散，页表页（4KB）内连续             |
| **内存占用**     | 全程常驻（32 位需 4MB，64 位需数百 GB）    | 按需分配（未使用的虚拟区无需分配下级页表）       |
| **访问内存次数**   | 1 次（查页表）+ 1 次（取数据）= 2 次       | n 级页表需 n+1 次（多级页表 + 数据）       |
| **TLB 命中优化** | 命中后 1 次访存                      | 命中后仍为 1 次访存（TLB 缓存最终物理地址）    |
| **适用场景**     | 早期小地址空间（16 位系统）               | 现代 64 位系统（地址空间稀疏，4 级页表主流）   |
| **页表项寻址公式** | `物理地址 = PTBR + 页号 × 项大小`      | 逐级索引：`下级基址 = 当前项[页框号] << 12` |

| **维度**     | **分页**                   | **分段**                  |
| ---------- | ------------------------ | ----------------------- |
| **分割依据**   | 固定大小物理块（4KB）             | 逻辑单元（代码段、数据段、栈段）        |
| **内部碎片**   | 有（最后一页可能浪费 0~4KB）         | 有（段内最后一块）               |
| **外部碎片**   | 无（固定大小分配）                | 有（变长段导致内存"蜂窝"）          |
| **地址结构**   | `页号 + 页内偏移`              | `段号 + 段内偏移`             |
| **越界检查**   | 硬件检查页内偏移 < 页大小（隐式）       | 硬件检查段内偏移 < 段长度（显式，段表项存段长） |
| **共享与保护**  | 粒度粗（整页共享）                | 粒度细（按逻辑单元共享代码段）         |
| **典型应用**   | 现代 OS 虚拟内存主流方案           | Intel x86 历史遗留，已被平坦模型替代 |

## 4. 408 大题：考法拆解与解题模板

### 核心考法

**类型 1：虚实地址转换计算**
- 给定页表内容、虚拟地址、页大小，求物理地址
- 变种：结合 TLB 命中率计算有效访存时间

**类型 2：多级页表空间开销计算**
- 给定地址空间大小、页大小、页表项大小，求页表占用内存
- 陷阱：题目问"最大占用"还是"实际占用"（按需分配）

**类型 3：缺页中断处理流程**
- 画状态图：CPU 发虚拟地址 → P=0 触发缺页 → OS 调页 → 更新页表 → 重新执行

### 解题模板

**模板 1：虚实地址转换（二级页表）**
```
已知：虚拟地址 0xABCD1234，页大小 4KB，页表如下
      页目录[0xABC] = 0x5000 (P=1)
      页表[0xD1] = 0x7000 (P=1)

步骤 1：拆解虚拟地址（页大小 4KB = 2^12，页内偏移 12 位）
        假设 32 位地址，10-10-12 分级：
        页目录索引 = 虚拟地址 >> 22 = 0x2AF (高 10 位)
        页表索引 = (虚拟地址 >> 12) & 0x3FF = 0x3CD (中间 10 位)
        页内偏移 = 虚拟地址 & 0xFFF = 0x234 (低 12 位)

步骤 2：查页目录
        页目录项物理地址 = CR3 + 0x2AF × 4
        读取页目录项 → 二级页表页框号 = 0x5000

步骤 3：查二级页表
        页表项物理地址 = 0x5000 << 12 + 0x3CD × 4
        读取页表项 → 数据页框号 = 0x7000

步骤 4：拼接物理地址
        物理地址 = (0x7000 << 12) | 0x234 = 0x07000234
```

**模板 2：多级页表空间计算**
```
已知：32 位地址空间，页大小 4KB，页表项 4B，采用二级页表

最大空间占用（假设虚拟地址全部使用）：
  - 页目录项数 = 2^32 / 2^12 / 2^10 = 2^10 = 1024 项
  - 页目录占用 = 1024 × 4B = 4KB（1 页）
  - 每个二级页表 = 1024 项 × 4B = 4KB
  - 二级页表总数 = 1024 个（页目录每项指向一个）
  - 总占用 = 4KB + 1024 × 4KB = 4MB + 4KB

实际占用（按需分配）：
  - 若进程只使用 8MB 虚拟地址空间：
  - 需要的页数 = 8MB / 4KB = 2048 页
  - 需要的二级页表数 = 2048 / 1024 = 2 个
  - 实际占用 = 4KB(页目录) + 2 × 4KB(二级页表) = 12KB
```

**模板 3：TLB 与 Cache 结合的有效访存时间**
```
已知：TLB 访问时间 = 1ns，TLB 命中率 = 80%
      内存访问时间 = 100ns
      Cache 命中率 = 90%，Cache 访问时间 = 10ns
      采用二级页表

情况分析：
  1. TLB 命中 + Cache 命中：1(TLB) + 10(Cache) = 11ns
  2. TLB 命中 + Cache 未命中：1(TLB) + 100(内存) = 101ns
  3. TLB 未命中 + Cache 命中：
     1(TLB 查询) + 2×100(查两级页表) + 10(Cache) = 211ns
  4. TLB 未命中 + Cache 未命中：
     1(TLB 查询) + 2×100(查两级页表) + 100(取数据) = 301ns

有效访存时间 EAT：
  EAT = 0.8 × [0.9×11 + 0.1×101] + 0.2 × [0.9×211 + 0.1×301]
      = 0.8 × 20 + 0.2 × 220 = 16 + 44 = 60ns
```

**易错点警示**：
- 单位换算：1KB = 1024B（二进制），1Kb = 1000bit（十进制）
- 页表项大小：32 位系统通常 4B，64 位系统 8B
- 访存次数：n 级页表未命中 TLB 时需 n+1 次访存（n 次查页表 + 1 次取数据）

## 5. 跨界联动

### OS 内部联动

**与进程管理**：
- 进程创建（`fork`）：父子进程共享页表，标记为只读，写时复制（COW）触发页表分离
- 进程切换：保存/恢复 CR3，刷新 TLB（ASID 技术可避免全刷新）
- 进程终止：回收页表占用的物理内存（逐级释放页表页）

**与内存管理**：
- 请求调页：缺页中断 → OS 页面置换算法（LRU/Clock）→ 更新页表项的 P 位
- 内存共享：多进程页表项指向同一物理页框号（动态库共享）
- 写时复制：页表项的 R/W 位标记只读，写操作触发保护异常 → OS 复制物理页

**与文件系统**：
- 内存映射文件（mmap）：文件内容直接映射到进程虚拟地址空间，页表项关联文件页缓存
- Swap 分区：被换出的页面在磁盘上的位置记录在页表项中（P=0 时，页框号字段存 Swap 偏移）

### 与计组联动

**MMU（内存管理单元）**：
- 硬件：地址翻译、权限检查、触发缺页异常（Page Fault）
- 软件（OS）：处理缺页异常、维护页表内容、调度页面换入换出

**TLB（快表）**：
- 本质：全相联 Cache，缓存虚拟页号 → 物理页框号的映射
- 计组考点：TLB 命中率、替换策略（LRU）、ASID（地址空间标识符）避免进程切换时全刷新
- 计算公式：`有效访存时间 = TLB命中率 × (TLB时间 + 内存时间) + TLB未命中率 × (TLB时间 + 页表查询时间 + 内存时间)`

**Cache 与页表交互**：
- 物理 Cache（PIPT）：用物理地址做索引，需先查页表/TLB 得物理地址
- 虚拟 Cache（VIPT）：用虚拟地址索引，可能导致歧义（同义/别名问题）
- 408 考点：虚实地址转换与 Cache/TLB 命中的组合计算

**中断机制**：
- 缺页中断：属于内中断（异常/陷入），CPU 自动保存现场 → 查中断向量表 → 跳转 OS 缺页处理程序
- 中断向量表基址寄存器（IDTR）：存物理地址（与 CR3 同理）

# 内存管理专题

## 1. 核心本源

**一语破的**：内存管理负责地址空间抽象、分配策略、页面调度与碎片治理，目标是空间利用率与访问效率的动态平衡。

**解决痛点**：
- **物理内存稀缺**：进程总需求超过物理容量（如 100 个 1GB 进程同时运行，物理内存仅 16GB）
- **地址冲突**：多进程直接使用物理地址会相互覆盖
- **碎片浪费**：固定分区产生内部碎片，动态分区产生外部碎片
- **物理直觉**：内存管理 = 虚拟化（给每个进程 4GB 假象）+ 复用（按需调页，100 个进程实际只加载 16GB 热数据）+ 隔离（页表权限位防越界）

---

## 2. 运行机制与核心数据结构

### 核心数据结构

**页框（Page Frame）**：
- 物理内存按 4KB 划分的块，用页框号标识（PFN, Page Frame Number）
- 分为两类用途：**数据页**（存放进程代码/数据）、**管理页**（存放页表项）

**空闲页框链表**：
- OS 维护的空闲物理页框池，分配时从链表摘下，释放时归还
- Linux：伙伴系统（Buddy System）管理不同尺寸的连续页框块（2^0, 2^1, ..., 2^10 页）

**页表项（PTE）结构**：
```
| 页框号 (物理页) | P | R/W | U/S | A | D | ... |
  - P (Present)：存在位，0 表示页面在磁盘
  - D (Dirty)：脏位，1 表示页面被修改过（换出时需写回磁盘）
  - A (Accessed)：访问位，用于页面置换算法（LRU/Clock）
```

**对换区（Swap Space）**：
- 磁盘专用分区，存放被换出的页面
- 页表项 P=0 时，页框号字段存该页在 Swap 中的偏移地址

### 运转闭环

**请求调页（Demand Paging）**：
1. **进程访问虚拟地址** → MMU 查页表 → P=0 触发缺页中断（硬件）
2. **OS 缺页处理**（软件）：
   - 若物理内存有空闲页框：从 Swap/文件系统调入页面 → 分配页框 → 更新页表 PTE（P=1, 页框号）
   - 若物理内存已满：执行页面置换算法（选择牺牲页） → 若牺牲页 D=1 则写回磁盘 → 调入新页面
3. **返回用户态**：重新执行触发缺页的指令（CPU 从中断返回地址继续）

**页面置换算法流程**（以 LRU 为例）：
1. 扫描页表找最久未使用页（通过 A 位 + 时间戳模拟）
2. 若牺牲页 D=1：写回磁盘（同步 I/O）
3. 更新牺牲页的页表项：P=0，页框号字段改为 Swap 偏移
4. 将新页面加载到该页框，更新请求页的页表项

## 3. 408 选择题：易混陷阱与概念辨析

### 概念排雷

**陷阱 1：页框的"众生平等"误解**
- **正确理解**：物理内存中的 4KB 页框，既可存放进程的数据页，也可存放页表项（页表也占用物理内存）
- **推论**：多级页表的每一级都存储在某个页框中，页表本身也可能被换出到 Swap（虽然顶级页表通常常驻）

**陷阱 2：页表项的页框号含义**
- **P=1 时**：页框号指向物理内存中的页框（数据或下级页表）
- **P=0 时**：页框号字段改为存储 Swap 偏移地址（磁盘块号）
- **408 陷阱**："页表项只存储物理页框号" → 错误（P=0 时存磁盘地址）

**陷阱 3：内部碎片 vs 外部碎片**
- **内部碎片**：分配单元内部浪费（分页最后一页、固定分区未用完）
- **外部碎片**：分配单元之间的空闲碎片无法利用（动态分区的"蜂窝洞"）
- **记忆口诀**：内部 = 单元内浪费；外部 = 单元间无法合并

### 对比表格

| **内存分配方式** | **连续分配**                    | **离散分配（分页）**            |
| ---------- | --------------------------- | ----------------------- |
| **分配原则**   | 进程占用连续物理地址                  | 进程可占用不连续的页框             |
| **内部碎片**   | 固定分区有；动态分区无                 | 有（最后一页）                 |
| **外部碎片**   | 动态分区严重；需紧凑（Compaction）      | 无（固定大小分配）               |
| **地址转换**   | 简单（基址寄存器 + 偏移）              | 复杂（页表查询）                |
| **共享实现**   | 困难（需调整多个进程的基址）              | 简单（页表项指向同一页框）           |
| **典型策略**   | 首次适应（FF）、最佳适应（BF）、最坏适应（WF） | 无需策略（任意空闲页框即可）          |

| **页面置换算法** | **实现复杂度** | **性能**    | **408 考法**                |
| ---------- | --------- | --------- | ------------------------- |
| **OPT**    | 理论最优      | 最少缺页次数  | 作为性能上界对比                  |
| **FIFO**   | 简单（队列）    | 可能产生抖动  | Belady 异常（页框增加反而缺页增多）     |
| **LRU**    | 复杂（栈/链表）  | 接近 OPT   | 计算缺页次数、模拟栈操作              |
| **Clock**  | 中等（循环链表）  | 近似 LRU   | 扫描 A 位找第一个 0（二次机会算法）      |
| **LFU**    | 复杂（计数器）   | 可能驱逐热页  | 区分访问频率 vs 访问时间            |

## 4. 408 大题：考法拆解与解题模板

### 核心考法

**类型 1：页面置换算法模拟**
- 给定页面访问序列、物理块数，求缺页次数与置换过程
- 常考算法：FIFO、LRU、OPT

**类型 2：地址空间与页表空间计算**
- 给定虚拟地址位数、页大小、页表项大小，求页表占用内存
- 陷阱：多级页表需分层计算

**类型 3：Belady 异常证明**
- 给特定序列，证明 FIFO 算法在页框增加时缺页次数反增

## 5. 跨界联动

### OS 内部联动

**与进程管理**：
- **写时复制（COW）**：`fork` 后父子进程共享物理页，页表项标记只读，首次写操作触发保护异常 → OS 复制物理页 → 更新页表 → 内存占用翻倍
- **进程换出（Swapping）**：中级调度将整个进程的页面批量换出到 Swap，保留 PCB 与顶级页表

**与文件系统**：
- **内存映射文件（mmap）**：文件内容映射到进程虚拟地址空间，读写操作触发缺页 → OS 从文件系统加载页面到页缓存
- **页缓存（Page Cache）**：文件 I/O 与内存页框的缓冲区，减少磁盘访问

**与设备管理**：
- **DMA 传输**：I/O 设备与内存直接传输数据，需物理地址（绕过 MMU）
- **驱动程序**：需访问固定物理地址的硬件寄存器，使用内核页表映射

### 与计组联动

**Cache 与内存层次**：
- **局部性原理**：页面置换算法（LRU）与 Cache 替换策略（LRU）共享理论基础
- **多级存储**：寄存器 → L1/L2/L3 Cache → 内存 → Swap → 磁盘，访问速度逐级递减

**虚拟内存与 Swap**：
- **磁盘 I/O**：换页是同步阻塞操作，延迟 ~10ms（机械硬盘）或 ~0.1ms（SSD）
- **颠簸（Thrashing）**：缺页频繁导致 CPU 大量时间等待 I/O，进程几乎无法推进
- **工作集模型**：计组中的"局部性窗口"对应 OS 的工作集，工作集大小 > 物理内存 → 颠簸

**地址总线与寻址范围**：
- 32 位地址总线 → 最大寻址 4GB（2^32 字节）
- 64 位地址总线 → 理论 16EB（2^64 字节），实际 CPU 仅实现 48 位（256TB）
- 页表层级由实际地址位数决定（x86-64 四级页表对应 48 位地址）

**TLB 与页表协同**：
- TLB Miss → 硬件自动遍历多级页表（x86 的 Page Walk）或触发软件 TLB 重填异常（MIPS）
- Page Walk 失败（P=0）→ 触发缺页中断 → OS 接管
