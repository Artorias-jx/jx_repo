# 1. 操作系统概述
## 1.1 基本概念
**操作系统**：系统资源的**管理者**，硬件资源与应用程序的**接口**，对系统资源进行**扩充**。
**管理**：处理器，存储器，文件，设备。分别在2,3,4,5章介绍。
**核心特性**：**并发**，**共享**，**虚拟**，**异步**。前二是一切的基础。
## 1.2 发展历程
**微观上并发，宏观上并行。只有多个cpu才能做到宏观上并行。**
考虑：CPU利用率，系统开销，IO利用率，系统吞吐量，实时，用户响应。
人工→脱机→**单道批处理**→**多道批处理**
**分时**→**实时**
网络/分布式，微机
## 1.3 操作系统运行环境
操作系统**内核**，支撑：**时钟管理**，**中断机制**，**原语**。提供资源管理的功能
**内核态**与**用户态**。只有内核态才能用特权指令。中断或异常时，硬件CPU自动切换用户态到内核态。异常中断部分参考计组。
**系统调用**：真正的操作系统接口。过程：传参，识别trap并切换到内核态，执行，切换回用户态。
## 1.4 操作系统结构
**分层法**：类似计算机网络的分层，下层为上层提供服务，方便调试与维护，但难划分，难修改
**模块化**：功能划分不同的模块，继续划分子模块，模块内部高耦合，模块之间低内聚。
**宏内核**：功能模块高度耦合内聚在内核中。
**微内核**：内核精简，任务分配出去，方便管理维护。微内核安全度高但是慢。
**外核**：将系统资源直接给用户用，自己只是负责安全分配和隔离
## 1.5 操作系统引导
**操作系统引导**：计算机通电后，通过一系列程序将操作系统内核加载到内存并启动的过程。
### 引导流程
1. **BIOS** 固化在 **ROM** 中，通电后 CPU 自动执行 BIOS，初始化硬件，建立中断向量表。
2. **BIOS** 执行硬件自检 (POST)，检测 CPU、内存、外设是否正常。根据 **CMOS 设置**确定启动设备优先级。
3. **BIOS** 从启动设备（硬盘/U盘）的**首扇区**读取 **MBR (主引导记录)** 到内存并执行。MBR 包含：引导代码 + 硬盘分区表。
4. **MBR 中的引导代码**解析分区表，找到**活动分区**，读取该分区的**首扇区 PBR (分区引导记录)** 到内存并执行。
5. **PBR 中的代码**加载**启动管理器**（如 GRUB、Bootmgr）到内存，提供操作系统选择界面。
6. **启动管理器**根据用户选择，将**操作系统内核**从硬盘加载到内存，跳转执行。 内核接管系统，重建中断机制，不再依赖 BIOS。
7. **内核**初始化内存管理、进程管理、设备驱动等模块，启动**首个用户进程**（如 `init`）。

> [!tip] 核心概念
> **BIOS** (ROM) → **MBR** (硬盘首扇区) → **PBR** (分区首扇区) → **启动管理器** → **内核** (内存)
## 1.6虚拟操作系统
第一类，直接运行在物理硬件上，最高特权软件。客户的操作系统处于虚拟内核态
第二类，运行在用户的操作系统上，本质用户级进程。

# 4. 文件管理

>引言：由于计算机内存ROM是易失性设备，容量有限，故现代计算机系统必须配置外存，用于存储用户和系统用到的大量程序和数据。其中存储的形式就是“文件”。需要的时候调入内存，或者打印出来。
>如果用户直接管理在外存中的文件，要求用户熟知外存特性，了解文件属性以及文件在外存中的位置，若有多用户，则要求保持数据的安全性和一致性。为了方便用户，OS中增加了文件管理功能，专门管理外存中的文件，并把文件的存取，共享和保护等手段交给用户
# 4.1 文件系统基础

文件由记录组成，记录是数据项的集合。数据项分为基本数据项和组合数据项。
文件的属性和分类，大致了解即可。属性就是文件的特性，包括名称类型创建者，控制权限，位置大小等。
文件的逻辑结构－－用户视角下的文件组织方式：
	分为无结构文件（由连续的字符流组成，又称字符流文件）和有结构文件
	有结构文件分为定长记录和变长记录。前者方便随机查找，后者只能顺序查找
	1.顺序文件，记录按顺序依次排列。按存入时间有序是串结构，按键字有序是顺序结构。只适用于连续存储，单条记录插入删除麻烦
	2.索引文件，**定长记录的顺序文件可以通过公式计算地址**，但是变长只能累加。设计一个**索引表**，用于存储执行某条记录地址的**指针**，索引文件需要额外维护一张索引表，增大了存储开销。
	3.索引顺序文件，变长记录的文件分为若干组，每组头部设一个索引，为每组的首条记录设置一个索引表。组内可无序，但组间按==关键字有序==，类似于分块查找。最优效率与分块查找一致。同样有维护索引表的开销
	4.直接查找，通过H（key）= address来设计，可能有冲突

# 4.2 目录与文件
对文件目录的要求：按名存储，提供检索速度，支持共享，允许重名。
### 基础概念辨析

目录项，目录文件中的一项
目录文件，一个专门存目录项的文件，只有目录（文件夹）才有一个目录文件，存在磁盘里面。若引入了Inode，就可以是小的目录项，否则只能存FCB

FCB存基本信息，控制信息和使用信息。==若不设索引节点==，目录项就是FCB，存FCB目录文件会占用大量磁盘空间，进一步导致占用盘块过多，检索文件名时需要访问大量盘块，引发大量磁盘IO。

因为只需要匹配文件名即可进行文件匹配，匹配成功才需要地址等信息，这就意味着检索阶段只需要文件名，于是设计出来==索引节点==。
索引节点存的是文件的详细信息。文件的索引节分为磁盘索引节点和内存索引节点。磁盘索引节点存在磁盘里，文件被打开时，磁盘索引节点载入内存，附加状态等成为内存索引节点。
这样目录项就精简成文件名+索引节点的编号。显著减少了检索阶段的磁盘IO频率。匹配成功文件名，得到编号，去磁盘中拿出对应编号的索引节点，进一步得到文件的物理块号。

目录的结构，现在常用树形目录，显著提升了文件系统的提升效率和性能。用路径名来管理文件，分隔符为"/"，若从根目录开始则为绝对路径，否则为相对路径。每个用户都有当前目录，加快了文件的检索速度。虽然按路径名访问增大了IO次数，但其优大于弊。
### 文件的物理结构与文件的分配方式（对非空闲块的管理）：
物理结构关注文件在磁盘上如何存储，分为连续分配，链接分配，索引分配。
分配方式，指的是解决如何给文件分配已使用的磁盘块，属于对非空闲块的管理。磁盘也被分为磁盘块，大小与内存的页面大小一致，==所有磁盘操作都是以磁盘块为单位==
1. **连续分配**：要求文件在磁盘上占用连续的块，使得寻道时间和次数最短。目录项需要记录==文件起始块的块号和总块数（长度）==。支持顺序访问和随机访问，顺序访问高效速度快。但是占用连续空间，易产生大量外部碎片，难以支持动态增长，插入删除开销大。
2. **链接组织方式**：消除了外部碎片，可离散存物理块。插入删除容易，适应动态增长。==题目默认是隐式链接==
**隐式链接组织**：不支持随机，只支持顺序，可靠性差，一个指针出错导致整链断开。且存储指针占用空间。目录项存==起始指针和末尾指针==

> 引入“簇”，将连续的物理块组成成“簇”，文件的分配和链接以“簇”为基本单位，降低存储开销，节省链式查找时间，可能产生内部碎片。

**显式链接组织**：把指针集中在FAT表中，==整个文件系统只有一张==，每个物理块的下一个物理块编号（类似静态链表）。目录项中额外存文件起始的物理块号（簇号）。支持顺序访问和随机访问，要访问第i个物理块（==或者第j个字节的内容==），只需要在FAT表中通过“下一块“来顺序找到（==或计算偏移之后再找==）即可，因为FAT表在内存，所以开销比隐式低多了。FAT表可以存-2（也可以其他）表示空闲，-1表示结尾等等。
缺点：FAT表会被全部调用到内存中。假设物理块大小不变，磁盘越大，物理块越多，FAT表行数越多，每行存字节数不变，故所占内存越大。
3. 索引分配方式
**单级索引分配方式**：为每个文件分配一个==索引表==，顺序存储物理块号，索引表存在磁盘块中，大小受到磁盘块的限制。优点：高效
访问第i块，只需读索引表的第i个即可。且不会产生外部碎片。缺点：若文件过小，浪费索引块的存储空间。文件过大，索引块还得连起来，效率低下。
多级索引分配方式：文件过大，索引块过多，借鉴内存的多级页表，形成多级索引。优点：提升大型文件的查找效率。缺点：访问一个盘块会因索引级数增加而导致IO次数增加，系统若只采用多级索引，则对于小文件，IO次数多，整体IO性能不行。于是创造出了混合索引。
混合索引分配方式：根据文件大小动态采用分配策略。对于小文件，inode中直接存放盘块地址，即直接寻址；对于中型文件，采用一级索引；对于大型，采用多级索引。常用10个直接地址，1个间接地址，1个二级间址，1个三级间址。若磁盘块大小4KB，10个直接可存40KB的文件；
