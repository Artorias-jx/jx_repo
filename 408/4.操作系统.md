# 操作系统核心笔记：进程与页表体系全景解析

## 1. 核心本质：为什么要为每个进程分配独立页表？

|**核心目标**|**具体解决的问题**|**底层实现机制**|
|---|---|---|
|**内存隔离与安全**|防止进程间非法越界访问与恶意破坏|各进程拥有独立的页表映射，虚拟地址空间物理隔离。|
|**统一地址视图**|简化编译、链接与程序重定位|编译器让每个程序都独占从 `0x00000000` 开始的虚拟地址空间，运行时由页表动态映射到物理内存。|
|**支持虚拟存储**|解决物理内存不足与大程序运行问题|结合缺页中断与页面置换，实现按需调页、超额分配（Overcommit）与换入换出。|
|**细粒度权限控制**|防止代码自篡改与栈溢出攻击|页表项自带硬件标志位：读/写控制（`R/W`）、不可执行保护（`NX/XD`）、特权级（`U/S`）。|
|**共享与写时复制**|减少内存浪费，极速创建子进程|动态库（libc）多进程映射同一物理页；`fork()` 默认共享物理内存并标记只读，发生写入时再按需分配新页（COW）。|

## 2. 页表的物理存储机制：一级页表 vs. 多级页表

Plaintext

```
【一级页表】 物理上必须严格连续（单一大数组） ──> 易产生外部碎片，常驻内存开销大 (4MB)
【多级页表】 物理上高度离散（按 4KB 页框切分） ──> 顶级页表索引下级页表，按需动态分配
```

- **一级页表（必须物理连续）**：
    
      
    - **寻址公式**：
        
          
        
        $$\text{页表项物理地址} = \text{PTBR} + (\text{页号} \times \text{页表项大小})$$
        
    - **特性**：由于硬件 MMU 依靠纯物理连续数组偏移寻址，一级页表必须占用一整块**连续物理内存**，且必须全部常驻内存。
        
          
        
- **多级页表（实现物理离散）**：
    
      
    - **按页切割**：将庞大的页表切分为大小恰好为 **1 个物理页框（通常为 4 KB）** 的微型页表块。
        
          
        
    - **离散分配**：各级页表块可任意存放在物理内存的空闲页框中，**块与块之间完全无需连续**。
        
          
        
    - **按需创建**：未使用的虚拟地址空间不需要分配对应的下级页表，极大节省主存。
        
          
        

## 3. 硬件交互：页表基址寄存器（PTBR / CR3）

- **存储属性**：**必须存放顶级页表的绝对物理地址**。
    
      
    
- **核心成因**：
    
      
    - CPU 内部的 MMU 是纯硬件电路。
        
          
        
    - 若寄存器存放虚拟地址，MMU 为读取页表必须先翻译该虚拟地址，而翻译又需要访问页表，将陷入**先有鸡还是先有蛋的硬件死循环**。
        
          
        
- **地址属性对比**：
    
      
    - **PC（程序计数器）、SP（栈指针）** $\to$ 存放**虚拟地址（逻辑地址）**，执行时需经 MMU 翻译。
        
          
        
    - **PTBR / CR3（页表基址寄存器）** $\to$ 存放**物理地址**，直接供 MMU 作为翻译的硬件绝对起点。
        
          
        

## 4. 进程调度与切换时的页表流转

### 进程被调度换下 CPU 时，页表去哪了？

- **常规进程切换（低级调度：进入就绪/阻塞态）**：
    
      
    - **页表完全保留在物理内存中**，并没有被销毁或换出。
        
          
        
    - 操作系统将该进程顶级页表的物理地址保存在其 **PCB** 中。
        
          
        
    - 调度器加载新进程的页表物理基地址写入 **CR3 寄存器**，并**刷新快表（TLB Flush）**。
        
          
        
- **内存不足被挂起换出（中级调度：就绪挂起/阻塞挂起）**：
    
      
    - 进程的数据页与部分下级页表被写入磁盘对换区（Swap）以腾出物理内存。
        
          
        
    - 顶级页表与 PCB 依然常驻内核内存。
        
          
        

## 5. 多进程页表的空间隔离与共享架构

Plaintext

```
【进程 A 页表 (物理页框 100)】                   【进程 B 页表 (物理页框 230)】
┌───────────────────────────┐                  ┌───────────────────────────┐
│ 内核空间页表项 (高地址)    │ ───┐          ┌─── │ 内核空间页表项 (高地址)    │
├───────────────────────────┤    │          │    ├───────────────────────────┤
│ 用户空间页表项 (低地址)    │ ─┐  │          │  ┌─ │ 用户空间页表项 (低地址)    │
└───────────────────────────┘  │  │          │  │ └───────────────────────────┘
                               │  │          │  │
                               ▼  ▼          ▼  ▼
                        ┌───────────┐      ┌───────────┐
                        │ 进程 A    │      │ 进程 B    │
                        │ 私有物理页│      │ 私有物理页│
                        └───────────┘      └───────────┘
                                   ╲        ╱
                                    ▼      ▼
                               ┌────────────────┐
                               │ 操作系统内核   │
                               │ 共享物理内存   │
                               └────────────────┘
```

- **不同进程页表的存放**：
    
      
    - 各进程页表在物理内存中**离散存放于不同物理页框**中，彼此物理地址完全无关。
        
          
        
- **用户空间（下半部）**：
    
      
    - 各进程映射完全独立，相同的虚拟地址指向完全不同的物理页框。
        
          
        
- **内核空间（上半部）**：
    
      
    - 所有进程的高地址内核映射**完全相同**，统一指向物理内存中唯一的操作系统内核代码与数据。
        
          
        

## 6. 408 考点速记与高频陷阱

- **单级页表物理必须连续，多级页表物理整体离散。**
    
      
    
- **页表基址寄存器存的是物理地址，不是虚拟地址。**
    
      
    
- **进程下 CPU 时，页表依然留在物理内存，改变的只是 CR3 寄存器的指向。**
    
      
    
- **多进程在用户空间相互隔离，在内核空间共享同一份物理映射。**
