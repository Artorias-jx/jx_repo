### 1.1.1 三种字长对比

| 字长类型     | 定义            | 典型位数      | 决定因素            | 408常考陷阱              |
| -------- | ------------- | --------- | --------------- | -------------------- |
| **机器字长** | CPU一次能处理的数据位数 | 16/32/64位 | 通用寄存器位数 = ALU位宽 | 与存储字长混淆              |
| **指令字长** | 一条指令的二进制位数    | 不固定       | 指令格式设计          | 可以是存储字长的倍数           |
| **存储字长** | 一个存储单元的位数     | 8/16/32位  | 编址方式决定          | 按字节编址=8bit，按字编址≠8bit |

| 特点 | 冯诺依曼机 | 现代计算机 | 备注 |
|------|-----------|-----------|------|
| 核心部件 | 以**运算器**为核心 | 以**存储器**为核心 | 408爱考这个区别 |
| 存储器 | 主存 | 主存 + Cache | Cache透明性 |
| 工作方式 | 存储程序 | 存储程序 | 相同 |

## 1.2 性能指标计算模板

### 1.2.1 主存容量计算

**存储器层次结构**（帮助理解）：
```
1个存储体
  └─ n个存储单元（与地址一一对应，n = 2^MAR位数）
       └─ n×m个存储元件（每个存储元件存1个bit，m = 存储字长 = MDR位数）
```

**公式**：主存容量 = 2^MAR位数 × (MDR位数 ÷ 8)，单位是B

**解题步骤**：
1. ⚠️ **第一步必看**：确定编址方式（按字节/按字）
2. 计算存储单元个数 = 2^MAR位数
3. 计算每个单元字节数 = MDR位数 ÷ 8
4. 相乘得容量

**例题模板**：
```
已知：MAR=20位，MDR=32位，按字节编址
第一步：按字节编址 → 存储字长=8bit
第二步：存储单元个数 = 2^20
第三步：每单元字节数 = 32÷8 = 4B
第四步：容量 = 2^20 × 4B = 4MB
```

**易错点**：
- ❌ 忘记看编址方式
- ❌ MDR位数忘记÷8转成字节
- ❌ 按字编址时，以为存储字长固定是8bit

### 1.2.2 CPU性能指标关系图

```
主频 (Hz) ←→ CPU时钟周期 (s)
   ↓                ↓
   ├────→ CPI ←─────┤
   ↓                ↓
 MIPS            CPU执行时间
```

**核心公式串联**：
1. CPU时钟周期 = 1 ÷ 主频
2. CPU执行时间 = 时钟周期数 ÷ 主频 = 指令条数 × CPI ÷ 主频
3. MIPS = 主频 ÷ (CPI × 10^6) = 指令条数 ÷ (执行时间 × 10^6)

**解题模板**：
```
已知：程序有1000条指令，平均CPI=2，主频=1GHz
求：CPU执行时间和MIPS

步骤1：CPU执行时间 = (1000 × 2) ÷ (1×10^9) = 2μs
步骤2：MIPS = 1×10^9 ÷ (2 × 10^6) = 500 MIPS
```

**防坑提醒**：
- ⚠️ 注意单位换算：GHz = 10^9 Hz，MHz = 10^6 Hz
- ⚠️ MIPS公式中的10^6不要漏

### 1.4.1 "透明"的本质理解

**透明 = 看不见 = 不需要关心**

例如：
- Cache对程序员透明 = 程序员不需要（也无法）手动管理Cache
- IR对程序员透明 = 你写代码时根本不知道有IR这个寄存器
- 虚拟内存对程序透明 = 程序以为自己在用物理内存

**反例（不透明）**：
- 通用寄存器对汇编程序员不透明 = 你要明确指定用哪个寄存器

**类比理解**：

- 增加流水线 → 吞吐量↑，但单条指令的响应时间不一定↓

# 2. 数据表示和运算

## 2.1 核心对比表

### 2.1.1 四种编码方式对比

| 编码 | 符号位规则 | 数值位规则 | 表示范围（n+1位） | 单调性 | 主要用途 |
|------|----------|-----------|----------------|--------|---------|
| **原码** | 0正1负 | 与真值相同 | -(2^n-1) ~ +(2^n-1) | ❌ 不单调 | 不用于运算 |
| **补码** | 0正1负 | 负数=模-真值 | -2^n ~ +(2^n-1) | ✅ 单调 | **运算首选** |
| **反码** | 0正1负 | 负数=按位取反 | -(2^n-1) ~ +(2^n-1) | ❌ 不单调 | 过渡形式 |
| **移码** | **相反** | 真值+2^n | -2^n ~ +(2^n-1) | ✅ 单调 | **浮点数阶码** |

**重要结论**：
- 补码和移码都是单调的：二进制编码越大 → 真值越大
- 移码 = 补码符号位取反
- 只有补码能多表示一个最小负数（-128 / -2^n）

---

### 2.1.2 补码的"里程表"理解

**个人理解**：把符号位也当成数值位，整个补码就是一个"循环计数器"

```
真值:     -4    -3    -2    -1     0    +1    +2    +3
8位补码: 1100  1101  1110  1111  0000  0001  0010  0011
         ←────────── 连续递增 ──────────→
```

**关键insight**：
- 补码空间是连续的、单调的
- 从0往前数（减法）就自然到负数区域
- **这就是为什么补码能用加法实现减法！**

---

### 2.1.3 定点数 vs 浮点数

| 特性 | 定点数 | 浮点数 |
|------|--------|--------|
| 小数点位置 | 固定 | 浮动（科学计数法） |
| 表示范围 | 小 | 大（指数表示） |
| 精度 | 固定 | 可变（尾数决定） |
| 运算复杂度 | 简单 | 复杂（需对阶） |
| 硬件成本 | 低 | 高 |
| C语言类型 | int, long | float, double |

## 2.2 计算题模板

### 2.2.1 IEEE 754浮点数转换（真值→机器码）

**解题步骤**（以单精度为例）：

**第一步：转二进制**
- 整数部分：除2取余
- 小数部分：乘2取整
- ⚠️ 注意：不是每个十进制小数都能精确表示！

**第二步：规格化**
- 移动小数点，使其变为 1.xxxxx × 2^e 的形式
- 记录阶码 e

**第三步：计算偏置阶码**
- 单精度：E = e + 127
- 双精度：E = e + 1023
- ⚠️ 注意：E用无符号数表示

**第四步：处理尾数**
- IEEE 754隐藏最高位的1（规格化数才隐藏）
- 单精度取23位，双精度取52位
- 不够补0，多了四舍五入（就近舍入）

**第五步：拼接**
```
[符号位 1位][阶码 8/11位][尾数 23/52位]
```

**例题**：
```
将 -12.625(D) 转换为IEEE 754单精度浮点数

步骤1：转二进制
12(D) = 1100(B)
0.625(D) = 0.101(B)
结果：-1100.101(B)

步骤2：规格化
-1100.101 = -1.100101 × 2^3
阶码 e = 3

步骤3：计算偏置阶码
E = 3 + 127 = 130(D) = 10000010(B)

步骤4：处理尾数
隐藏1后：100101
补齐23位：10010100000000000000000

步骤5：拼接
符号位=1, 阶码=10000010, 尾数=10010100000000000000000
结果：1 10000010 10010100000000000000000
```

**易错点清单**：
- ❌ 忘记加偏置值127/1023
- ❌ 尾数忘记隐藏最高位的1
- ❌ 十六进制输出时，忘记4位一组分组
- ❌ 阶码全0和全1的特殊情况没判断

---

### 2.2.2 IEEE 754特殊情况判断

**快速记忆法**：

| 阶码E | 尾数M | 表示 | 真值 |
|-------|-------|------|------|
| **全0** | 全0 | ±0 | 0 |
| **全0** | 非0 | 非规格化数 | ±0.M × 2^(-126/-1022) |
| 正常值 | 任意 | 规格化数 | ±1.M × 2^(E-127/1023) |
| **全1** | 全0 | ±∞ | 无穷大 |
| **全1** | 非0 | NaN | 非数字 |

**口诀**：
- 阶码全0看尾数：尾数全0是零，尾数非0是非规格化
- 阶码全1看尾数：尾数全0是无穷，尾数非0是NaN

---

### 2.2.3 浮点数加减运算步骤

**步骤**：对阶 → 尾数运算 → 规格化 → 舍入 → 溢出判断
**详细流程**：
1. **对阶**（小阶向大阶看齐）
   - 比较两数阶码，阶码小的尾数右移
   - ⚠️ **大数吃小数**：float大-小>24，double大-小>53时，小数完全丢失

2. **尾数运算**
   - 对阶后的尾数相加/减
   - 注意符号位的处理

3. **规格化**
   - 左规：尾数左移，阶码-1（尾数出现前导0时）
   - 右规：尾数右移，阶码+1（尾数溢出时）

4. **舍入**
   - 默认：就近舍入（0舍1入，但遇到0.5看前一位奇偶）
   - ⚠️ IEEE 754规定至少保留3位冗余位
   - 规则：
     - 冗余位第一位=0：截断
     - 冗余位第一位=1且后面有非0：进1
     - 冗余位=100：看尾数最后一位，0截断，1进位

5. **溢出判断**
   - 上溢：阶码 > 最大阶码（如单精度>254）
   - 下溢：阶码 < 最小阶码（如单精度<-126）

**易错点**：
- ❌ 对阶时搞反方向（应该是小→大）
- ❌ 舍入规则记错
- ❌ 左规时忘记阶码要减1

## 2.3 知识串联

### 2.3.1 为什么计算机用补码？

**问题链**：
1. 为什么不用原码？
   - 原码加法需要判断符号，硬件复杂
   - 原码有+0和-0两种表示，浪费编码

2. 补码的优势？
   - **减法变加法**：a - b = a + (-b的补码)
   - 符号位可以参与运算
   - 只有一个0
   - 硬件实现简单（只需要加法器）

3. 为什么浮点数阶码用移码？
   - 移码比较大小方便：直接按无符号数比较
   - 对阶时需要频繁比较阶码大小

**全局视角**：
```
运算需求 → 选择编码方式 → 影响硬件设计
   ↓              ↓              ↓
减法要快 → 补码（加法实现） → 只需加法器
阶码比较 → 移码（便于比较） → 简化对阶电路
```

### 2.3.2 数据类型转换全景图

```
        精度
         ↑
    double (64位)
      ↗  ↖
float      long (64位)
  ↗  ↖      ↗  ↖
int ←→ unsigned int
(32位)    (32位)
  ↖  ↗
   short
  (16位)
```

**转换规则总结**：

| 转换方向 | 会不会出问题 | 原因 |
|---------|------------|------|
| int → float | **可能精度丢失** | float有效位仅24位，int有32位 |
| int → double | ✅ 通常安全 | double有效位53位 > int的32位 |
| float → double | ✅ 通常安全 | double表示范围更大 |
| double → float | **可能溢出或精度丢失** | float表示范围小、有效位少 |
| float/double → int | **小数截断 + 可能整数溢出** | 小数部分直接丢弃 |

## 2.4 个人理解笔记

### 2.4.1 移码的"平移"本质

**个人理解**：移码就是把整个数轴向右平移，让最小的负数映射到0

```
真值:     -128  -127  ...   -1    0    1   ...  127
8位移码:    0     1   ...  127  128  129  ...  255
           └────────  向右平移128  ────────┘
```

**为什么这样设计？**
- 硬件比较大小时，只需要按无符号数比较
- 0000 0000 一定是最小值，1111 1111 一定是最大值
- **对于浮点数对阶，这个特性太重要了！**

---

### 2.4.2 IEEE 754的"隐藏位"技巧

**为什么隐藏最高位的1？**
- 规格化后第一位必然是1（1.xxxxx的形式）
- 与其浪费一个bit存储必然是1的位，不如省下来多存一位尾数
- **相当于白赚1位精度！**

**为什么非规格化数不隐藏？**
- 非规格化数是0.xxxxx的形式，第一位是0不是1
- 用来表示接近0的极小数

# 附录：快速查询表

## A. 所有计算公式汇总

### 存储器相关
- 主存容量 = 2^MAR位数 × (MDR位数 ÷ 8)
- Cache容量 = 块数 × 块大小

### CPU性能
- CPU执行时间 = 指令条数 × CPI ÷ 主频
- MIPS = 主频 ÷ (CPI × 10^6)
- CPI = Σ(指令i的CPI × 指令i的比例)

### 总线
- 总线带宽 = 总线位数 × 总线工作频率
- 总线工作频率 = 时钟频率 ÷ 总线周期数

### 浮点数
- IEEE 754单精度：E = e + 127
- IEEE 754双精度：E = e + 1023
