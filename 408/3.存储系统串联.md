# 3. 存储系统（计组 + OS 串联）

> 存储系统有**两套映射**要打通：**Cache 映射**把主存映射进 CPU 旁边的小内存，**页式映射**把虚拟地址映射成物理地址。
> 两套都是"上层快而小、下层慢而大"，都吃**局部性原理**，都由硬件自动完成、对程序员透明。
> 本章把计组第 3 章（硬件）和 OS 第 3 章（页表/缺页）缝成一条线，走完"一个虚拟地址怎么变成 CPU 手里那条数据"。
> 单科细节见 [[408/2.计算机组成原理笔记]] 第 3 章、[[408/4.操作系统]] 第 3 章。

## 3.1 两套映射体系总览

### 3.1.1 存储层次结构

| 存储层次           | 访问速度         | 容量               | 成本  | 由谁管理  | 对程序员 | 主要技术  |
| -------------- | ------------ | ---------------- | --- | ----- | ---- | ----- |
| **寄存器**        | 最快（<1ns）     | 最小（KB级）          | 最高  | 编译器   | 可见   | 硬件    |
| **Cache**      | 很快（1-10ns）   | 小（MB级）           | 高   | 硬件自动  | 透明   | SRAM  |
| **主存**         | 较快（50-100ns） | 中（GB级）           | 中   | OS+硬件 | 透明   | DRAM  |
| **虚拟内存**       | -            | 由地址位数决定（32位→4GB） | -   | OS    | 透明   | 页表/段表 |
| **辅存（磁盘/SSD）** | 慢（ms级）       | 最大（TB级）          | 最低  | OS+用户 | 可见   | 机械/闪存 |

**虚拟内存容量** = 地址位数决定（32位最大4GB），==实际可用 ≈ 物理内存 + 交换空间==，但它不是"把磁盘当内存用"，而是一套地址映射机制，给每个进程独立的地址空间。

**核心原理**：**时间局部性**（刚访问的还会再访问）+ **空间局部性**（相邻地址一起访问）→ 数据分层按需调度，对上层透明。

***

### 3.1.2 两套映射对照

**Cache 映射（计组）**：物理地址 → Cache 位置，硬件实现，纳秒级，目标是**速度**。

| 映射方式      | 地址划分      | 硬件复杂度    | 冲突      | 替换算法         |
| --------- | --------- | -------- | ------- | ------------ |
| **直接映射**  | 标记+行号+块内  | 低        | 多（固定位置） | 不需要          |
| **全相联映射** | 标记+块内     | 高（并行比较器） | 少       | 需要（LRU/FIFO） |
| **组相联映射** | 标记+组号+块内  | 中        | 折中      | 组内需要         |

**页式映射（OS）**：虚拟地址 → 物理地址，OS管理+硬件辅助（MMU），微秒级（缺页时毫秒级），目标是**扩展地址空间**。

| 映射方式     | 地址划分         | 页表层级 | 空间开销    | 适用场景  |
| -------- | ------------ | ---- | ------- | ----- |
| **单级页表** | 页号+页内偏移      | 1级   | 大（连续空间） | 小地址空间 |
| **多级页表** | 一级页号+二级页号+偏移 | 2-4级 | 小（按需分配） | 大地址空间 |

**段式/段页式（OS）**：

| 特性 | 页式 | 段式 | 段页式 |
|-----|------|------|--------|
| **划分依据** | 固定大小 | 逻辑单位（可变） | 段内分页 |
| **地址结构** | 页号+页内偏移 | 段号+段内偏移 | 段号+页号+页内偏移 |
| **碎片** | 内部碎片 | 外部碎片 | 内部碎片 |
| **共享/保护** | 较难 | 容易 | 容易 |
| **透明性** | 完全透明 | 对用户可见 | 结合 |

> [!tip] 一句话分工
> ==Cache 映射在页式映射之后==：先由页表把虚拟地址变成物理地址，再由 Cache 用物理地址去找数据。所以串起来是 **虚拟地址 → 页表/TLB → 物理地址 → Cache → 数据**。

***

### 3.1.3 替换算法对比

**Cache 替换算法（计组）**：

| 算法 | 原理 | 硬件实现 | 命中率 | 开销 |
|-----|------|---------|-------|------|
| **随机(RAND)** | 随机选一块 | 简单（随机数生成器） | 低 | 最低 |
| **FIFO** | 先进先出 | 简单（队列计数器） | 中 | 低 |
| **LRU** | 最近最少使用 | 复杂（访问时间记录） | 高 | 高 |
| **LFU** | 最不经常使用 | 复杂（访问次数计数） | 中 | 高 |

**页面置换算法（OS）**：

| 算法 | 原理 | 是否需要硬件支持 | 性能 | Belady异常 | 实现难度 |
|-----|------|---------------|------|----------|---------|
| **最佳(OPT)** | 置换最长时间不用的 | 否（理论算法） | 最优 | 无 | 不可实现 |
| **FIFO** | 先进先出 | 否 | 差 | **有** | 简单 |
| **LRU** | 最近最少使用 | 是（访问位） | 好 | 无 | 困难 |
| **Clock(二次机会)** | FIFO+访问位 | 是（访问位） | 较好 | 无 | 中等 |
| **改进Clock** | Clock+修改位 | 是（访问位+修改位） | 好 | 无 | 中等 |

**Belady异常**：增加页框数，缺页次数反而增加。==只有 FIFO 会出现==。

- LRU 是 Cache 和页面置换的首选（性能好）
- 实际系统常用 Clock 算法（LRU 的近似，实现简单）
- Cache 用"替换算法"叫法，OS 用"页面置换"，**本质同一个东西**，只是对象不同（Cache 行 vs 物理页框）

***

### 3.1.4 TLB vs Cache

| 对比维度      | TLB（快表）           | Cache                 |
| --------- | ----------------- | --------------------- |
| **组成**    | 有效位/Tag(虚页号)/页框号   | 有效位/脏位/Tag/数据块        |
| **作用**    | 缓存页表项（虚页号→页框号）    | 缓存数据和指令               |
| **输入**    | **虚拟**页号           | **物理**地址              |
| **输出**    | 物理页框号             | 数据                    |
| **位置**    | CPU中的MMU内部         | CPU与主存之间（逻辑上），实际在CPU内 |
| **大小**    | 很小（几十到几百项）        | 较大（KB到MB）             |
| **映射方式**  | 全相联/组相联（很少直接映射）   | 直接/组相联/全相联            |
| **未命中代价** | 访问页表（几十ns）        | 访问主存（几十ns）            |
| **管理者**   | OS（页表内容）+硬件（TLB）  | 硬件自动                  |

> tag 相当于身份证前几位，表示"这个位置是不是你"；有效位表示"这个位置的数据是否真实存在"。==先看有效位，再看 tag==，有效位=1 且 tag 相同才命中。比较器在哪、标记里放哪几位、三张表各存在哪，见 3.5.2、3.5.3。

> [!warning] 别把两个"标记"混了
> TLB 的标记是**虚页号**（用虚拟地址查），Cache 的标记是**物理块号**（用物理地址查）。==TLB 在 Cache 前面==。

## 3.2 三种地址的组成

> 做题时先把"当前是哪种地址、切成哪几段、每段几位"写清楚，剩下的都是套公式。三个地址层层递进：虚拟地址 →（页表）→ 物理地址 →（再切）→ Cache 地址。

### 3.2.1 虚拟地址（逻辑地址）

**分页**：由==虚页号 + 页内偏移==两部分组成。

```
| 虚页号 VPN | 页内偏移 W |
```

设虚拟地址 $m$ 位，页大小 $2^n$ 字节：

- **页内偏移 W**：$n$ 位，$n = \log_2(\text{页大小})$
- **虚页号 VPN**：$m - n$ 位

**两级页表**：把虚页号再拆成两段，`| 一级页号 P1 | 二级页号 P2 | 页内偏移 W |`。
**分段**：`| 段号 S | 段内偏移 W |`；**段页式**：`| 段号 S | 段内页号 P | 页内偏移 W |`。

> 页大小是 2 的幂，所以切分就是**数位**：低 $n$ 位是偏移，往上都是页号。
> ==加入 TLB 后，虚页号内部还要按 TLB 的映射方式再切一刀（标记 + 组号），见 3.3.2。==

***

### 3.2.2 物理地址

**分页**：由==物理页框号 + 页内偏移==两部分组成。

```
| 页框号 PPN | 页内偏移 W |
```

设物理地址 $k$ 位，页大小仍 $2^n$ 字节：

- **页内偏移 W**：$n$ 位，==与虚拟地址的偏移位数完全相同==
- **页框号 PPN**：$k - n$ 位

> [!tip] 核心：偏移不动，只换高位
> 页大小 = 页框大小 ⇒ 虚拟地址和物理地址的**低 $n$ 位偏移一模一样**。地址变换只用把高位的**虚页号**换成**页框号**，低位原样抄下来。
> 这就是"物理地址 = 页框号 × 页大小 + 页内偏移"的位运算本质：$\text{PA} = (\text{PPN} \ll n) \mid W$。

***

### 3.2.3 Cache 地址（把物理地址再切一刀）

Cache 拿**物理地址**来切。物理地址先看成 `| 块号 | 块内地址 |`，块号 = 物理地址的高位；再按映射方式把块号切分：

**直接映射**：

```
| 标记 Tag | 行号 | 块内地址 |
```

**全相联映射**：

```
| 标记 Tag | 块内地址 |
```

**组相联映射**：

```
| 标记 Tag | 组号 | 块内地址 |
```

各段位数：

- **块内地址**：$\log_2(\text{块大小})$
- **行号 / 组号**：直接映射取 $\log_2(\text{Cache 行数})$；组相联取 $\log_2(\text{组数})$，而 $\text{组数} = \text{行数} \div \text{路数}$
- **标记 Tag**：物理地址位数 − 行号/组号位数 − 块内地址位数

> [!warning] 易错点
> - 块内地址位数由**块大小**定，行号由**行数**定，两者别混。
> - 组相联的组号位数看**组数**（= 行数 ÷ 路数），不是行数。
> - 标记位数 = 总位数 − 其余两段，**算完记得倒扣**。

***

### 3.2.4 位数怎么算：用 2016-45 走一遍

> 某机：虚拟地址 32 位，物理地址 24 位，页大小 8KB；TLB 全相联；Cache 数据区 64KB，2 路组相联，主存块 64B。求图中字段 A~G 的位数。

| 字段 | 含义 | 计算 | 位数 |
|------|------|------|:---:|
| A | 虚页号 VPN | 32 − 13 | **19** |
| D | 页内地址 W | $\log_2 8\text{KB}=\log_2 2^{13}$ | **13** |
| B | TLB 标记 | 全相联，= 虚页号 | **19** |
| C | 页框号 PPN | 24 − 13 | **11** |
| G | 块内地址 | $\log_2 64\text{B}=\log_2 2^6$ | **6** |
| F | Cache 组号 | 行数 $=64\text{KB}/64\text{B}=2^{10}$，组数 $=2^{10}/2=2^9$ | **9** |
| E | Cache 标记 | 24 − 6 − 9 | **9** |

==先算页内偏移（13 位）→ 虚页号/页框号靠它倒扣 → Cache 三段靠块大小和行数→ 标记靠倒扣。== 顺序对了就不会乱。

## 3.3 TLB 的组成与查找

### 3.3.1 TLB 表项结构

TLB（快表）缓存的是**页表项**，所以结构像页表项，但更精简——它只管"映射"，不管缺页/置换：

```
| 有效位 V | 标记(虚页号) | 物理页框号 PPN | (ASID/权限位/访问位) |
```

- **有效位 V**：该表项是否有效
- **标记**：==被映射的虚页号==（全相联时是整个虚页号，组相联时是虚页号高位）
- **物理页框号 PPN**：命中后直接当物理地址高位用
- **ASID**（可选）：进程标识，用于进程切换时不刷新整个 TLB

> 与 OS 页表项的区别：页表项还有**修改位、外存地址、访问字段**（要为缺页和置换服务）；TLB 只存最近用过的映射，==够用就行==。

***

### 3.3.2 虚拟地址怎么切（TLB 视角）

==TLB 吃的是虚拟地址，所以切的是虚拟地址==。页内偏移 W 永远不动（只由页大小定），被切的是**虚页号内部**，切几段取决于 TLB 的映射方式：

| TLB 映射方式 | 虚拟地址划分 | 组号/行号位数 | 标记位数 |
|---------|------------------|:---:|:---:|
| **全相联** | 标记 + 页内偏移 W | 无（整个虚页号=标记） | = 虚页号位数 |
| **组相联** | 标记 + 组号 + 页内偏移 W | $\log_2(\text{组数})$，组数 = 表项数 ÷ 路数 | 虚页号位数 − 组号位数 |
| **直接映射** | 标记 + 行号 + 页内偏移 W | $\log_2(\text{表项数})$ | 虚页号位数 − 行号位数 |

- **全相联**：整个**虚页号**就是标记，靠比较器阵列并行比所有表项。
- **组相联**：组号取**虚页号低位** $\log_2(\text{组数})$ 位，标记取虚页号高位。
- 做题顺序：页大小 → 页内偏移 → 虚页号（= 地址位数 − 偏移）→ 组号（由 TLB 组数）→ 标记倒扣。

> [!warning] 两个"低位"来源不同的地址
> ==TLB 的组号取**虚拟地址**低位，Cache 的组号取**物理地址**低位==。都叫"组号"、都是低位，但一个切虚拟地址、一个切物理地址，别串。

**例**（2021-44）：虚拟地址 30 位，页大小 4KB = $2^{12}$ → 页内偏移 12 位、虚页号 18 位。TLB 2 路组相联、共 8 组 → 组号 $\log_2 8 = 3$ 位、标记 $18-3=15$ 位。虚拟地址三段即 `| 标记(15) | 组号(3) | 页内偏移(12) |`。

***

### 3.3.3 查 TLB 的过程

1. 按 3.3.2 的切法拆**虚拟地址**（页内偏移 W 始终是最低那几位）：
   - 全相联 TLB：`| 虚页号(整个，当标记) | 页内偏移 W |`
   - 组相联 TLB：`| TLB 标记 | TLB 组号 | 页内偏移 W |`
2. 用拆出来的字段查 TLB：
   - 全相联：拿整个虚页号并行比较所有表项的标记
   - 组相联：先拿**组号**定位到唯一一组，再并行比较该组内各行的标记
   - 比较时==先看有效位=1，再比标记相同==，两个都满足才命中
3. **命中**：取出物理页框号 PPN，与页内偏移 W 拼成物理地址 → 去查 Cache
4. **未命中**：查**慢表**（内存中的页表）
   - 页表命中 → 取出 PPN，==顺手填入 TLB==，再拼物理地址
   - 页表说该页不在内存（状态位=0）→ **缺页中断**，OS 调页后再重来
5. TLB 满了 → 按 LRU/RAND 淘汰一个表项

> [!warning] 易错点
> - TLB 未命中 ≠ 缺页。TLB 里没有该映射，但页**可能**就在内存里（映射被挤出 TLB 而已），这时查页表即可。==只有页表也说不在内存，才是缺页==。
> - 进程切换要刷新 TLB（或靠 ASID 区分），因为不同进程页表不同。

***

## 3.4 Cache 的组成与查找

### 3.4.1 Cache 行结构

Cache 和主存以**块（行）** 为单位交换数据，每行除了数据，还带若干控制位：

```
| 有效位 V | 脏位 D | 标记 Tag | 数据块 |
```

- **有效位 V**：这行是不是有效数据（=0 表示空行/无效）
- **脏位 D**：==只有写回法才需要==，标记这行被改过，替换前要写回主存
- **标记 Tag**：物理块号的高位（用来判断"这行是不是我要的块"）
- **数据块**：一整块数据（如 64B，不止一个字节）

**Cache 总容量**：

$$
\text{总容量} = \text{行数} \times (\text{标记位} + \text{有效位} + \text{脏位} + \text{替换位} + \text{数据位}) \div 8 \text{ 字节}
$$

> 题目问"数据区容量"就只算数据位，问"总容量"要把所有控制位算进去。==看清问的是哪个==。

***

### 3.4.2 查 Cache 的过程

1. 拿到**物理地址**，拆成 `| 标记 | 组号/行号 | 块内地址 |`（全相联则 `| 标记 | 块内地址 |`）
2. 用**组号/行号**定位到某一组（或某一行）
3. 并行比较该组各行标记，==要求有效位=1 且标记相同==
4. **命中**：用块内地址从数据块中取出对应的字 → 返回 CPU
5. **未命中**：访问主存，把整个块调入
   - 直接映射：直接覆盖该行
   - 组相联/全相联：按替换算法（LRU/FIFO/RAND）选一行
   - 若被替换行的**脏位=1** → 先写回主存再覆盖

> 为什么按"块"调入：利用**空间局部性**，一次把相邻数据都搬来，省得下次再访主存。

***

## 3.5 完整访存流程（把两套映射串起来）

> 一个虚拟地址走完全程：**TLB → 页表 → 物理地址 → Cache → 主存**。
> 每一步都是同一个套路：==拿地址的某几位去索引，再用剩下的高位当标记去比==。索引位和标记位在哪一步取哪几位，是这一节要钉死的东西。

### 3.5.1 总流程

```
CPU 发出虚拟地址 VA
   ↓
拆成 | 虚页号 VPN | 页内偏移 W |
   ↓
① 查 TLB（输入 VPN，在 CPU 内的 MMU 里）
   ①a 取 VPN 低位的组号 → 选中 TLB 的一组
   ①b 组内各行并行比：有效位=1 且 标记==VPN 的高位 → 命中该行
   ①c 从命中行读出页框号 PPN
   ├─ 命中 → 到 ③
   └─ 未命中 ↓
② 查页表（慢表，在主存）
   ├─ 状态位 P=1（页在内存）→ 取 PPN → 顺手填入 TLB → 到 ③
   └─ 状态位 P=0（页在外存）→ 缺页中断 → OS 调页 → 更新页表 → 重新执行本指令
        └ 页框从哪来？（同一步的两个分支）
           ├─ 有空闲页框 → 直接分配（首次用的栈/堆页，不用读外存）
           └─ 无空闲页框 → 页面置换，挑一页换出
                ├ 牺牲页修改位=0 → 直接覆盖，丢弃
                └ 牺牲页修改位=1 → 先写回对换区，再调入新页（两次磁盘 I/O）
   ↓
③ 拼物理地址 PA = PPN ‖ W（高 PPN、低 W，偏移原样继承）
   ↓
④ 查 Cache（输入 PA，在 CPU 内的 SRAM 里）
   ④a 取 PA 的组号/行号 → 选中一行（一组）
   ④b 并行比：有效位=1 且 标记==PA 的块号高位 → 命中
   ④c 用块内地址从命中行的数据块里取出那一个字节/字
   ├─ 命中 → 返回数据 → 结束
   └─ 未命中 ↓
⑤ 访问主存，调入整块 → 写进被选中行的数据块（置有效位，写回法还置脏位）→ 返回数据
```

### 3.5.2 "比有效位、比标记"到底在比什么

**两件事分开**：有效位答"这一格有没有装过东西"，标记答"装的是不是我要的那块"。==先看有效位，再看标记==——有效位=0 时格子里的标记是上一轮留下的残值，本身无意义（开机时全 0，若标记恰好也是 0 就会假命中）。

**比较器在哪**：TLB 每行、Cache 每行都挂一套**相等比较器**。被索引选中的那一组（或那一行）把各行标记同时送进比较器阵列**并行比较**。==这就是"相联度越高越贵"的来源：k 路就要 k 套 tag 比较器==，全相联则是所有行一起比，最贵。

**比出结果怎么用**：比较器输出一组"命中第几路"的一选信号 → 交给多路选择器，把该路的 **PPN**（TLB）或**数据块**（Cache）选出来送走。==同时命中两路不可能==（同一标记在一个组里只会存一份），否则说明硬件出错。

**标记里到底放了什么（关键）**：==已经被拿去索引的那几位，不能再放进标记==。

| 结构 | 用哪些位索引 | 标记放哪些位 | 比较对象来自 |
|------|------|------|------|
| TLB（全相联） | 无 | 整个虚页号 | **虚拟**地址 |
| TLB（组相联） | 虚页号低位的组号 | 虚页号高位 | **虚拟**地址 |
| TLB（直接映射） | 虚页号低位的行号 | 虚页号高位 | **虚拟**地址 |
| Cache（全相联） | 无 | 整个物理块号 | **物理**地址 |
| Cache（组相联） | 物理地址的组号位 | 物理块号高位 | **物理**地址 |
| Cache（直接映射） | 物理地址的行号位 | 物理块号高位 | **物理**地址 |

> [!warning] 易错点
> - 标记位数 = 总位数 − 索引位数 − 块内/页内偏移位数，**倒扣出来**；索引位和偏移位都不算进标记。
> - TLB 比的是**虚拟**地址的位，Cache 比的是**物理**地址的位。两个都叫"标记"，来源不是一个地址。

### 3.5.3 三张表分别在哪、谁维护

| 结构 | 存在哪 | 一行/一项里有什么 | 谁写 | 谁读 |
|------|------|------|------|------|
| **TLB 表项** | CPU 内 MMU 的相联存储器 | 有效位 V、标记（虚页号）、页框号 PPN、ASID | OS（缺页后、进程切换时） | MMU 硬件 |
| **页表项** | 主存的页表里（PTBR 指向） | 页框号、状态位 P、访问位 A、修改位 M、外存地址 | OS（缺页/置换后） | MMU 硬件（TLB 未命中时才来读） |
| **Cache 行** | CPU 内的 SRAM | 有效位 V、脏位 D、标记（物理块号）、数据块 | 硬件自动 | Cache 控制器 |

- ==TLB 表项是页表项的"精简副本"==：只留"有效位 + 标记 + 页框号"，把为缺页和置换服务的状态位、修改位、外存地址全去掉——TLB 既不判缺页，也不管写回。
- 一次访存 CPU 最多碰三处：**MMU 里的 TLB → 主存里的页表（TLB 未命中才碰）→ CPU 里的 Cache（未命中才碰主存）**。

### 3.5.4 要点与两个结论表

**要点**：

- 虚实地址变换发生在 **Cache 查找之前**（或与之并行，视是否物理索引）
- TLB 加速**地址转换**，Cache 加速**数据访问**
- 缺页是最大的性能瓶颈（磁盘 I/O，ms 级）；牺牲页是脏页时还要多一次写回
- ==页框分配与缺页置换是同一动作的两条出口：先试空闲页框，没有再换==。分配策略、调入时机、局部/全局置换见 [[408/4.操作系统.md]] 3.2.3

**命中组合**（2010-17，==不可能的是 D==）：

| TLB | Cache | Page | 是否可能 | 说明 |
|:---:|:---:|:---:|:---:|------|
| 未中 | 未中 | 未中 | ✅ | 真缺页 |
| 未中 | 命中 | 命中 | ✅ | 映射被挤出 TLB，但页在内存 |
| 命中 | 未中 | 命中 | ✅ | 映射在，数据不在 Cache |
| 命中 | 命中 | 未中 | ❌ | ==数据在 Cache ⇒ 页必在主存== |

==记住两条推论==：Cache 命中 ⇒ Page 命中（但 TLB 不一定命中）；TLB 命中 ⇒ Page 命中。

**访问主存次数**（不含取指令，地址变换按串行算）：

| TLB | Cache | 访问主存次数 | 说明 |
|:---:|:---:|:---:|------|
| 命中 | 命中 | **0** | 全走片上 |
| 命中 | 未中 | **1** | 取数据块 |
| 未中 | 命中 | **1** | 查页表 |
| 未中 | 未中 | **2** | 查页表 + 取数据块 |
| 缺页 | — | **很多** | 还要访磁盘 |

## 3.6 计算题模板

### 3.6.1 虚拟地址转物理地址

**公式汇总**：

- **页号位数** = $\log_2(\text{虚拟地址空间} \div \text{页面大小})$，**页内偏移位数** = $\log_2(\text{页面大小})$
- **页表项地址** = 页表基址 + 页号 × 页表项大小
- **物理地址** = 页框号 × 页面大小 + 页内偏移（位运算：页框号拼偏移）

**解题步骤**：

1. 确定页内偏移位数 = $\log_2(\text{页大小})$，页号位数 = 地址总位数 − 偏移位数
2. 从虚拟地址切出页号（右移偏移位数）和页内偏移（取低偏移位）
3. 页号 × 页表项大小 = 该页表项在页表中的字节偏移 → 页表项地址 = 页表基址 + 该偏移
4. 物理地址 = 页框号 × 页大小 + 页内偏移

**典型例题**（2024-45）：

> 按字节编址，虚拟/物理地址均 32 位，页大小 4MB（2²²B），页表项 4B，虚拟地址 [页号 10 位 | 偏移 22 位]。进程 P 页表起始虚拟地址 B8C0 0000H，被装入物理地址 6540 0000H 起的连续空间。
> （1）访问 1234 5678H 时缺页，处理后物理地址 BAB4 5678H。求该页表项的虚拟地址、物理地址、更新后的页框号。
> （2）求页表所在页的页号、该页表项的虚拟地址、该表项中的页框号。

**解**：

页表项即页表中被划分的小单元，类似数组，连续存储，有隐藏下标 = 页号。
页表项的 PA/VA = 页表的 PA/VA + 页号 × 页表项大小。

| 操作                       | 步骤                 | 结果             |
| ------------------------ | ------------------ | -------------- |
| 1234 5678H 高 10 位 = 48H  | 页号 = VA >> 22      | 页号 = **48H**   |
| 48H × 4 = 120H           | 页表内偏移 = 页号 × 4B    | 偏移 = **120H**  |
| B8C0 0000H + 120H        | (1) 表项虚拟地址         | **B8C0 0120H** |
| 6540 0000H + 120H        | (1) 表项物理地址         | **6540 0120H** |
| BAB4 5678H 高 10 位 = 2EAH | (1) 页框号 = PA >> 22 | **2EAH**       |

页表大小 = $2^{10} \times 4\text{B} = 4\text{KB} \ll 4\text{MB}$ → 页表只占 **1 页**，故页表自身的虚拟地址也落在此页，系统靠页表内部对应的页表项（自映射）记录其物理页框号。

| 步骤 | 操作 | 结果 |
|------|------|------|
| 页表所在页号 = B8C0 0000H >> 22 | 高 10 位 = 2E3H | **2E3H** |
| (2) 表项虚拟地址 = 基址 + 2E3H × 4 | B8C0 0000H + B8CH | **B8C0 0B8CH** |
| (2) 页框号 = 6540 0000H >> 22 | 高 10 位 = 195H | **195H** |

**核心**：页表项地址 = 页表基址 + 页号×4；页框号 = 物理地址 >> 22。两问共用一套逻辑。

### 3.6.2 Cache 字段与容量计算

**解题步骤**：

1. 由**块大小**定块内地址位数 = $\log_2(\text{块大小})$
2. 由**行数**（数据区容量 ÷ 块大小）定行号位数；组相联再 ÷ 路数得组数，取 $\log_2(\text{组数})$
3. 标记位数 = 物理地址位数 − 行号/组号 − 块内地址
4. 某块映射到哪一行/组：行号 = 块号 mod 行数（组号 = 块号 mod 组数）
5. 总容量 = 行数 ×（标记位 + 控制位 + 数据位）÷ 8

**典型例题**（2010-44）：

> 主存地址空间 256MB，按字节编址。指令 Cache 和数据 Cache 分离，各 8 行，每行 64B，数据 Cache 直接映射。
> （1）不考虑一致性维护位和替换控制位，数据 Cache 总容量多少？
> （2）a[0][31]、a[1][1] 所在主存块对应的 Cache 行号？

**解**：

- 地址 28 位（$256\text{M}=2^{28}$），块内地址 $\log_2 64 = 6$ 位，行号 $\log_2 8 = 3$ 位 → 标记 = $28-6-3=19$ 位
- 每行标记项 = 19（标记）+ 1（有效位）= 20 位
- 总容量 = $8 \times (64 + 20/8)\text{B} = 8 \times 66.5\text{B} =$ **532B**
- 行号 = $\lfloor \text{块地址}/64 \rfloor \bmod 8$：a[0][31] → 行 **6**；a[1][1] → 行 **5**

> 映射题一律用**二进制串分割**，别硬算十进制。

## 3.7 真题复盘

### 真题1：二级页表——"2¹⁶ 页"的含义

> 2010－某计算机采用二级页表的分页存储管理方式，按字节编址，页大小为 2¹⁰B，页表项大小为 2B，逻辑地址结构为 [页目录号 | 页号 | 页内偏移量]。逻辑地址空间大小为 2¹⁶ 页，则表示整个逻辑地址空间的页目录表中包含表项的个数至少是\_\_。

**我的错选**：64
**正确答案**：128
**坑点分析**：我把"2¹⁶ 页"当成了 2¹⁶ **字节**去算，导致地址划分全错。正确理解：总共有 2¹⁶ 个页面，即逻辑地址总共能访问这么多页。

- 页大小 2¹⁰B，一个页表能放 $2^{10} \div 2\text{B} = 2^9 = 512$ 个页表项 → 每个二级页表覆盖 2⁹ 页
- 总共 2¹⁶ 页 → 需要 $2^{16} \div 2^9 = 2^7 =$ **128** 个二级页表
- 页目录表每个表项指向一个二级页表 → 至少 **128** 个表项

**知识盲区**："2¹⁶ 页"和"2¹⁶ B"是两回事。题目给的是**页数**，直接用来算二级页表个数，不用先转成字节再绕回来。
**防错方法**：看清单位——"页"还是"B"。页数 ÷ 每个页表能装的表项数 = 需要的页表个数。

### 真题2：虚拟存储器的容量与实现

> 2012－下列关于虚拟存储器的叙述中，正确的是（ ）。
> A. 虚拟存储只能基于连续分配技术
> B. 虚拟存储只能基于非连续分配技术
> C. 虚拟存储容量只受外存容量的限制
> D. 虚拟存储容量只受内存容量的限制

**我的错选**：C
**正确答案**：B
**坑点分析**：我把虚拟存储误解成了**交换空间**。实际上：

- **虚拟存储容量** = 由 CPU 地址位数决定（32 位 → 最大 4GB），跟外存大小无关。外存只是暂存换出的页面（swap 分区）。
- **虚拟存储的实现** = 请求分页/分段/段页式，全是**非连续分配**——程序各页分散在物理内存的不同页框，通过页表映射。连续分配根本无法实现"只调入需要的页面"。

**知识盲区**：虚拟存储 ≠ 外存扩容。虚拟存储靠的是 **地址映射（页表）+ 缺页中断 + 页面置换**，不是"内存+外存"。
**防错方法**：虚拟存储容量 → 看地址位数。虚拟存储实现 → 必是非连续分配。遇到"受外存限制"直接排除。

### 真题3：最少页框数的判定因素

> 2025-确定进程运行所需的最少页框数时，要考虑的指标是（ ）。
> A. 代码段长  B. 虚拟地址空间大小  C. 物理地址空间大小  D. 指令系统支持的寻址方式

**我的错选**：C（物理地址空间大小）
**正确答案**：D（指令系统支持的寻址方式）

题目问的是：一个进程正常运行，**至少需要分配几个页框**。

**为什么是 D**：寻址方式决定了**一条指令执行过程中会访问几个不同的页**。

| 寻址方式 | 访问流程 | 最少需要几个页框 |
|---------|---------|:--------------:|
| **立即寻址** | 取指令 | **1 个** |
| **直接寻址** | 取指令 → 取操作数 | **2 个** |
| **间接寻址** | 取指令 → 取地址 → 取数据 | **3 个** |

若分配不足，访问下一页时被迫置换掉正在用的页，下条指令又缺页 → 反复缺页 = **抖动**。

**为什么 C 错误**：物理地址空间大小决定系统**总共有多少页框**（资源总量），不能告诉你"一条指令会访问几个页"。

| 概念 | 含义 | 由什么决定 | 类比 |
|------|------|-----------|------|
| **物理地址空间大小** | 系统总共有多少页框 | 物理内存大小 | 停车场 1000 个车位 |
| **最少页框数** | 一个进程至少需要几个 | 指令的内存访问模式（寻址方式） | 一辆车至少占 1 个车位 |
| **页框大小** | 每个页框多大 | 系统页面大小设置 | 每个车位面积 |

**防错方法**：看到"最少页框数"，立即想 **一条指令执行会访问几个不同的页**。口诀：**寻址方式定访问层数，层数 = 最少页框数**。

### 真题4：地址字段位数——2016-45

> 页式虚拟存储，按字节编址，虚拟地址 32 位，物理地址 24 位，页大小 8KB；TLB 全相联；Cache 数据区 64KB，2 路组相联，主存块 64B。（1）图中字段 A~G 各多少位？TLB 标记 B 存什么？（2）块号 4099 主存块映射到哪个 Cache 组？（3）Cache 缺失 vs 缺页开销哪个大？（4）为什么 Cache 能直写、修改页面却总用回写？

**解（1）**：见 3.2.4 表 → A=19、B=19、C=11、D=13、E=9、F=9、G=6。TLB 标记 B 存的是**虚页号**，表示该表项对应哪个虚页的页表项。

**解（2）**：块号 = `| 主存字块标记 | 组号 |`。$4099 = \underbrace{00\,0001\,000}_{\text{标记}}\underbrace{0\,0000\,0011}_{\text{组号}}\text{B}$ → 组号 = **3**，标记 H = 0 0000 1000B。

**解（3）**：Cache 缺失只需访问**主存**，缺页要访问**磁盘**，磁盘比主存慢几个数量级 → ==缺页开销大得多==。

**解（4）**：直写要同时写快存和慢存；写磁盘比写主存慢太多，为减少写盘次数，主存-外存层次必须用**回写**。==越快越贵的层次用回写，慢的层次才敢直写==。

**考点**：一题串起 虚拟地址组成 + 物理地址组成 + TLB 组成 + Cache 三段划分。

### 真题5：TLB 表项组成与替换——2021-44

> 主存地址 24 位，按字节编址；分页管理，虚拟地址 30 位，页大小 4KB；TLB 2 路组相联、LRU、共 8 组。（1）虚页号哪几位？（2）TLB 标记/组号各哪几位？（3）访问虚页号 10、12、16、7、26、4、12、20，哪个被替换？（4）虚拟地址增到 32 位，TLB 表项增加几位？

**解**：

- （1）页大小 $4\text{KB}=2^{12}$ → 页内 12 位、虚页号 $30-12=18$ 位
- （2）组数 $8=2^3$ → TLB 组号 3 位、标记 $18-3=15$ 位
- （3）组号 = 虚页号 mod 8 → 依次 2、4、0、7、2、4、4、4。只有组 4 超过 2 项（12、4、12、20），LRU 下访问 20 时换出 **虚页号 4**
- （4）页大小不变 → 页内位数不变，虚页号 $+2$ 位 → ==TLB 表项位数 +2 位（标记 +2）==

**考点**：TLB 标记 vs 组号怎么切（3.3.2）；替换看**组号**定位 + 组内 LRU。

### 真题6：命中组合不可能情形——2010-17

> 下列命中组合中，一次访存不可能发生的是（ ）。
> A. TLB未中，Cache未中，Page未中　B. TLB未中，Cache命中，Page命中
> C. TLB命中，Cache未中，Page命中　D. TLB命中，Cache命中，Page未中

**答案**：D

**理由**：==Cache 命中 ⇒ 数据在 Cache ⇒ 所在页必然已调入主存（Page 必命中）==，所以 D 自相矛盾。

- B 可能：映射被挤出 TLB，但页在内存
- C 可能：映射在 TLB，但数据不在 Cache
- A 可能：TLB 未中且 Page 未中 = 真缺页

**防错方法**：记两条推论——**Cache 命中 ⇒ Page 命中**；**TLB 命中 ⇒ Page 命中**。

### 真题7：虚实地址变换与 TLB 命中判断——2013-16

> 主存地址空间 256MB，按字节编址；虚拟地址空间 4GB，页式管理，页大小 4KB；TLB 全相联，4 个页表项（内容为表）。对虚拟地址 03FFF180H 做虚实地址变换，结果是（ ）。

**解**：

- 页大小 $4\text{KB}=2^{12}$ → 低 12 位是页内地址
- $03\text{FFF}180\text{H} = \underbrace{03\text{FFF}}_{\text{虚页号}}\underbrace{180}_{\text{页内地址}}\text{H}$
- 查 TLB 中虚页号 03FFFH 的表项，有效位为 1、页框号 0153H
- 拼物理地址 = $\underbrace{0153}_{\text{页框号}}\underbrace{180}_{\text{页内地址}}\text{H}$ = **0153180H**

**变式**：若虚拟地址是 FF180000H，TLB 中查不到对应虚页号 → ==TLB 缺失==。注意：==TLB 缺失时 Page 不一定缺失；TLB 命中时 Page 一定命中==。

**考点**：虚实变换 = 拆页号/偏移 → 查 TLB → 换高位 → 拼地址。全部是位操作。

## 3.8 个人理解笔记

### 3.8.1 为什么需要多级存储？

**核心矛盾**：速度 vs 容量 vs 成本。

**类比**：寄存器 = 工作台（快、小）；Cache = 抽屉；主存 = 书架；辅存 = 仓库。不可能把仓库的书全放工作台，于是常用的放抽屉、要用的放书架、不常用的进仓库。

### 3.8.2 虚拟内存的本质

**不是**：把磁盘当内存用（那只是表面现象）。
**本质**：给每个程序一个"假象"——它拥有整个地址空间。

**三大作用**：

1. **扩展地址空间**：程序可用比物理内存更大的地址空间
2. **内存保护**：每个进程独立地址空间
3. **内存共享**：多个进程可映射到同一物理页（如共享库）

### 3.8.3 TLB 存在的意义

**没有 TLB**：每次访问数据都要先访问内存中的页表，等于每次访问变两次，性能损失 50% 以上。
**有了 TLB**：页表项缓存在 TLB，命中率通常 >95%，大部分访问只需一次内存访问。

**类比**：页表 = 字典（每次查）；TLB = 脑子里记住的常用词（快速回忆）。

### 3.8.4 TLB 和 Cache 谁先查？

==TLB 在前，Cache 在后==——因为 Cache 要用**物理地址**找数据，而物理地址得先由 TLB/页表把虚拟地址翻译出来。

- 若 Cache 用**虚拟地址**索引（VIPT），两者可并行，但打上物理标记后仍要对齐
- 408 题目一律按 **TLB → 页表 → 物理地址 → Cache** 的顺序讲

**一句话**：TLB 管"地址翻译"，Cache 管"数据搬运"，两个都是拿局部性换速度，==但管的不是同一件事==。
