# 3. 存储系统（计组+OS融合）

> 本章融合计算机组成原理和操作系统中的存储相关内容，按主题组织，强调知识串联。

## 3.1 核心对比表
### 3.1.1 存储层次结构

| 存储层次           | 访问速度         | 容量               | 成本  | 由谁管理  | 对程序员 | 主要技术  |
| -------------- | ------------ | ---------------- | --- | ----- | ---- | ----- |
| **寄存器**        | 最快（<1ns）     | 最小（KB级）          | 最高  | 编译器   | 可见   | 硬件    |
| **Cache**      | 很快（1-10ns）   | 小（MB级）           | 高   | 硬件自动  | 透明   | SRAM  |
| **主存**         | 较快（50-100ns） | 中（GB级）           | 中   | OS+硬件 | 透明   | DRAM  |
| **虚拟内存**       | -            | 由地址位数决定（32位→4GB） | -   | OS    | 透明   | 页表/段表 |
| **辅存（磁盘/SSD）** | 慢（ms级）       | 最大（TB级）          | 最低  | OS+用户 | 可见   | 机械/闪存 |

**重要说明**：
- **虚拟内存容量** = 地址总线位数决定（如32位系统最大4GB，64位系统理论上16EB）
- **实际可用虚拟内存** ≈ 物理内存 + 交换空间（磁盘上的页面文件/swap分区）
- 虚拟内存不是"把磁盘当内存用"，而是一个地址映射机制，给每个进程独立的地址空间

**核心原理**：
- **时间局部性**：最近访问的数据很可能再次访问（利用Cache/页面缓存）
- **空间局部性**：相邻地址的数据很可能一起访问（利用Cache行/页面）
- **层次调度**：数据在各层之间按需调度，对上层透明

**408考点**：
- 各层之间的速度差异（数量级）
- Cache和虚拟内存都利用了局部性原理
- 透明性：Cache对程序员透明，虚拟内存对程序员透明

### 3.1.2 地址映射方式对比

#### Cache地址映射（计组）

| 映射方式      | 地址划分      | 硬件复杂度    | 命中率 | 冲突      | 替换算法         |
| --------- | --------- | -------- | --- | ------- | ------------ |
| **直接映射**  | 标记+索引+块内  | 低        | 低   | 多（固定位置） | 不需要          |
| **全相联映射** | 标记+块内     | 高（并行比较器） | 高   | 少       | 需要（LRU/FIFO） |
| **组相联映射** | 标记+组索引+块内 | 中        | 中   | 折中      | 组内需要         |

#### 页式映射（OS）

| 映射方式     | 地址划分         | 页表层级 | 空间开销    | 查找速度   | 适用场景  |
| -------- | ------------ | ---- | ------- | ------ | ----- |
| **单级页表** | 页号+页内偏移      | 1级   | 大（连续空间） | 快      | 小地址空间 |
| **多级页表** | 一级页号+二级页号+偏移 | 2-4级 | 小（按需分配） | 较慢     | 大地址空间 |

#### 映射方式对比（OS）

| 特性 | 页式 | 段式 | 段页式 |
|-----|------|------|--------|
| **划分依据** | 固定大小 | 逻辑单位（可变） | 段内分页 |
| **地址结构** | 页号+页内偏移 | 段号+段内偏移 | 段号+页号+页内偏移 |
| **碎片** | 内部碎片 | 外部碎片 | 内部碎片 |
| **共享/保护** | 较难 | 容易 | 容易 |
| **透明性** | 完全透明 | 对用户可见 | 结合 |

**核心区别**：
- **Cache映射**：物理地址→Cache位置，硬件实现，纳秒级
- **页式映射**：虚拟地址→物理地址，OS管理+硬件辅助（MMU），微秒级（有缺页时毫秒级）
- **目标不同**：Cache为了速度，页表为了扩展地址空间

### 3.1.3 替换算法对比

#### Cache替换算法（计组）

| 算法 | 原理 | 硬件实现 | 命中率 | 开销 |
|-----|------|---------|-------|------|
| **随机(RAND)** | 随机选一块 | 简单（随机数生成器） | 低 | 最低 |
| **FIFO** | 先进先出 | 简单（队列计数器） | 中 | 低 |
| **LRU** | 最近最少使用 | 复杂（访问时间记录） | 高 | 高 |
| **LFU** | 最不经常使用 | 复杂（访问次数计数） | 中 | 高 |

#### 页面置换算法（OS）

| 算法 | 原理 | 是否需要硬件支持 | 性能 | Belady异常 | 实现难度 |
|-----|------|---------------|------|----------|---------|
| **最佳(OPT)** | 置换最长时间不用的 | 否（理论算法） | 最优 | 无 | 不可实现 |
| **FIFO** | 先进先出 | 否 | 差 | **有** | 简单 |
| **LRU** | 最近最少使用 | 是（访问位） | 好 | 无 | 困难 |
| **Clock(二次机会)** | FIFO+访问位 | 是（访问位） | 较好 | 无 | 中等 |
| **改进Clock** | Clock+修改位 | 是（访问位+修改位） | 好 | 无 | 中等 |
| **LFU** | 最不经常使用 | 是（计数器） | 较好 | 无 | 困难 |

**Belady异常**：
- 增加页框数，缺页次数反而增加
- 只有FIFO会出现

**408重点**：
- LRU是Cache和页面置换的首选（性能好）
- 实际系统常用Clock算法（LRU的近似，实现简单）
- FIFO简单但性能差，且有Belady异常

### 3.1.4 TLB vs Cache

| 对比维度      | TLB（快表）           | Cache                 |
| --------- | ----------------- | --------------------- |
| **组成**    | Tag/控制位/实页号       | 控制位/Tag/数据块           |
| **作用**    | 缓存页表项（虚拟页号→物理页框号） | 缓存数据和指令               |
| **输入**    | 虚拟页号              | 物理地址                  |
| **输出**    | 物理页框号             | 数据                    |
| **位置**    | **CPU中的MMU内部**    | CPU与主存之间（逻辑上）实际在CPU内部 |
| **大小**    | 很小（几十到几百项）        | 较大（KB到MB）             |
| **映射方式**  | 全相联/组相联           | 直接/组相联/全相联            |
| **未命中代价** | 访问页表（几十ns）        | 访问主存（几十ns）            |
| **管理者**   | OS（页表内容）+硬件（TLB）  | 硬件自动                  |

**协同工作**：
```
CPU发出虚拟地址
  ↓
查TLB（虚拟页号→物理页框号）
  ↓
TLB命中 → 得到物理地址 → 查Cache
TLB未命中 → 查页表 → 更新TLB → 查Cache
  ↓
Cache命中 → 返回数据
Cache未命中 → 访问主存 → 更新Cache → 返回数据
```

**408考点**：
- TLB是虚拟内存的加速机制，Cache是主存的加速机制
- 两者都利用局部性原理
- 访问顺序：TLB → 页表 → Cache → 主存

## 3.2 计算题模板
### 3.2.1 虚拟地址转物理地址（OS+计组）

**公式汇总**：
- **虚拟地址** = 页号 × 页面大小 + 页内偏移
- **物理地址** = 页框号 × 页面大小 + 页内偏移
- **页号位数** = log₂(虚拟地址空间 ÷ 页面大小)
- **页内偏移位数** = log₂(页面大小)

**解题步骤**：
1. 确定页内偏移位数 = log₂(页大小)，页号位数 = 地址总位数 − 偏移位数
2. 从虚拟地址中切出页号（右移偏移位数）和页内偏移（取低偏移位）
3. 页号 × 页表项大小 = 该页表项在页表中的字节偏移 → 页表项地址 = 页表基址 + 该偏移
4. 物理地址 = 页框号 × 页大小 + 页内偏移

**典型例题**（2024-45）：

> 按字节编址，虚拟/物理地址均 32 位，页大小 4MB（2²²B），页表项 4B，虚拟地址 [页号 10 位 | 偏移 22 位]。进程 P 页表起始虚拟地址 B8C0 0000H，被装入物理地址 6540 0000H 起的连续空间。
> （1）访问 1234 5678H 时缺页，处理后物理地址 BAB4 5678H。求该页表项的虚拟地址、物理地址、更新后的页框号。
> （2）求页表所在页的页号、该页表项的虚拟地址、该表项中的页框号。

**解**：

| 步骤 | 操作 | 结果 |
|------|------|------|
| 页号 = VA >> 22 | 1234 5678H 高 10 位 = 48H | 页号 = **48H** |
| 页表内偏移 = 页号 × 4B | 48H × 4 = 120H | 偏移 = **120H** |
| (1) 表项虚拟地址 | B8C0 0000H + 120H | **B8C0 0120H** |
| (1) 表项物理地址 | 6540 0000H + 120H | **6540 0120H** |
| (1) 页框号 = PA >> 22 | BAB4 5678H 高 10 位 = 2EAH | **2EAH** |

页表大小 = 2¹⁰ × 4B = 4KB ≪ 4MB → 页表只占 **1 页**。

| 步骤 | 操作 | 结果 |
|------|------|------|
| 页表所在页号 = B8C0 0000H >> 22 | 高 10 位 = 2E3H | **2E3H** |
| (2) 表项虚拟地址 = 基址 + 2E3H × 4 | B8C0 0000H + B8CH | **B8C0 0B8CH** |
| (2) 页框号 = 6540 0000H >> 22 | 高 10 位 = 195H | **195H** |

**核心**：页表项地址 = 页表基址 + 页号×4；页框号 = 物理地址 >> 22。两问共用同一套逻辑。(1) 套在缺页 VA 上，(2) 套在页表自身 VA 上。

> **手工取高 N 位技巧**：不看整个 32 位二进制，只取前几个 hex 位转二进制即可。
> 例：22 位偏移 → 页号 10 位，`1234 5678H` 只需取前 3 位 `123H` → `0001 0010 0011` 然后截前 10 位 → `0001 0010 00` = **048H**。

## 3.3 知识串联

### 3.3.1 CPU访问数据的完整路径

**完整流程图**：
```
1. CPU执行指令，产生虚拟地址
   ↓
2. MMU（内存管理单元）接收虚拟地址
   ↓
3. 查TLB（快表）
   ├─ TLB命中 → 得到物理页框号 → 跳到步骤5
   └─ TLB未命中 ↓
   
4. 查页表（在主存中）
   ├─ 页表命中 → 得到物理页框号 → 更新TLB → 继续
   └─ 缺页中断 → OS调入页面 → 更新页表 → 更新TLB → 重新执行指令（回到步骤1）
   
5. 拼接物理地址（物理页框号 + 页内偏移）
   ↓
6. 查Cache
   ├─ Cache命中 → 返回数据 → 结束
   └─ Cache未命中 ↓
   
7. 访问主存
   ↓
8. 主存返回数据 → 更新Cache → 返回CPU
```

**时间开销分析**：
- **最快路径**：TLB命中 + Cache命中 ≈ 几ns
- **中等路径**：TLB未命中 + Cache命中 ≈ 几十ns
- **慢路径**：TLB命中 + Cache未命中 ≈ 几十到上百ns
- **最慢路径**：缺页中断 ≈ 几ms（磁盘I/O）

**408考点**：
- 虚拟地址转换发生在Cache查找之前
- TLB加速地址转换，Cache加速数据访问
- 缺页中断是最大的性能瓶颈

---

### 3.3.2 多级存储的协同工作原理

#### 层次间的数据流动

**向上流动（CPU请求数据）**：
```
辅存 ──页面调入──→ 主存 ──Cache行调入──→ Cache ──取数──→ 寄存器
     (OS管理)          (硬件自动)         (硬件自动)
```

**向下流动（数据写回）**：
```
寄存器 ──存数──→ Cache ──写回/写直达──→ 主存 ──页面换出──→ 辅存
              (硬件控制)                (OS管理)
```

#### 一致性问题

| 问题 | 发生层次 | 解决方案 |
|-----|---------|---------|
| **Cache一致性** | Cache ↔ 主存 | 写直达/写回 + 监听协议（多核） |
| **页面一致性** | 主存 ↔ 辅存 | 修改位（Dirty bit）+ 写回策略 |
| **多级Cache一致性** | L1 ↔ L2 ↔ L3 | 包含性策略/MESI协议 |

**408考点**：
- 写策略：写直达（简单但慢）vs 写回（快但复杂）
- 修改位的作用：避免干净页的写回
- 多核系统的Cache一致性

---

### 3.3.3 局部性原理在各层的应用

#### 时间局部性

| 存储层次 | 利用方式 | 具体机制 |
|---------|---------|---------|
| **Cache** | 最近访问的数据留在Cache | LRU替换算法 |
| **TLB** | 最近翻译的页表项留在TLB | 全相联快速查找 |
| **页面缓存** | 最近访问的页面留在内存 | LRU/Clock置换算法 |

#### 空间局部性

| 存储层次 | 利用方式 | 具体机制 |
|---------|---------|---------|
| **Cache** | 以行（块）为单位调入 | 一次调入整个Cache行（如64字节） |
| **页面** | 以页为单位调入 | 一次调入整个页面（如4KB） |
| **预取** | 预测并提前调入 | 硬件预取器 |

**局部性失效的情况**：
- **时间局部性差**：数据只访问一次（如流式处理）→ Cache命中率低
- **空间局部性差**：访问地址跳跃（如链表遍历）→ 预取失效
- **工作集超出容量**：活跃数据>Cache/内存大小 → 频繁置换

**408考点**：
- 程序优化：提高局部性 → 提高命中率
- 循环顺序：按行/按列遍历数组的性能差异
- 为什么链表比数组慢：空间局部性差

## 3.4 个人理解笔记

### 3.4.1 为什么需要多级存储？

**核心矛盾**：速度 vs 容量 vs 成本

**类比理解**：
- **寄存器** = 你的工作台（最快，但很小）
- **Cache** = 你的书桌抽屉（快，小）
- **主存** = 你书房的书架（中速，中等容量）
- **虚拟内存** = 家里所有房间的书架（扩展空间）
- **辅存** = 仓库（慢，但容量巨大）

你不可能把仓库的所有书都放在工作台上，所以需要：
- 把常用的放在抽屉（Cache）
- 把最近要用的放在书架（主存）
- 把不常用的放在仓库（磁盘）

### 3.4.2 虚拟内存的本质

**不是**：把磁盘当内存用（这只是表面现象）

**本质**：给每个程序一个"假象"——它拥有整个地址空间

**三大作用**：
1. **扩展地址空间**：程序可以使用比物理内存更大的地址空间
2. **内存保护**：每个进程有独立地址空间，互不干扰
3. **内存共享**：多个进程可以映射到同一物理页（如共享库）

### 3.4.3 TLB存在的意义

**没有TLB的世界**：
- 每次访问数据都要先访问页表（在主存中）
- 等于每次访问变成了两次访问（一次页表，一次数据）
- 性能损失50%以上

**有了TLB**：
- 页表项缓存在TLB（全相联，速度快）
- TLB命中率通常>95%
- 大部分访问只需一次内存访问

**类比**：
- 页表 = 字典（每次都要查）
- TLB = 你脑子里记住的常用词（快速回忆）

## 3.5 真题复盘

### 真题1：二级页表——"2¹⁶ 页"的含义
> 2010－某计算机采用二级页表的分页存储管理方式，按字节编址，页大小为 2¹⁰B，页表项大小为 2B，逻辑地址结构为 [页目录号 | 页号 | 页内偏移量]。逻辑地址空间大小为 2¹⁶ 页，则表示整个逻辑地址空间的页目录表中包含表项的个数至少是\_\_。

**我的错选**：64
**正确答案**：128
**坑点分析**： "逻辑地址空间大小为 2¹⁶ 页"——我把"2¹⁶ 页"当成了 2¹⁶ **字节**去算，导致地址划分全错。正确的理解：总共有 2¹⁶ = 65536 个页面，即逻辑地址总共能访问这么多页。
- 页大小 2¹⁰B，一个页表能放 2¹⁰ ÷ 2B = 2⁹ = 512 个页表项
- 即每个二级页表覆盖 2⁹ 页
- 总共 2¹⁶ 页 → 需要 2¹⁶ ÷ 2⁹ = 2⁷ = **128** 个二级页表
- 页目录表每个表项指向一个二级页表 → 至少 **128** 个表项
**知识盲区**： "2¹⁶ 页"和"2¹⁶ B"是两回事。页数 × 页大小 = 地址空间字节数（2¹⁶ × 2¹⁰ = 2²⁶B），但题目给的是页数，直接用来算二级页表个数，不需要先转成字节再绕回来。
**防错方法**： 看清单位——"页"还是"B"。页数直接 ÷ 每个页表能装的表项数 = 需要的页表个数。

---

### 真题2：虚拟存储器的容量与实现
> 2012－下列关于虚拟存储器的叙述中，正确的是（ ）。
> A. 虚拟存储只能基于连续分配技术
> B. 虚拟存储只能基于非连续分配技术
> C. 虚拟存储容量只受外存容量的限制
> D. 虚拟存储容量只受内存容量的限制

**我的错选**： C
**正确答案**： B
**坑点分析**： 我以为虚拟存储就是"内存不够了拿外存来凑"，外存多大虚拟存储就能多大。这是把虚拟存储误解成了**交换空间**。实际上：
- **虚拟存储容量** = 由 CPU 地址位数决定（32 位 → 最大 4GB），跟外存大小没关系。外存只是暂存换出的页面（swap 分区），它决定了能同时跑多少程序，但不决定单个进程能访问的地址空间上限。
- **虚拟存储的实现** = 请求分页/请求分段/段页式，这些全都是**非连续分配**——程序各页分散在物理内存的不同页框中，通过页表映射。连续分配（整个程序必须装在连续的一块内存中）根本无法实现"只调入需要的页面、其余留在外存"。
**知识盲区**： 虚拟存储 ≠ 外存扩容。虚拟存储的"大地址空间"来自地址位数，外存提供的是"后备存储"，二者角色不同。虚拟存储器靠的是 **地址映射（页表）+ 缺页中断 + 页面置换** 这套机制，不是简单的"内存+外存"。
**防错方法**： 虚拟存储容量 → 看地址位数。虚拟存储实现 → 必是非连续分配（页式/段式/段页式）。遇到"受外存限制"直接排除。

### 真题3：最少页框数的判定因素
> 2025-确定进程运行所需的最少页框数时，要考虑的指标是（ ）。
> A. 代码段长  B. 虚拟地址空间大小  C. 物理地址空间大小  D. 指令系统支持的寻址方式

**我的错选**： C（物理地址空间大小）  
**正确答案**： D（指令系统支持的寻址方式）


题目问的是：一个进程正常运行，**至少需要分配几个页框**（不是调整页框大小）。

**为什么是 D（寻址方式）**：

寻址方式决定了**一条指令执行过程中会访问几个不同的页**：

| 寻址方式 | 访问流程 | 可能涉及的页 | 最少需要几个页框 |
|---------|---------|------------|----------------|
| **立即寻址** | 取指令 | 1 页（指令页） | **1 个** |
| **直接寻址** | 取指令 → 取操作数 | 2 页（指令页 + 数据页） | **2 个** |
| **间接寻址** | 取指令 → 取地址 → 取数据 | 3 页（指令页 + 地址页 + 数据页） | **3 个** |

**举例**：
假设指令 `MOV R1, [A]` 采用间接寻址：
1. 取指令（指令在页 P0）
2. 读取地址 A（A 的值在页 P1）
3. 访问 A 指向的数据（数据在页 P2）

如果只给进程分配 2 个页框：
- 访问 P2 时，必须置换掉 P0 或 P1
- 下一条指令又需要 P0，再次缺页
- 反复缺页 → **抖动**（thrashing）

因此，这个进程**最少需要 3 个页框**才能正常运行。

**为什么 C 错误**：

**物理地址空间大小** → 决定系统**总共有多少个页框**（系统级资源总量）

例如：
- 物理地址 32 位，页大小 4KB → 系统总共有 2²⁰ = 1M 个页框
- 但这不能告诉你"一条指令执行时会访问几个页"

即使系统有 1M 个页框（资源充足），如果某进程采用间接寻址但只分配 2 个页框，仍然会抖动。

**对比理解**：

| 概念 | 含义 | 由什么决定 | 类比 |
|------|------|-----------|------|
| **物理地址空间大小** | 系统总共有多少页框 | 物理内存大小 | 停车场总共有 1000 个车位 |
| **最少页框数** | 一个进程至少需要几个页框 | 指令的内存访问模式（寻址方式） | 一辆车至少需要占 1 个车位 |
| **页框大小** | 每个页框多大 | 系统页面大小设置（如 4KB） | 每个车位的面积 |

**题目问的是**："一辆车至少需要占几个车位"（看车本身的需求），而不是"停车场有多少车位"（系统容量）。

**知识盲区**：  
- 混淆了"页框数量"和"页框大小"
- 混淆了"系统总页框数"（资源总量）和"进程最少页框数"（单个进程需求下限）
- 没有理解"最少页框数"的本质：**避免抖动所需的页框数 = 一条指令执行过程中最多同时涉及的页数**

**防错方法**：  
- 看到"最少页框数"，立即想：**一条指令执行会访问几个不同的页？**
- 口诀：**寻址方式定访问层数，层数 = 最少页框数**
- 记住：物理空间是"总量"（系统能给多少），寻址方式是"需求"（进程要多少）
- 页框数是**数量**（几个），页框大小是**尺寸**（每个多大）
